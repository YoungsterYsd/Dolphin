### 2.3 衍生公式（recompute_derived）

```
PrimaryAttributeSet.recompute_derived():
  attack_final = (attack_base + attack_bonus) * (1 + attack_mul)
  armor_final = (armor_base + armor_bonus) * (1 + armor_mul)

HealthSet.recompute_derived(move_speed_mul_param = 0.0):
  max_health = (health_base + health_bonus) * (1 + health_mul)
  move_speed_final = move_speed_base * (1 + move_speed_mul_param)
```

ASC._run_post_inject_init 中按顺序调用：
1. PrimaryAttributeSet.recompute_derived（玩家有；敌人无 PrimaryAttributeSet 跳过）
2. HealthSet.recompute_derived(0.0)（移速倍率默认 0；未来加 move_speed_mul 词条由 ASC 传入）

## 六、踩坑记录

### 坑 1：删 PrimaryAttributeSet.move_speed_mul 后 ASC 引用未同步

**现象**：第一次 run_project 报 `SCRIPT ERROR: Invalid access to property 'move_speed_mul' on PrimaryAttributeSet`，bootstrap 中断，玩家无属性。

**根因**：我在 ASC._run_post_inject_init 内写 `(s as PrimaryAttributeSet).move_speed_mul`，但同步删 PrimaryAttributeSet 时把 `move_speed_mul` 字段也删了（旧案没有 %移速）。

**修复**：ASC._run_post_inject_init 调 `HealthSet.recompute_derived(0.0)`，move_speed_mul 默认 0。如未来加该词条字段，再传入。

**经验**：删字段时**必须 grep 一遍所有引用**，特别是 ASC 这类聚合容器。仅靠 lint 0 不能保证运行时 OK。

### 坑 2：MCP execute_editor_script 在编辑器主进程跑，看不到游戏运行时实例

**现象**：用 execute_editor_script 写脚本读 Player 节点，输出"Player not found"。

**根因**：execute_editor_script 在编辑器进程跑，runtime 实例在另一个进程。要看运行时状态应该读 `source: "runtime"` log（user://logs/godot.log）。

**经验**：runtime log 在 stop_project 之后才能稳定读到（取决于 Godot 是否 flush 文件）。也可以直接看 editor_panel 因为 run_project 的输出会同步到主进程。
