### 0.2 创建目录骨架

在 `RPG/Content/GameData/GE/` 下建好 4 个子目录：

```
RPG/Content/GameData/GE/
├─ Init/
├─ Derive/
├─ Regen/
├─ State/
└─ Health/
```

**操作**：
1. 在 Content Browser 定位到 `Content/`（点左侧 `Content` 文件夹）。
2. 右键 → New Folder → 输入 `GameData` → 回车。
3. 进入 `GameData` → 新建子文件夹 `GE` → 进入 `GE` → 依次新建 `Init`、`Derive`、`Regen`、`State`、`Health` 五个子文件夹。

> 注意大小写：UE 在 Windows 大小写不敏感，但 Linux 打包敏感，**务必统一首字母大写**。

### 0.3 通用创建步骤模板

每个 GE 资产的创建流程都相同：

| 步 | 操作 |
|---|---|
| 1 | 进入对应子目录（如 `GameData/GE/Init/`） |
| 2 | 右键空白处 → **Gameplay → Gameplay Effect** |
| 3 | 弹出对话框 → **Pick Parent Class** → 选 `GameplayEffect`（默认根类即可，**不要选 LyraGameplayEffect_Cooldown**） |
| 4 | 命名为表中的资产名（**严格一致，不带空格、用下划线**） |
| 5 | 双击打开 → 按本手册"配置详情"逐项填表 → **Save All（Ctrl+Shift+S）** |

## 13. 常见问题 FAQ

**Q1：Modifier 下拉里搜不到 `RPGHealthSet.HealthMax` / `RPGHealthSet.StaminaCurrent` / `RPGHealthSet.HealthFinal` / `RPGPrimaryAttributeSet.AttackFinal` / `RPGPrimaryAttributeSet.DefenseFinal` 怎么办？**

A：两种可能，优先排查第 ①：

① **`HideFromModifiers` Meta 标记**（最常见）：UE 的 GE 编辑器会把带 `HideFromModifiers` 的字段从 Modifier 下拉里**完全过滤**。若遇到这种情况，打开 `RPGHealthSet.h` / `RPGPrimaryAttributeSet.h`，对目标字段删掉 `Meta = (HideFromModifiers, ...)` 里的 `HideFromModifiers`（保留 `AllowPrivateAccess = true`），重编即可。
> **A3-3 v1.1 已修正**：`HealthFinal` / `StaminaCurrent`（HealthSet）+ `AttackFinal` / `DefenseFinal`（PrimaryAttributeSet）四个字段的 `HideFromModifiers` 已摘除（钳制由 `PostGameplayEffectExecute` + `ClampAttribute` 保障；Final 字段语义上由 MMC Override 写入，不会自然累加）。`HealthDamage` 仍保留 `HideFromModifiers`（伤害只能走 DamageExecution，不允许 GE Modifier 直接 `-100`）。

② **A3-1/A3-2 编译没过或 Live Coding 缓存**：关闭 Editor → `tools\kill_editor.ps1` → `tools\build_editor.ps1` → 重启 Editor。

**Q2：AttributeBased 的 Backing Attribute 列表里没有 PrimaryAttributeSet 怎么办？**
A：检查 ASC 是否已经持有该 AttributeSet。A3 阶段是 PlayerState 持有 ASC + 两个 AttributeSet（A3-1/A3-2 实现），如果 PlayerState 还没 AddAttributeSetSubobject，Editor 缓存里看不到这些字段——重启 Editor。

**Q3：PIE 时 HealthFinal 一直是 0？**
A：典型违反 §3.3.4 顺序——一定是 Step 6 在 Step 3 之前 Apply 了。检查 BP_TempInitTester 的 ApplyGameplayEffect 顺序。

**Q4：StaminaCurrent 不停增长超过 100？**
A：A3-1 的 `PostGameplayEffectExecute` 没正确钳制。不属于 A3-3 范围，但建议同步检查。

**Q5：脱战 GE 一直在跑（Tag 过滤无效）？**
A：A3 阶段 `RPG.State.Combat.Active` Tag 还没人挂——这是 A3-5 `URPGCombatStateSubsystem` 的责任，A3-3 阶段只验证 GE 创建正确，Tag 联动留给 A3-5 验收。

**Q6：MMC 是不是 A3 必须做？**
A：**强烈建议 A3-3 阶段就做**，详见 §15。简化版只能让 V3.1/V3.2 通过，V3.3（"派生 GE 链路：手动改 AttackBase / AttackMul / AttackBonus → AttackFinal 按公式同步"）必须靠 MMC 才能验收。本手册 v1.1 已把 MMC 落地步骤写完。

## 15. MMC 实现指南（A3-3 完整版派生公式）

> **预计工时**：0.5d（C++ 3 个 MMC 子类 + 资产改 3 处）

### 15.1 MMC 是什么

`UGameplayModMagnitudeCalculation`（MMC）是 UE GAS 提供的"Modifier 级"计算节点，比 `UGameplayEffectExecutionCalculation`（Execution）轻量。一个 MMC 子类只算一个 float 返回值，由 GE 的 Modifier 调用，可读多个 Captured Attribute 做组合公式 —— 正好满足"读 3 个属性算 1 个目标值"的需求。

| 对比 | MMC | Execution |
|---|---|---|
| 输出 | 单个 Modifier Magnitude | 任意多 OutputModifier |
| 用途 | 派生属性（HealthMax = ...） | 复杂结算（DamageExecution） |
| 接入 GE | Modifier 的 Magnitude Calculation Type = `Custom Calculation Class` | GE 顶层 Executions 数组 |

### 15.3 完整代码：`URPGMMC_HealthMax`

`RPG/Source/RPGGame/AbilitySystem/MMC/RPGMMC_HealthMax.h`：

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.
#pragma once

#include "GameplayModMagnitudeCalculation.h"
#include "RPGMMC_HealthMax.generated.h"

class UObject;

/**
 * HealthMax = HealthBase × (1 + HealthMul) + HealthBonus
 * 读 URPGPrimaryAttributeSet 三字段，写入 URPGHealthSet.HealthMax。
 */
UCLASS()
class URPGMMC_HealthMax : public UGameplayModMagnitudeCalculation
{
    GENERATED_BODY()

public:
    URPGMMC_HealthMax();

    virtual float CalculateBaseMagnitude_Implementation(const FGameplayEffectSpec& Spec) const override;

private:
    FGameplayEffectAttributeCaptureDefinition HealthBaseDef;
    FGameplayEffectAttributeCaptureDefinition HealthBonusDef;
    FGameplayEffectAttributeCaptureDefinition HealthMulDef;
};
```

`RPG/Source/RPGGame/AbilitySystem/MMC/RPGMMC_HealthMax.cpp`：

```cpp
// Copyright Epic Games, Inc. All Rights Reserved.
#include "RPGMMC_HealthMax.h"
#include "AbilitySystem/Attributes/RPGPrimaryAttributeSet.h"

#include UE_INLINE_GENERATED_CPP_BY_NAME(RPGMMC_HealthMax)


URPGMMC_HealthMax::URPGMMC_HealthMax()
{
    HealthBaseDef  = FGameplayEffectAttributeCaptureDefinition(URPGPrimaryAttributeSet::GetHealthBaseAttribute(),  EGameplayEffectAttributeCaptureSource::Target, false);
    HealthBonusDef = FGameplayEffectAttributeCaptureDefinition(URPGPrimaryAttributeSet::GetHealthBonusAttribute(), EGameplayEffectAttributeCaptureSource::Target, false);
    HealthMulDef   = FGameplayEffectAttributeCaptureDefinition(URPGPrimaryAttributeSet::GetHealthMulAttribute(),   EGameplayEffectAttributeCaptureSource::Target, false);

    RelevantAttributesToCapture.Add(HealthBaseDef);
    RelevantAttributesToCapture.Add(HealthBonusDef);
    RelevantAttributesToCapture.Add(HealthMulDef);
}

float URPGMMC_HealthMax::CalculateBaseMagnitude_Implementation(const FGameplayEffectSpec& Spec) const
{
    const FGameplayTagContainer* SourceTags = Spec.CapturedSourceTags.GetAggregatedTags();
    const FGameplayTagContainer* TargetTags = Spec.CapturedTargetTags.GetAggregatedTags();

    FAggregatorEvaluateParameters EvalParams;
    EvalParams.SourceTags = SourceTags;
    EvalParams.TargetTags = TargetTags;

    float Base = 0.f, Bonus = 0.f, Mul = 0.f;
    GetCapturedAttributeMagnitude(HealthBaseDef,  Spec, EvalParams, Base);
    GetCapturedAttributeMagnitude(HealthBonusDef, Spec, EvalParams, Bonus);
    GetCapturedAttributeMagnitude(HealthMulDef,   Spec, EvalParams, Mul);

    return Base * (1.f + Mul) + Bonus;
}
```
