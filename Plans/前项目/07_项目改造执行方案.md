## §1 总体策略选择

### 路径 A：清空重做（彻底派生）

**步骤摘要**
1. 备份 `Source/`、`Plugins/UnrealMCP/`、`Config/` 到外部目录（防呆）
2. 删除 `RPG/` 下除 `.git/`（如有）外的所有内容
3. 复制 Lyra 模板整目录到 `RPG/`
4. 全局重命名 LyraXxx → RPGXxx
5. 修复编译 → 启动验证

**优点**
- 工程结构与 Lyra 标准完全一致
- 没有"半改不改"的模糊地带
- 后续套用 Lyra 文档/教程零成本

**缺点**
- 现有 7 个目录的业务逻辑（19 属性 AttributeSet、AI BT 设计、装备框架、伤害公式）**全部丢失**
- 主理人虽然许可了删除，但这些代码细节是策划案的隐性参考资料
- 一旦后续想确认"现有 AttributeSet 哪些属性该保留"，就只能去 Git 历史找，效率低

---

### 路径 B：增量裁剪（保留参考） ✅ **推荐**

**步骤摘要**
1. **重命名** `Source/` → `Source_Legacy/`（**不参与编译**，仅作参考）
2. **重命名** `RPG.uproject` → `RPG.uproject.legacy`（备份）
3. **重命名** `RPG.sln` → 删除（VS 会重建）
4. **删除** `Saved/`、`Intermediate/`、`Binaries/`、`DerivedDataCache/`
5. **删除** `Content/`（主理人许可，606 个 .uasset 全删）
6. **保留** `Plugins/UnrealMCP/`（外部 MCP 工具，与游戏无关）
7. **保留** `Config/` 内文件，但稍后会大改
8. 复制 Lyra 模板整目录的内容（不含 `.git/`）到 `RPG/`，**冲突文件以 Lyra 为准**
9. 全局重命名 LyraXxx → RPGXxx
10. 修复编译 → 启动验证
11. **后续 Phase**：把 `Source_Legacy/RPG/<目录>` 中需要的字段/逻辑作为参考拷贝到新工程

**优点**
- 保留 Legacy 作"需求确认参考资料"
- 不可逆改动只有 Content/（主理人已许可）
- Source_Legacy 不参与编译，不会污染新工程
- 后续 Phase A3~A6 写新代码时，可以直接 diff 参考 Legacy 实现

**缺点**
- 工程根目录多了一个 `Source_Legacy/` 文件夹（视觉上稍乱）
- 需要在 `.uproject` 和 `.gitignore` 里显式排除 `Source_Legacy/`，避免误编译

---

### 推荐决策

> **选路径 B**。多保留一个文件夹的代价，远小于"想看现有伤害公式但找不到"的代价。
> Legacy 完成迁移后（约 Phase A6 末），再统一删除 `Source_Legacy/`。

## §2 Lyra 模板获取与版本对齐

### 2.1 版本一致性

| 组件 | 版本 | 来源 |
|---|---|---|
| Unreal Engine | **5.7.x**（与 implementer 本机一致） | Epic Launcher |
| Lyra Sample Project | **5.7 对应版本** | 见下文 |

> **不要混用**：UE 5.6 引擎 + Lyra 5.7 模板会编译失败；UE 5.7 + Lyra 5.5 模板会有 IWYU/API 不匹配。

### 2.2 Lyra 5.7 三种获取方式（推荐顺序）

**方式 a：Epic Games Launcher → Marketplace → Lyra Starter Game**（推荐）
- 在 Launcher 的 "Sample" 标签下搜索 "Lyra"
- 选择 5.7 版本下载到任意目录（例如 `D:/UE_Lyra_5.7/`）
- 优点：版本与引擎严格对齐，Epic 官方维护

**方式 b：UE 引擎安装目录 `Engine/Samples/Games/Lyra`**
- UE 5.7 安装时若勾选了 Sample 才会有
- **不推荐**：很多人安装时没勾选；且部分 5.7 引擎版本的 Sample 仅含 ShooterCore 子集

**方式 c：GitHub `EpicGames/UnrealEngine` 仓库 `Samples/Games/Lyra`**
- 需 Epic 账号关联 GitHub
- 切到 5.7 release 分支
- **仅当 a/b 不可用时**

### 2.3 模板完整性校验

下载后，模板根目录应至少包含：
```
LyraStarterGame/
├── Config/
├── Content/
├── Plugins/
│   ├── GameFeatures/        ← Lyra 自带的 GameFeature 插件集合
│   │   ├── ShooterCore/
│   │   ├── ShooterMaps/
│   │   └── TopDownArena/
│   ├── AsyncMixin/
│   ├── CommonGame/
│   ├── CommonLoadingScreen/
│   ├── CommonUser/
│   ├── GameSettings/
│   ├── ModularGameplayActors/
│   └── UIExtension/
├── Source/
│   ├── LyraGame/            ← 主模块
│   ├── LyraGame.Target.cs
│   └── LyraGameEditor.Target.cs
├── LyraStarterGame.uproject
└── ...
```

> 若缺少 `Plugins/GameFeatures/` 或 `Plugins/CommonGame/`，说明模板不完整，**停止操作**，重新下载。

### 2.4 5.7 与 5.5/5.6 主要差异提醒

- 5.7 的 GAS 默认开启 PushModel，旧版的 ReplicatedUsing 写法仍兼容但有 Warning
- 5.7 的 EnhancedInput 把 InputAction Trigger 拆得更细，老 InputConfig 资产可能需要重新指认
- 5.7 移除了几个 Lyra 早期废弃 API，若模板里还有 `LYRA_DEPRECATED` 字样直接删除引用

## §3 命名映射规则（核心）

### 3.1 总原则

| 范围 | 是否改名 | 理由 |
|---|---|---|
| **主模块 LyraGame 的所有类、API 宏、模块名** | ✅ 全改 | 主理人明确指示 |
| **Source/LyraGame/ 下所有 .h/.cpp 文件名** | ✅ 全改 | 与类名一致 |
| **Lyra 子插件（CommonGame、GameSettings、AsyncMixin 等）内部代码** | ❌ 不改 | 这些是"半通用"插件，改名收益小但工作量翻倍 |
| **GameFeatures/ShooterCore 等 GameFeature 插件内部** | ❌ 不改 | ShooterCore 后续会被 RPG 自己的 GameFeature 替换/参考，无需改名 |
| **引擎插件（GameplayAbilities、EnhancedInput、CommonUI）** | ❌ 不改 | 引擎自带，不能动 |
| **GameplayTag 中的 `Lyra.*` 前缀** | ✅ 改为 `RPG.*` | 主模块的 Tag 必须统一 |
| **GameplayTag 中的 `Ability.*` `InputTag.*` `Status.*`（无 Lyra 前缀的）** | ❌ 保留 | 这些是通用约定，不动 |
| **资产文件名 `Lyra*.uasset`** | ⚠️ 保留 | Content/ 会全删，不存在 |
| **Config 文件名 `DefaultLyraXxx.ini`** | ✅ 改 | 与类对应 |

### 3.2 模块级重命名

| Lyra | RPG | 类型 | 备注 |
|---|---|---|---|
| `LyraGame` | `RPGGame` | Module 名 | 不要用 `RPG`（与原项目重名） |
| `LYRAGAME_API` | `RPGGAME_API` | API 宏 | 全文件批量替换 |
| `LyraGame.Build.cs` | `RPGGame.Build.cs` | 文件名 | |
| `LyraGame.Target.cs` | `RPGGameTarget.Target.cs` ⚠️ | 文件名 | UE Target 文件命名约定 |
| `LyraGameEditor.Target.cs` | `RPGGameEditorTarget.Target.cs` | 文件名 | |
| `class LyraGameTarget` | `class RPGGameTarget` | 类名 | Target.cs 内部 |
| `class LyraGameEditorTarget` | `class RPGGameEditorTarget` | 类名 | |
| `LyraGame.h` | `RPGGame.h` | 文件 | 模块入口头 |
| `LyraGame.cpp` | `RPGGame.cpp` | 文件 | |
| `class FLyraGameModule` | `class FRPGGameModule` | 类名 | IMPLEMENT_PRIMARY_GAME_MODULE 里 |
| `IMPLEMENT_PRIMARY_GAME_MODULE(FLyraGameModule, LyraGame, "LyraGame")` | `IMPLEMENT_PRIMARY_GAME_MODULE(FRPGGameModule, RPGGame, "RPGGame")` | 宏调用 | |
| `LogLyra`（LogCategory） | `LogRPG` | 日志通道 | |
| `LyraStarterGame.uproject` | `RPGGame.uproject` ⚠️ | 文件名 | 见下方说明 |

> **关于 .uproject 名称**：建议用 `RPGGame.uproject` 而不是 `RPG.uproject`，原因：
> - 避免与历史的 `RPG.uproject` 重名（已 .legacy 备份）
> - .uproject 名通常与主模块名一致
> - 后续打包出来的 exe 名也会是 RPGGame.exe，更专业
>
> **如果主理人坚持要 `RPG.uproject`**：把 .uproject 文件名改为 `RPG.uproject`，但 .uproject 内部的 `Modules.Name` 仍写 `"RPGGame"`，二者不必相同。

## §6 编译修复指南

### 6.1 常见错误类型与解法

| 错误类型 | 现象 | 解法 |
|---|---|---|

| 资产 outer 错误 | `Asset references invalid class` | 同上 |

|---|---|---|---|

## §12 给 implementer 的最终提醒

1. **不要纯文本批量替换**。Rider Refactor → Rename 是唯一推荐方式。

#### Step 2 · 清理 RPG 残留（10 min）

```powershell
$rpg = "D:\UE_Work\FDRPG\RPG"
```

**失败处理**：某文件占用 → 关闭所有相关进程（Task Manager 查 UnrealEditor / MSBuild / Rider）

#### Step 3 · 拷贝 Lyra 模板（排除 5 个业务 GameFeature）（30~60 min）

```powershell
$src = "D:\UE_Work\FDRPG\LyraStarterGame"

robocopy $src $dst /E `
  /XD ".git" "Saved" "Intermediate" "Binaries" "DerivedDataCache" `
```

**预期**：

- `Plugins/GameFeatures/` 下**无任何子目录**（输出为空）

**失败处理**：

#### Step 4 · 改名 LyraGame → RPGGame（60~90 min）

```powershell
$rpg = "D:\UE_Work\FDRPG\RPG"

# 1. Source/LyraGame/ → Source/RPGGame/
Rename-Item "$rpg\Source\LyraGame" "RPGGame"

# 2. Build.cs / 模块入口文件改名

Rename-Item "$rpg\Source\RPGGame\LyraGame.h"        "RPGGame.h"
Rename-Item "$rpg\Source\RPGGame\LyraGame.cpp"      "RPGGame.cpp"

# 3. Target.cs 改名
Rename-Item "$rpg\Source\LyraGame.Target.cs"       "RPGGameTarget.Target.cs"
Rename-Item "$rpg\Source\LyraGameEditor.Target.cs" "RPGGameEditorTarget.Target.cs"

Rename-Item "$rpg\LyraStarterGame.uproject" "RPGGame.uproject"
```

然后**手动编辑以下 5 个文件**（用 VSCode/记事本，不涉及 UE 类改名）：

| 文件 | 内容修改 |
|---|---|
| `RPGGame.uproject` | `"Name": "LyraGame"` → `"Name": "RPGGame"`；Plugins 字段**追加** `{"Name":"UnrealMCP","Enabled":true}` 和 `{"Name":"EditorScriptingUtilities","Enabled":true}`（RPG 原有） |
| `Source/RPGGame/RPGGame.Build.cs` | `public class LyraGame` → `public class RPGGame`；构造函数 `LyraGame(...)` → `RPGGame(...)` |
| `Source/RPGGame/RPGGame.h` | `#include` 路径无需改（头文件内部） |
| `Source/RPGGame/RPGGame.cpp` | `#include "LyraGame.h"` → `#include "RPGGame.h"`；`FLyraGameModule` → `FRPGGameModule`；`IMPLEMENT_PRIMARY_GAME_MODULE(FLyraGameModule, LyraGame, "LyraGame")` → `IMPLEMENT_PRIMARY_GAME_MODULE(FRPGGameModule, RPGGame, "RPGGame")` |
| `Source/RPGGameTarget.Target.cs` | `class LyraGameTarget` → `class RPGGameTarget`；构造函数同名改；`ExtraModuleNames.Add("LyraGame")` → `ExtraModuleNames.Add("RPGGame")` |
| `Source/RPGGameEditorTarget.Target.cs` | `class LyraGameEditorTarget` → `class RPGGameEditorTarget`；同上 |

**说明**：以上 6 个文件是编译系统必须改的**最小集**；其他几百个 Lyra 类的改名放到 Day 2。

### 13.4 Day 1 常见故障速查

| 现象 | 原因 | 解法 |
|---|---|---|
| robocopy 返回码 ≥ 8 | 权限/文件被锁 | 关闭所有 UE/VS；以管理员运行 PowerShell |
