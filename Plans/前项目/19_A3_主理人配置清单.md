### 7.1 4 样式参数表

└─ [Text_Damage] (Common Text / UCommonTextBlock, Anchor=Center)

### 7.3 动画建议（在 Animations 面板创建）

### 7.4 Init Damage Popup 蓝图实现

> **A3 阶段使用方案 A**（直接判 3 个布尔），未来 A6 美术化阶段切换到方案 C（GameplayTag + Switch）。详见 §7.6。

#### 方案 A：3 段 Branch（A3 当前实现，最快打通）

```
Init Damage Popup
  ↓
[Branch] bIsCrit ?
  ├─True → [Crit 样式]  : SetText(Amount→Text), SetColor(Gold 1,0.84,0,1), SetFont.Size=40
  └─False
      ↓
      [Branch] Amount < 0 ?
      ├─True → [Healing 样式] : SetText("+"+Abs(Amount)), SetColor(Green 0.2,0.9,0.3,1), SetFont.Size=28
      └─False
          ↓
          [Branch] bIsBlocked ?
          ├─True  → [Blocked 样式] : SetText("BLOCK"), SetColor(Gray 0.6,0.6,0.6,1), SetFont.Size=24
          └─False → [Normal 样式]  : SetText(Amount→Text), SetColor(White), SetFont.Size=28
  ↓ (4 路汇合)
PlayAnimation(Anim_FloatUp)
  ↓
Set Timer by Event 1.0s → RemoveFromParent
```

> **注意**：UE 蓝图没有 Switch on String 节点（只支持 int / Enum / Name / GameplayTag），所以 C++ 传过来的 `StyleHint: FString` **在方案 A 里直接忽略**，4 样式由前面 3 个布尔/数值参数完整区分。

#### 方案 B（备选，可读性略好）：Switch on Name

把 `StyleHint` 经 `String to Name` 转一次，再用 `Switch on Name` 节点（Pin Names: Crit / Healing / Blocked / Normal）。多一次 String→Name 转换开销，A3 不推荐。

### 7.6 后续优化（A6 美化阶段切换到方案 C）

> **决策时间**：2026-05-15
> **当前状态**：A3 用方案 A 已能完整覆盖 4 样式 + V3.10 验收
> **触发切换条件**：A6 阶段需要新增第 5+ 种样式（如 MISS / Immune / Debuff Tick / 格挡耐力击溃 等）

**方案 C：把 StyleHint 改为 `FGameplayTag`，蓝图用 `Switch on Gameplay Tag` 节点**

**改动点**（A6 阶段执行，A3 不动）：
1. **C++**：`URPGDamagePopupWidget::InitDamagePopup` 第 4 个参数 `const FString& StyleHint` 改为 `FGameplayTag StyleTag`
2. **C++**：`URPGDamageNumberSubsystem::OnDamagePopupReceived` 现有的 `StyleName` 字符串判定改为 `FGameplayTag StyleTag`，对应到 4 个新 Tag：
   - `RPG.Damage.Style.Normal`
   - `RPG.Damage.Style.Crit`
   - `RPG.Damage.Style.Healing`
   - `RPG.Damage.Style.Blocked`
   - （A6 扩展）`RPG.Damage.Style.Miss` / `RPG.Damage.Style.Immune` / ...
3. **GameplayTags**：在 `RPGGameplayTags.h/.cpp` 注册上面 N 个 Tag
4. **Widget BP**：`Init Damage Popup` 节点替换为 `Switch on Gameplay Tag`，每个 Pin 对应一种样式

**优势**：
- ✅ 新加样式只需注册 Tag + Widget BP 加 Pin，不动 C++
- ✅ Tag 层次化（`RPG.Damage.Style.*`）便于通配匹配
- ✅ 与项目其它 GameplayMessage / Cue 系统一致
- ✅ 编辑器自动补全，不会拼错字符串

**A6 切换 ETA**：约 1.0 工作日（代码改 30 min + Tag 注册 15 min + Widget BP 重建 4 样式映射 15 min）。

> **结论**：A3 阶段 §7.4 方案 A 不需要追求"未来兼容"，先打通链路。A6 美术化时连同 4 样式描边/Niagara 特效升级一并切方案 C。

## 8. 步骤 7：A3-DOD 15 条验收

> 启动 Editor → PIE → 控制台输入命令验证。Editor 启动时按 ` 键打开控制台。

### 8.1 验证方式（控制台命令 + 键盘）

> **UE 5.7 + Lyra 没有逐属性查询的命令**（`gas.DebugAttribute` / `AbilitySystem.DebugAttribute` 都不存在）。
> Lyra 的标准路径是 **HUD 调试视图**：在屏幕上画出 ASC 的全量信息（含所有 AttributeSet 字段、当前 ActiveGameplayEffects、已授予的 Abilities）。

#### 步骤 A：开启调试视图

PIE 启动后按 ` 键打开控制台，输入：

```
showdebug abilitysystem
```

回车后**屏幕左上角**会出现一大段调试文本（不在 Output Log 里！）。

#### 步骤 B：循环切换调试类别

项目已把这个功能绑到 **`End` 键**（`URPGCheatManager::CycleAbilitySystemDebug`）：

- **按一次 End 键** → 切到下一个调试分类（Attributes / GameplayEffects / Abilities / Tags）
- **再按一次** → 下一类
- **持续按** → 4 类循环

或者控制台手动：

```
AbilitySystem.Debug.NextCategory
```

#### 步骤 C：定位到 Attributes 类别

调试视图顶部会显示当前类别名（如 `Category: Attributes`），按 End 键循环到 **Attributes** 时，屏幕上就能看到：

```
URPGHealthSet
  HealthFinal:    100.000
  HealthMax:      100.000
  HealthHealing:  0.000 (Meta)
  HealthDamage:   0.000 (Meta)
  StaminaCurrent: 100.000
  StaminaMax:     100.000

URPGPrimaryAttributeSet
  HealthBase:     100.000
  AttackBase:     10.000
  ...
  AttackFinal:    10.000
  DefenseFinal:   10.000
  MoveSpeed:      600.000
  CritChance:     0.050
  CritDamage:     0.500
```

> **如果没看到 URPGHealthSet / URPGPrimaryAttributeSet 这两段** → AttributeSet 没挂上 ASC（链路断在 PlayerState/Pawn 层），跳到 §10 风险表。
>
