## §9 启动崩溃修复（v1.3 新增）

> A1 改名 + 裁剪期间遗留了一组**只在 Editor 进入 Init 阶段才会触发**的硬编码地雷，导致**双击启动 Editor 立即崩**（Fatal in `RPGAssetManager.cpp:186` / `RPGExperienceManagerComponent.cpp:61`）。本节记录定位与修复经过。

### 9.1 故障现象

启动 Editor → 引擎初始化阶段（`UEngine::Init` → AssetManager StartInitialLoading）直接 Fatal：

```
Fatal error: Failed to load GameData asset at /Game/DefaultGameData.DefaultGameData. Type RPGGameData.
LogAssetManager: Display: Ignoring PrimaryAssetType RPGExperienceDefinition - Conflicts with LyraExperienceDefinition - Asset: B_LyraDefaultExperience
LogAssetManager: Display: Ignoring PrimaryAssetType RPGUserFacingExperienceDefinition - Conflicts with LyraUserFacingExperienceDefinition - Asset: DA_Frontend
```

第二条 Callstack（更早会触发）：

```
Assertion failed: AssetClass [RPGExperienceManagerComponent.cpp:61]
  → SetCurrentExperience（拿不到 PrimaryAsset 路径）
  → ARPGGameMode::OnMatchAssignmentGiven (Line 298)
  → HandleMatchAssignmentIfNotExpectingOne (Line 164)
```

### 9.2 根因（4 处遗留）

| # | 位置 | 问题 | 影响 |
|---|---|---|---|
| 1 | `RPGGameMode.cpp:160` | `FPrimaryAssetType("LyraExperienceDefinition")` 硬编码字符串 | fallback DefaultExperience 找不到资产 → check(AssetClass) Fatal |
| 2 | `RPGUserFacingExperienceDefinition.h:28` | `meta=(AllowedTypes="LyraExperienceDefinition")` | UI 选择器过滤不出资产 |
| 3 | `RPGDeveloperSettings.h:53` | `meta=(AllowedTypes="LyraExperienceDefinition")` | PIE 中 ExperienceOverride 选不到资产 |
| 4 | `AnimNotify_RPGContextEffects.h:83` | `meta=(AllowedClasses="/Script/LyraGame.LyraContextEffectsLibrary")` | AnimNotify 字段不可选 |

**最深层根因**：`B_LyraDefaultExperience.uasset` / `DA_Frontend.uasset` / `DefaultGameData.uasset` 这些资产在 **.uasset 文件的元数据里序列化的 PrimaryAssetType 仍是旧 Lyra 名字**（创建当时由 Lyra 类决定）。AssetManager 扫描时既看到 ini 注册的 `RPGExperienceDefinition`，又从资产元数据反推出 `LyraExperienceDefinition`，二者冲突 → Ignore → fallback 也失败。CoreRedirects 不能修这一层。

### 9.3 修复

| 修改 | 文件 | 说明 |
|---|---|---|
| 1 | `RPGGameMode.cpp:160` | `"LyraExperienceDefinition"` → `URPGExperienceDefinition::StaticClass()->GetFName()` |
| 2 | `RPGUserFacingExperienceDefinition.h:28` | `AllowedTypes="LyraExperienceDefinition"` → `"RPGExperienceDefinition"` |
| 3 | `RPGDeveloperSettings.h:53` | 同上 |
| 4 | `AnimNotify_RPGContextEffects.h:83` | `AllowedClasses="/Script/LyraGame.LyraContextEffectsLibrary"` → `"/Script/RPGGame.RPGContextEffectsLibrary"` |
| 5 | `DefaultGame.ini` | 在 `[/Script/Engine.AssetManagerSettings]` 段新增 5 条 `PrimaryAssetIdRedirects`，把旧 Lyra* 的 PrimaryAssetType 兜底重定向到 RPG*（解决资产元数据冲突的核心修复） |

```ini
+PrimaryAssetIdRedirects=(OldName="LyraExperienceDefinition",NewName="RPGExperienceDefinition",bMatchPartialName=True)
+PrimaryAssetIdRedirects=(OldName="LyraUserFacingExperienceDefinition",NewName="RPGUserFacingExperienceDefinition",bMatchPartialName=True)
```

### 9.5 经验沉淀

未来再做大规模改名时，除 CoreRedirects（C++ 类符号层）外，**还要检查这三层**：

1. **C++ 字符串字面量**：`FPrimaryAssetType("Xxx")` / `FName("XxxAsset")` / `FString("/Script/...")` 这种**绕过类型系统的字符串硬编码**，CoreRedirects 修不了，必须 grep + 改源码（已加到 `tools/audit_source_tags.ps1` 后续审计范围）
2. **UPROPERTY 的 Meta 标记**：`AllowedTypes` / `AllowedClasses` / `MetaClass` 都是字符串，CoreRedirects 修不了
3. **资产元数据**：`.uasset` 序列化的 PrimaryAssetType 字段，要用 `[/Script/Engine.AssetManagerSettings]` + `PrimaryAssetIdRedirects` 兜底

### 9.6 v1.4 复发修复（PIE 阶段崩溃 + 治本 ResavePackages）

**v1.3 的修复（headless 阶段）做完后，用户实际启动 Editor + 进 PIE 时再次崩溃在同一行 `RPGExperienceManagerComponent.cpp:61`**。深入分析后发现：

- `PrimaryAssetIdRedirects` 只在"别处引用此 Asset 时"重映射，**不能治"资产文件本身的元数据自报家门"问题**
- AssetManager 扫描时仍然报 `Ignoring PrimaryAssetType RPGExperienceDefinition - Conflicts with LyraExperienceDefinition - Asset: B_LyraDefaultExperience`
- 后续 `HandleMatchAssignmentIfNotExpectingOne` 的最终 fallback 用了这个被 Ignore 的资产，导致 `SetCurrentExperience` 拿不到 AssetClass 而 `check()` 致命

**根治三步**：

| 步骤 | 操作 | 文件 |
|---|---|---|
| 1 | 在 `OnMatchAssignmentGiven` 调用 `SetCurrentExperience` 前先 `GetPrimaryAssetData` 校验，失败时 Error Log + 退出（防御层） | `RPGGameMode.cpp` |
| 2 | 跑 `ResavePackages` Commandlet 把 `/Game` 下 **2852/2853 个资产**全部重新序列化（治本，让 CoreRedirects 真正写回资产元数据，应用 `LyraExperienceDefinition → RPGExperienceDefinition` 等所有改名） | tools/_out/_resave_all.ps1 |
| 3 | 用 `UnrealEditor.exe -game` 模式跑 12 秒，验证 InitGame → HandleMatchAssignmentIfNotExpectingOne → SetCurrentExperience 完整链路 | 工具 |

**ResavePackages 数据**：2852/2853 packages 重写（255 秒），0 fatal。覆盖所有 Lyra 残留资产（`B_LyraDefaultExperience` / `B_LyraFrontEnd_Experience` / `DA_Frontend` / `DefaultGameData` / `TeamDA_*` 等）。

> ⚠️ **任何项目的大规模改名后，必须跑一次 ResavePackages**。CoreRedirects 只在加载时生效，资产文件落盘前的旧字符串元数据不会被 redirect 修复 —— Editor 启动扫描时仍报 PrimaryAssetType 冲突。

### 9.8 v1.5 编辑 UIPolicy 蓝图崩溃修复 + Editor 显示文本去 Lyra

#### 9.8.1 故障现象

主理人在创建 `B_RPG_UIPolicy`（父类原版 `UGameUIPolicy`）后，**点 Class Defaults 的 Layout Class 下拉框选项时 Editor 立即 Fatal**：

```
Fatal error: [Casts.cpp:10] Cast of Package /Game/UI/B_RPG_UIPolicy to GameUIManagerSubsystem failed
  → UGameUIPolicy::GetOwningUIManager() at GameUIPolicy.cpp:33
  → UGameUIPolicy::GetWorld() at GameUIPolicy.cpp:38
  → FEditorViewportClient::OnObjectTransacted at EditorViewportClient.cpp:7116
  → ... PostTransacted → SPropertyEditorClass::OnClassPicked
```

#### 9.8.2 根因（CommonGame 插件设计缺陷）

```cpp
// CommonGame/Source/Public/GameUIPolicy.h:56
UCLASS(MinimalAPI, Abstract, Blueprintable, Within = GameUIManagerSubsystem)
class UGameUIPolicy : public UObject { ... }

// CommonGame/Source/Private/GameUIPolicy.cpp:31-38
UGameUIManagerSubsystem* UGameUIPolicy::GetOwningUIManager() const
{
    return CastChecked<UGameUIManagerSubsystem>(GetOuter());   // ← 编辑 CDO 时 Outer 是 Package
}
UWorld* UGameUIPolicy::GetWorld() const
{
    return GetOwningUIManager()->GetGameInstance()->GetWorld();
}
```

- 运行时：`UIManagerSubsystem::Initialize` 调 `NewObject<UGameUIPolicy>(this, PolicyClass)`，Outer 是 Subsystem，`CastChecked` 通过
- 编辑 CDO：Outer 是 Package，`CastChecked` 必崩
- 任何 `PostTransacted` 触发的 `GetWorld()`（如 PropertyEditor 设值）都会触发崩溃

#### 9.8.3 修复

新增 `URPGUIPolicy` 子类（`RPG/Source/RPGGame/UI/Subsystem/RPGUIPolicy.h+cpp`），override `GetWorld`：

```cpp
UWorld* URPGUIPolicy::GetWorld() const
{
    if (HasAnyFlags(RF_ClassDefaultObject | RF_ArchetypeObject))
        return nullptr;  // 编辑 CDO/Archetype 安全返回
    UObject* Outer = GetOuter();
    if (!Outer) return nullptr;
    UGameUIManagerSubsystem* OwningUIManager = Cast<UGameUIManagerSubsystem>(Outer);
    if (!OwningUIManager) return Outer->GetWorld();  // Outer 链兜底
    UGameInstance* GameInstance = OwningUIManager->GetGameInstance();
    return GameInstance ? GameInstance->GetWorld() : nullptr;
}
```

主理人创建 `B_RPG_UIPolicy` 时**父类必须选 `RPGUIPolicy` 而不是原版 `GameUIPolicy`**，否则同样会崩。15A 主理人执行清单已更新。

#### 9.8.4 Editor 显示文本去 Lyra（顺手做的）

主理人反馈"创建 DA_RPG_PawnData 时菜单还有 Lyra 字样"。本质是 A1 改名时**只改了类名没改 UPROPERTY 的反射元标签**，Editor 是按 `DisplayName` / `Category` 显示给用户的。本次清扫范围：

| 类型 | 数量 | 影响位置 |
|---|---|---|
| `DisplayName="Lyra*"` | 15 处 | Pick Class 对话框、AssetTypeActions 列表 |
| `Category="Lyra...|"` | 114 处（31 文件） | Detail 面板的折叠分组、BlueprintCallable 节点搜索菜单 |
| `Category=Lyra`（无引号） | 6 处 | 同上 |
| **共计** | **135 处** | |

清扫脚本：`tools/_out/_purge_lyra_meta.ps1`（保留下来供后续审计回归）。

保留下来的（不影响用户体验，且改了反而要联动 BP/Tag 搜索）：
- `LOCTEXT_NAMESPACE "Lyra*"` / `NSLOCTEXT("Lyra*", ...)` — 本地化命名空间纯 ID
- CVar 名 `LyraPC.*` / `LyraCheat.*` — 控制台命令名（用户键入习惯）
- Stat 名 `Lyra_Latency_*` — 性能统计 ID
- Tag 标识 `LyraAbilitiesReady` — 蓝图侧已绑定
- `LyraTest.pem` — 证书文件名

#### 9.8.5 经验沉淀（追加）

C++ 改名工程 **5 层全清单**（CoreRedirects 之外）：

1. **C++ 字符串字面量**（`FPrimaryAssetType("Xxx")` / `FName(...)` / `FString("/Script/...")`）
2. **UPROPERTY Meta 标记**（`AllowedTypes` / `AllowedClasses` / `MetaClass`）
3. **资产元数据**（PrimaryAssetIdRedirects + ResavePackages）
4. **反射显示标签**（`UCLASS Meta=DisplayName=` / `UPROPERTY Category=` / `UFUNCTION Category=`）— 不影响功能但用户能看到 Lyra
5. **Editor CDO 行为**（如 UIPolicy 这种 `Within=` 强约束 UCLASS，编辑 CDO 时 GetWorld() 这类需求要专门 override 防崩）
