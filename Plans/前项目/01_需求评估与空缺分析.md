## 总览结论（先读这里）

### 关键风险 Top 3

1. **战斗操作复杂度严重超标**  
   俯视角 ARPG 同时背了"格挡+格挡反击+冲刺闪避+跳跃+主副普攻连段+主副各 2 技能+切入+切出+大招"——总计 **11~13 个独立战斗输入**，比 Hades（5）、暗黑 4（6 技能槽）、Returnal（5）都多。键位会爆，玩家学习曲线在 Demo 阶段直接崩。**必须裁剪。**

2. **能量系统的语义没有定义**  
   "切入耗能、切出耗能、大招耗能" + "%充能倍率" 同时存在，但**完全没说能量怎么获得、上限多少、是不是单池、是否分主副**。这是战斗系统的核心调度变量，模糊到这种程度无法落地。属于 P0 必须本周敲死的设计点。

3. **三层成长系统（武器 / 附魔 / 角色强化）未做层级区分**  
   D1 局内强化、D3 拾取附魔、UI 里的"角色强化系统"和"武器附魔系统" —— 4 个名词，含义重叠，关系不清。如果不在动工前把"局内 vs 局外""装备槽 vs 词条池""主动选择 vs 被动触发"切清楚，开发出来一定是俄罗斯套娃。

### 强烈建议补充的 Top 5 空缺模块

1. **核心玩法循环（Core Loop）定义** —— 单局多长、为什么打第二局、长期目标是什么，**必须在动工前敲死**
2. **世界观与"为什么"的一句话定位** —— "万界副本穿梭"目前只是名字，没有动机骨架，会拖累 D1.机制改变、强化与剧情结合等高价值设计
3. **货币体系分层** —— 当前只有"金币"一种，肉鸽至少需要 2~3 层（局内消耗币 / 局外永久币 / 稀有解锁币）
4. **战斗时长目标（节奏锚点）** —— 小怪 X 秒、精英 X 秒、Boss X 分钟、单局 X 分钟，没有这个数值带，所有数值都是空中楼阁
5. **死亡惩罚与失败回收策略** —— 现在只写了"存档点复活"，肉鸽里"死亡=本局结束 + 带走什么 + 解锁什么"是核心驱动力

### Demo 阶段建议裁剪掉的功能

| 功能 | 裁剪理由 | 何时再做 |
|---|---|---|
| 跳跃 | 俯视角 ARPG 跳跃几乎无玩法收益（Hades/暗黑/挺进地牢都没有），动画/碰撞/平台跳关成本高 | 永久砍 |
| 格挡 + 格挡反击 | 与冲刺闪避高度重复，俯视角下时机判定模糊 | 移到 v0.2 二期，Demo 只保留闪避 |
| 切入 + 切出 双能量技 | 简化为"切换武器=切入触发对应被动光环 1 次"，砍掉"切出"独立按键 | 砍切出 |
| 主副手各 2 技能（共 4 个） | 砍到主手 2 + 副手 1（共 3 个） | 二期回补 |
| 肉鸽强化的"自动化 / 连锁召唤 / 随机释放技能" | 这三类是 Hades 后期 Boon 才出现的高复杂度词条，需要大量内容支持 | 砍到二期 |
| 强化与剧情结合 | 极吃文案与系统耦合，Demo 阶段先做"纯数值+机制改变"两类 | 砍到二期 |
| 成就系统 | Demo 验证玩法即可，成就属于留存机制 | 砍到正式版 |
| 外观系统（角色/技能特效/武器模型更换） | 美术资产成本极高 | Demo 阶段每个武器 1 套即可 |
| 局外的"特殊武器解锁"完整树 | Demo 解锁 2~3 把武器够了，完整树后置 | 二期 |

### A. 游戏定位

| 评估项 | 结果 |
|---|---|
| 合理性 | ⚠️ 有疑问 |
| 疑问点 | "俯视角 + 即时战斗 + 肉鸽 + 主副武器 + 万界副本" 5 个标签都对，**但缺了一个最重要的标签：核心情绪**。Hades 是"快节奏爽 + 嘴炮叙事"；暗黑 4 是"打装备多巴胺"；Returnal 是"高难硬核 + 叙事悬疑"；死亡细胞是"手感 + 速通"。本作要哪种？ |

### B. 战斗系统

#### B1 基础动作（行走/奔跑/跳跃/冲刺闪避/格挡+反击）

| 评估项 | 结果 |
|---|---|
| 合理性 | ❌ 不合理（过载） |
| 疑问点 | 1) 跳跃在俯视角下有什么玩法？跳箱子？跳避技能？参考的同类游戏（Hades/暗黑/挺进地牢/死亡细胞——后者非俯视角）**都没有跳跃**，因为 8 向移动+闪避已经覆盖全部位移需求。2) 格挡+反击 vs 冲刺闪避 功能高度重复，都是"提供无敌帧/反制窗口"。 |
| 建议 | **砍掉跳跃**。**格挡 vs 闪避二选一**：建议保留**冲刺闪避**（俯视角下方向感更强、动画成本低），格挡放二期。如果非要做格挡反击，那就砍冲刺闪避（参考艾尔登法环走"防反流"，但这风格不适合俯视角肉鸽）。 |

#### B2 武器技能（被动+切入+切出+普攻+主副技能 4 个+大招）

| 评估项 | 结果 |
|---|---|
| 合理性 | ❌ 不合理（键位爆炸 + 概念混乱） |
| 疑问点 | 1) **键位统计**：普攻 1 + 切入 1 + 切出 1 + 主技能 2 + 副技能 2 + 大招 1 + 闪避 1 + 格挡 1 = **9 个战斗键**，加移动 4 + 交互 1 + 武器切换 = **15+ 键**。2) "切入" "切出" 字面是什么意思？是切换武器时触发的 buff？还是切到某武器时打一招？还是切下场时副手放一招？需求里没说。3) 大招"耗能无 CD"+ 技能"无耗有 CD" → 如果充能快，大招会比技能放得勤，这违反直觉（大招应是最稀有）。Hades 终极技要积满整条专属能量条，需求 ~30~60 秒打满 1 次。 |
| 建议 | **战斗键裁剪到 6 个**：普攻 / 主技能 1 / 主技能 2 / 副手协同（切入+切出合并为 1 键）/ 大招 / 闪避。具体方案见下方"切入切出语义建议"。 |

##### 切入切出语义建议（重要 P0 决策）

> 这是本次评审里最需要主 agent 拍板的一个语义问题，给三个备选方案：

| 方案 | 描述 | 参考 | 优势 | 劣势 |
|---|---|---|---|---|
| **A. 协同攻击式** | 主手驻场，副手只在按"协同键"时跳出来打一招（消耗能量），打完即回 | 原神切人后切回 | 节奏明快、键位少、Demo 落地容易 | 副手"驻场感"弱 |
| **B. 切换上场式** | 按键直接把主副手互换上场，原副手变主手；切换瞬间触发"切入技"，被切下的触发"切出技" | 鬼泣 5 武器切换、原神切人 | 战斗 Build 深度高 | 双套连段动画 = 资产 ×2，键位混乱 |
| **C. Buff/光环式** | 副手不上场，只提供持续被动光环 + 1 个能量主动技（按 Q 触发副手特殊技） | 暗黑 4 副手附魔、Hades Cast | 实现最简、概念清晰 | 副手"参与感"最弱 |

**策划推荐：方案 A（协同攻击式）**。  
理由：1) 一个键位解决切入切出双概念；2) "主驻场副辅助"的需求语义最匹配；3) 副手有露脸但不抢戏；4) Demo 期资产成本可控（副手只需要 1 段协同动画 + 1 个特效）。

## 任务2：空缺模块识别

> 对照标准 ARPG 肉鸽（Hades / 暗黑 4 / Returnal / 挺进地牢 / 死亡细胞），列出当前需求**完全没覆盖**或**严重不全**的模块，按优先级排序。

### 2.1 【P0 必须补】核心玩法循环（Core Loop）定义

**现状**：完全空缺。需求只描述了"零件"（战斗、关卡、强化、成长），没有描述"玩家从开始到结束的体验循环"。

**需要回答**：
- **单局长度**目标（建议 20~25 分钟）
- **单局节奏**：开局 2 分钟选武器→中段 15 分钟刷房+滚雪球→末段 5 分钟 Boss 战
- **死后驱动**：玩家为什么开第二局？（建议：积累魂币换永久属性 + 解锁新武器/新词条，10~15 局通关）

### 2.4 【P0 必须补】能量系统完整定义

**现状**：B2 只说"切入耗能、切出耗能、大招耗能 + %充能倍率"，**完全没说怎么获取**。

**必须本周敲死的字段**：

| 字段 | 含义 | 建议值 | 备注 |
|---|---|---|---|
| EnergyMax | 能量上限 | 100 | 公式锚点 |
| EnergyOnAttack | 普攻命中获得 | 3~5 | 主要来源 |
| EnergyOnHurt | 受击获得 | 5 | 鼓励不无脑闪避 |
| EnergyOnCrit | 暴击额外获得 | +2 | 与暴击流联动 |
| EnergyRegenPerSec | 自然回复 | 0~1 | 极慢，不依赖站撸 |
| 切入消耗 | 协同攻击 | 25 | 一局可用 ~10 次 |
| 大招消耗 | 大招 | 100（满条） | 一局可用 2~4 次 |
| %充能倍率 | 上述获取 ×（1+rate） | 0%~+150% 词条带 | 充能流核心属性 |

**关键设计原则**：大招"满条释放"，技能"独立 CD"，二者不冲突——大招是高回报终结技，技能是稳定 DPS 来源。这样回到了直觉："大招最稀有"。

| 4 暴击 = 基础暴击 + %暴击 | "基础暴击"在属性表里没列，是哪来的？武器自带？职业自带？ | 明确"基础暴击 = 武器固定值 5%~15%"，词条加 %暴击叠加上 |
| 5 暴伤 = 基础暴伤 + %暴伤 | 同上 | 明确"基础暴伤 = 150%（全角色统一）"，词条加 %暴伤 |
| 8 承伤率 = 500/(500+防御×(1-防御穿透)) | 500 是常数锚点，但**没说玩家面板防御和怪物防御的数量级**——如果都是 100，承伤率 = 500/600 = 83%（减伤 17%），对吗？是否符合数值预期？ | 在数值锚点表里明确：玩家防御初始 50，封顶 500；怪物防御 50~300。即玩家最多减伤 38%，怪物最多减 23% |
| 9 充能值 = 基础充能 ×(1+%充能倍率) | "基础充能"是哪类事件触发的？ | 见任务 2.4 表，区分 EnergyOnAttack/OnHurt/OnCrit/PerSec 多个来源 |
| 10 韧性减少值 = 基础破韧 ×(1+%击破加成) | "基础破韧"是单次攻击的固定值还是按武器？ | 建议每个攻击行为（普攻段、技能、大招）配置独立 BaseBreak 值，词条放大 %击破加成 |
| 11 最终伤害 = 未减免×承伤率×(1+%增伤)×(1-%减伤) | %增伤来自玩家，%减伤来自怪物——还是双方都可有？ | 明确：%增伤 = 攻击方词条；%减伤 = 受击方词条。逻辑上都成立 |
| 12 吸血量 = 实际伤害×%吸血 | 是否对所有伤害生效？包括 DoT？包括 AOE 范围伤害？大招？ | Demo 设定：**只对普攻和主手技能生效**，大招/DoT 不吸血（避免无脑站撸） |
| 13 血量回复 = 基础回复值×(1+施加方治疗效率) | "施加方"是谁？吸血是自己施加自己？ | 吸血来源 = 攻击方自身，治疗效率读自身。其他治疗（药水、奇遇）也读受疗者自身的治疗效率 |
