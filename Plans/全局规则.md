# Dolphin 全局规则

> 项目级强约束，所有里程碑开发都需遵守。
> 由 `godot-rpg-rule-keeper` agent 在指定触发时机做合规扫描，输出 `Plans/规则检查报告_YYYYMMDD.md`。
> Agent 仅生成报告，不直接修改代码（高风险违规由人工或主 agent 修复）。

---

## Agent 触发时机

| 触发点 | 启用 | 说明 |
|---|---|---|
| **T5**：用户显式说"跑一下规则检查" / "做规则扫描" / "rule-keeper 检查"等 | ✅ | **唯一启用入口** |
| ~~T1~~：每个里程碑完成后、验收前 | ❌ 已禁用（2026-05-19） | 改为按需，用户在适当时机主动触发 |
| ~~T2~~：每次新增 Autoload / 组件类 / Ability 或 GE 资源后 | ❌ 已禁用（2026-05-19） | 同上 |
| ~~T3~~：重构目录结构或批量重命名脚本后 | ❌ 已禁用（2026-05-19） | 同上 |
| ~~T4~~：每个 session 开始时 | ❌ 已禁用 | 噪声过大 |

> **执行约定**：开发 agent / 主 agent **不得主动**调用 `godot-rpg-rule-keeper`；
> 用户在希望做合规扫描时显式说"检查规则 / rule-keeper / 跑规则"等关键词，主 agent 才派发。
> 自身落地的代码仍须遵守本文规则清单（仅是"是否生成 rule-keeper 报告"这一动作改为按需）。

---

## 严重级定义

- **Error**：必须修复，违规阻塞验收
- **Warning**：建议修复，记录但不阻塞

## 规则清单

### R-ARCH-01 · 跨模块通信走 EventBus
- **严重级**：Error
- **内容**：跨系统/跨模块的事件通知必须通过 `EventBus` 全局信号；禁止用 `get_node("/root/...")` 或链式 `get_parent()` 直接拿其他模块的组件再调用方法。
- **允许例外**：父子节点内部组件相互引用（如 `BaseCharacter` 持有自身子组件）；同一系统内部允许直接引用。
- **检查方式**：grep `get_node\("/root/` 与 `get_parent\(\)\.get_parent` 等可疑模式，人工 review 命中处。

### R-ARCH-02 · Autoload 数量上限 6
- **严重级**：Error
- **内容**：Autoload 仅限 `EventBus` / `GameInstance` / `LevelManager` / `AudioManager` / `SettingsManager` / `ConfigCenter`（M6 起新增）；新增 Autoload 必须先在 `Plans/开发计划.md` 或 `Plans/二期开发计划.md` 变更记录中说明并经用户确认。
- **检查方式**：解析 `project.godot` 的 `[autoload]` section 计数与白名单比对。

### R-ARCH-03 · Autoload 使用约定（2026-05-22 新增）
- **严重级**：Error
- **范围**：所有 Autoload 节点（白名单 6 个）的 .gd 文件 + 业务侧调用方
- **核心原则**：Autoload 在 Godot 里既是节点又是全局符号，符号本身指向运行时实例；**不应再叠加 `class_name` 同名定义**，否则 GDScript 解析器会优先走"类静态调用"语义导致 Parse Error（实测 4.6 表现：`Cannot call non-static function on the class directly. Make an instance instead.`）。
- **强制要求**：
  1. **Autoload 的 .gd 文件禁止加 `class_name`**（与 Autoload 注册名同名时编辑器会报错；不同名也无意义）。如果需要类型注解，业务侧用 `Node` 即可（或用具体子类的 class_name 如 `CombatStateService` 等非 Autoload 自身类）。
  2. **业务侧统一通过 Autoload 名直访**：`ConfigCenter.get_xxx()` / `EventBus.signal_name.emit(...)` / `GameInstance.skill_timeline_player.play(...)`。
  3. **禁止动态查找 Autoload**：不写 `get_tree().root.get_node_or_null(^"ConfigCenter")` / `Engine.get_main_loop().root.get_node_or_null(^"EventBus")` 这类反射式访问（除非确实存在静态识别滞后问题，且必须在注释里说明该例外）。
  4. **禁止 `cfg.call(&"...")` 字符串反射调用 Autoload 方法**：直接用 Autoload 名 + 强类型方法名调用即可。
- **历史教训**（2026-05-22 R-Core 重构期实测）：
  - 给 ConfigCenter 加 `class_name ConfigCenter` → 全项目 13 个文件出现 Parse Error
  - 解法：删 class_name；调用方代码不变（`ConfigCenter.get_xxx()`）即可正常工作
- **允许例外**：
  - 启动期 race condition 防御（如 GameInstance 中先于自身 ready 的初始化代码）允许 `if not is_inside_tree(): return` 之类的 guard，但仍走 Autoload 名访问而非动态查找
  - 测试 / Editor 工具脚本中使用 `Engine.get_singleton(...)` 反射访问的情况
- **检查方式**：
  - grep `^class_name ` 在 Autoload .gd 文件中应零命中
  - grep `get_node_or_null\(\^?\"(ConfigCenter|EventBus|GameInstance|LevelManager|AudioManager|SettingsManager)\"\)` 应零命中
  - grep `\.call\(&\"get_(ge|character_def|skill_timeline|sfx_stream)\"` 应零命中

### R-ARCH-04 · 跨模块状态变更走 EventBus，禁反向 get_node 调用（2026-05-23 新增）
- **严重级**：Error
- **范围**：所有 GAS（ASC / AttributeSet / GameplayAbility / GameplayEffect）、Service（CombatStateService / Combat 相关）、Component（Block/Hit/Health 等）的 .gd 文件
- **核心原则**：**任何模块需要影响另一模块状态时（包括同节点的兄弟组件、ASC 与 Component 之间），必须经由 `EventBus` 信号广播**；禁止反向 `get_node_or_null` / `find_child` / `get(&"xxx_component")` 拿到目标节点然后调它的方法。
- **强制要求**：
  1. **跨模块状态变更必须经 EventBus**：组件 A 想让组件 B 改状态时，A emit 信号 + B connect。
  2. **禁反向查找子组件 / 兄弟组件然后调方法**：
     - ❌ `parent.get_node_or_null(^"X").call(&"do_y")`
     - ❌ `parent.find_child("X").do_y()`
     - ❌ `parent.get(&"x_component").do_y()`
  3. **特别针对 ASC**：ASC 内代码**不允许**出现 `get_parent().get_node_or_null(...)` / `get_parent().find_child(...)` 之类的兄弟反查。ASC 只关心自己的 attribute_sets / tags / abilities / cooldowns / active_effects；要影响 Component 一律 emit EventBus 信号。
- **历史教训**（2026-05-22 R-ASC 重构期实测）：
  - ASC.consume_block 在 stamina 归零时反向调 `BlockComponent.stop_block` → ASC 越权 + has_method 反射双重违规
  - 解法：`EventBus.block_broken.emit(blocker)`，BlockComponent 自己 connect 并 stop_block；耦合彻底解开
- **允许例外**：
  - **节点对自己的 child 调 method**：`hp_bar.set_value(...)` / `hud_root.add_child(...)` 这种**父→子的拥有关系**调用允许（不属于"跨模块"）
  - **Component 找自己 owner 的字段**：如 `BlockComponent` 通过 NodeFinder 找父节点的 ASC 是 R-CHAR-01 允许的（owner 关系）
  - **场景启动期一次性 wiring**：Player.gd 的 `_ready` 里把 ASC 引用拷给 Components 是允许的（一次性初始化）
  - **静态工具 + Component 强类型查找**：DamagePipeline 用 `NodeFinder.find_first_child_of_type(target, BlockComponent)` 是允许的（不是按节点名反查，而是按强类型检索 owner 子树）
- **检查方式**：
  - grep `get_parent\(\)\.get_node_or_null\(\^?\"[A-Z]` 在 `Script/GAS/` 与 `Script/Character/Components/` 应零命中
  - grep `get_parent\(\)\.find_child\(` 在 GAS / Component 应零命中
  - 新增 EventBus 信号必须配套：发起方 emit + 至少一个订阅方 connect

### R-GAS-01 · GameplayTag 必须注册
- **严重级**：Warning（宽松模式）
- **内容**：所有用到的 GameplayTag 必须在 `Data/Tags/GameplayTags.tres` 注册；运行时使用未注册 tag 由 Logger 打 warning，不中断启动。
- **检查方式**：扫描 `.gd` 与 `.tres` 中的 tag 字面量，与注册表 diff。

### R-GAS-02 · 属性必须经 set_attr 修改
- **严重级**：Error
- **内容**：`AttributeSet` 派生类的属性禁止外部直接赋值，必须经 `set_attr(name, value)` 走 clamp + 信号广播。
- **检查方式**：grep `\.attribute_set\.\w+\s*=` 等可疑直赋模式。

### R-GAS-03 · Ability/GE 必须 Resource 化
- **严重级**：Error
- **内容**：所有 Ability 与 GameplayEffect 的可调参数（cost / cd / 数值 / tag）必须以 `.tres` 文件存放在 `Data/Abilities/` 或 `Data/Effects/`；脚本里禁止硬编码具体数值（接口默认值除外）。
- **检查方式**：扫描 `Script/GAS/Abilities/` 和 `Script/GAS/Effects/` 子类是否存在魔数；扫描 `Data/` 是否有对应 `.tres`。

### R-DIR-01 · 目录分层
- **严重级**：Error
- **内容**：脚本放 `Script/`、场景放 `Scenes/`、数据 Resource 放 `Data/`、美术资产放 `Content/`；禁止混放（例如 `Script/` 下不应出现 `.tscn`，`Scenes/` 下不应出现 `.gd`，除非该 .gd 是该场景内部脚本且文件名与场景一致）。
- **检查方式**：扫描各根目录下的扩展名分布。

### R-NAME-01 · 命名规范
- **严重级**：Warning
- **内容**：
  - 脚本文件名（满足以下任一即合规）：
    1. **声明 `class_name` 的脚本**：文件名采用与 class_name 一致的 PascalCase（如 `BaseCharacter.gd` / `AbilitySystemComponent.gd`）
    2. **Autoload 脚本**：文件名采用与 Autoload 注册名一致的 PascalCase（如 `EventBus.gd` / `GameInstance.gd` / `LevelManager.gd` / `AudioManager.gd` / `SettingsManager.gd`），便于 `project.godot [autoload]` 段路径与名称对齐
    3. **场景同名脚本**：文件名与同目录场景文件 `xxx.tscn` 同名（如 `main_scene.gd` 配 `main_scene.tscn`），可走 snake_case
    4. **其他纯驱动/工具脚本**（不声明 class_name 也非 Autoload）：走 `snake_case.gd`
  - 类名（`class_name`）：`PascalCase`
  - GameplayTag：`lower.dot.case`
  - 信号：`snake_case` 过去式（如 `enemy_died`、`attribute_changed`）
  - 节点命名：`PascalCase`
- **检查方式**：
  - 声明 class_name 的脚本：校验文件名 == class_name + ".gd"
  - Autoload 脚本：校验文件名 == Autoload 注册名 + ".gd"
  - 场景同名脚本：校验同目录有同名 .tscn
  - 其余脚本：校验 snake_case

### R-CHAR-01 · 2D/3D 通用 API + 标准节点查找
- **严重级**：Error
- **内容**：
  - `BaseCharacter` 与所有 Component 的对外 public API 必须 2D/3D 通用；2D 实现内部允许使用 `Vector2`，但接口签名应使用 `Vector3` 或抽象（如方向用归一化 `Vector3` 或自定义类型，2D 实现内部投影到 XY）。
  - **节点查找统一用 `NodeFinder`（2026-05-22 新增）**：
    - 角色组件之间、角色类查找子组件，必须使用 `NodeFinder.find_first_child_of_type(parent, Type)` / `NodeFinder.find_first_of_type(root, Type)`
    - **禁止**写内联查找循环：`for child in get_children(): if child is X` → 用 `NodeFinder` 替代
    - **禁止**用硬编码节点名访问同级组件：`get_node_or_null(^"HardcodedNodeName")` → 必须按类型查找
    - **允许例外**：`@onready var x = $NodePath` 这种由 Godot 编辑器维护的引用（场景结构稳定时合理）；非 BaseCharacter 体系的纯 UI / 工具脚本不受约束
- **允许例外**：`AnimationComponent` 这类显式分 2D/3D 实现的子类内部可以使用平台特化类型。
- **检查方式**：
  - 人工 review 接口签名；扫描 `Script/Character/Components/` 公开方法的参数与返回类型
  - grep 内联查找模式：`for .* in .*get_children\(\):\s*[\r\n].*is\s+\w+Component`
  - grep 硬编码节点名：`get_node(_or_null)?\(\^?"[A-Z]\w+Component"\)`

### R-CHAR-02 · 3D 场景节点纯洁性（M9 启动前生效）
- **严重级**：Error（**M9 启动前正式激活**；M8 及以前不追溯）
- **内容**：3D 场景中游戏物体必须使用 3D 节点体系：
  1. **角色根节点**必须是 `CharacterBody3D`（或派生类）；视觉子节点必须是 `AnimatedSprite3D` / `Sprite3D` / `MeshInstance3D` / `Decal` 之一
  2. **物理判定节点**必须是 `Area3D` / `StaticBody3D` / `RigidBody3D`；碰撞形状必须是 `CollisionShape3D` + `Shape3D` 子类（`SphereShape3D` / `BoxShape3D` / `CapsuleShape3D` / `CylinderShape3D` 等）
  3. **光照/环境节点**必须是 `DirectionalLight3D` / `OmniLight3D` / `SpotLight3D` / `WorldEnvironment` / `ReflectionProbe` 等 3D 体系
  4. **禁止在 3D 场景的游戏物体子树中混用 2D 节点**（`Sprite2D` / `AnimatedSprite2D` / `Area2D` / `CollisionShape2D` / `CharacterBody2D` 等）
- **HUD 例外（重要）**：
  - **HUD / 菜单 / 飘字 / 头顶血条 / 小地图** 等 UI 节点允许使用 `CanvasLayer` + 2D `Control` 节点（如 `ProgressBar` / `Label` / `Button` / `TextureRect` 等），这是 Godot 官方推荐做法
  - **合规判定**：这些 2D Control 节点必须直接挂在 `CanvasLayer` 节点下（或 CanvasLayer 的 Control 子树中），**不可**作为 `Node3D` 子树的子节点
  - **典型合规结构**：
    ```
    MainScene (Node3D)
    ├── World (Node3D)
    │   ├── Player (CharacterBody3D)         ← 3D 节点纯洁
    │   └── Enemies (Node3D)
    └── HUD (CanvasLayer)                     ← HUD 例外允许
        ├── HealthBar (ProgressBar)
        ├── DamagePopupLayer (Control)
        └── EnemyOverheadHealthBarLayer (Control)
    ```
- **检查方式**：
  - 扫描 3D 场景（含 Camera3D / CharacterBody3D / DirectionalLight3D 等明显 3D 节点的 .tscn）中是否存在 2D 节点
  - 命中 2D 节点时检查其父链：若直接父或祖先包含 `CanvasLayer`，判定为 HUD 例外（合规）；否则报 Error

### R-CHAR-03 · 角色类瘦身原则（2026-05-22 新增）
- **严重级**：Error
- **范围**：`BaseCharacter` 派生类（`PlayerCharacter` / `EnemyCharacter` / 未来的 `CombatNPC` 等）
- **内容**：
  1. **行数硬约束**：派生类的 .gd 文件不超过 **80 行**（含注释）；超过通常意味着混入了应该下沉的逻辑
  2. **禁止承担的 5 类职责**（必须下沉到组件 / ASC / EventBus 订阅）：
     - 表现层：朝向 / 动画切换 / sprite 查找 / ground_offset → `VisualComponent`
     - 输入路由：按键映射 / 技能槽路由 / 移动方向输出 → `InputComponent`
     - 交互检测：找最近 InteractableTarget / interact() 调用 → `InteractorComponent`
     - 属性 Bootstrap：数据解算 / GE apply / Regen 挂载 → `AbilitySystemComponent.bootstrap_from_entity`
     - 跨类型判断：`if ai is BossAI` 这种"角色类感知子类型"的代码 → 让对应子类自己订阅 EventBus 信号
  3. **允许的职责**（仅 4 件）：
     - 加入对应组（`add_to_group(&"player")` 等）
     - override 虚函数声明配置（如 `_get_required_attribute_set_classes`）
     - 极少量编排（如 EnemyCharacter 找 player target、emit `enemy_spawned`）
     - 调 `super()` + 初始化必要的 @onready 节点
- **允许例外**：基类 `BaseCharacter` 本身不受 80 行约束（聚合容器允许更多）
- **检查方式**：
  - `wc -l Script/Character/PlayerCharacter.gd` 等派生类行数检查
  - grep 派生类 .gd 中的可疑模式：`_resolve_sprite|_update_facing|_update_animation|_inject_data_driven|interact_max_distance|ACTION_TO_SLOT|if .* is BossAI`

### R-DATA-01 · 玩家可见数值数据化
- **严重级**：Error
- **内容**：玩家可见数值（HP / 攻击 / 技能 CD / 移动速度 / Boss HP / 物品价格 等）一律走 `.tres` 配置；脚本中禁止出现魔数（除接口默认值与显然的 0/1 外）。
- **检查方式**：人工 review；针对 `Script/GAS` 与 `Script/Items` 重点扫描数字字面量。

### R-DATA-02 · 数据驱动优先 / 拒绝隐式硬编码
- **严重级**：Error（M6 起正式生效；M1–M5 已落地代码不追溯）
- **范围**：所有非 R-DATA-01 已覆盖的"可被策划/数值/关卡/UI/手感调优影响"的值，包括但不限于：
  - 战斗手感参数：屏幕震动幅度/时长、冻帧时长、闪白颜色/时长、命中飘字字号/颜色
  - 技能时间轴参数：技能时长、命中窗口、特效/音效触发时机、伤害倍率、伤害节点配置
  - AI 参数：检测半径、追击距离、攻击距离、Idle 切 Chase 阈值
  - 关卡/Boss 参数：Boss 分层步长（如 500）、ghost 追条延迟与速度、头顶血条显示距离
  - 相机参数：俯视角 pitch、距离、FOV、跟随平滑度
  - 光照/后处理：主光强度/颜色、雾参数、景深距离、SSAO 强度
  - 任何"未来很可能要调"的值
- **强制要求**：
  1. **优先用配置表**：上述值必须放 `Data/Config/*.tres`（按主题分文件，如 `HitFeedbackConfig.tres` / `CameraConfig.tres` / `HealthBarConfig.tres`），通过 `ConfigCenter` 统一访问。
  2. **开发期主动询问**：编码过程中遇到「可能被调优的数值/字符串/路径/枚举映射」时，开发 agent / 主 agent **必须主动询问用户**「该值是否要固化为配置表」，而不是擅自硬编码。
  3. **询问话术模板**：
     > "字段 X 在 `<文件:行号>` 当前硬编码为 Y。这个值未来很可能要调（手感/平衡/美术），建议固化为 `Data/Config/<XxxConfig>.tres` 的 `<field_name>` 字段，由 ConfigCenter 提供 API。是否固化？"
  4. **接口默认值与显然 0/1 不在此规则范围内**（与 R-DATA-01 保持一致）。
- **允许例外**：
  - 数学常量（π / 重力 9.8 等物理常数）
  - 单元测试桩值
  - Editor 工具/插件内部 UI 布局参数（不影响 runtime 玩法）
- **角色属性 Bootstrap 路径强制（2026-05-22 新增）**：
  - 角色属性初始化必须走 `AbilitySystemComponent.bootstrap_from_entity(entity_id, level, classes, skip_regens)`
  - **禁止**角色脚本 / 组件直接调 `AttributeResolver.apply_to_asc()` / `cfg.resolve_character_attributes()` 自己编排 Bootstrap 流程
  - **禁止**直接 new AttributeSet 然后 append 到 `asc.attribute_sets`（兜底创建反模式）—— 必须通过 `BaseCharacter._get_required_attribute_set_classes()` 声明性传入
  - 子类只通过 override `_get_required_attribute_set_classes` / `_should_skip_regens` 表达差异
- **检查方式**：
  - 人工 review 战斗/AI/UI/Camera/SkillSystem 模块的数字字面量与字符串路径
  - 重点扫描 `Script/Camera/` / `Script/UI/` / `Script/AI/` / `Script/SkillSystem/` / `Script/Items/`
  - 对命中模式输出"候选硬编码清单"，由人工逐项决定是否提配置

### R-DATA-03 · 纯数据配置走 CSV / 复合资源走 .tres（2026-05-23 新增 · 2026-05-23 修订为 CSV 路线）
- **严重级**：Warning（指引规则，不阻塞 rule-keeper；新建配置时遵循）
- **范围**：所有 `Data/` 下新增的配置文件
- **核心原则**：**当一份配置只是"数据表"（每行一条记录、字段值 / 数组、可有 sub_id 子行聚合），且不含方法、不引用其他 Resource、不依赖 .tres 编辑器内嵌资源时，应优先用 CSV 而非 .tres / .json**。
- **背景**：项目已建立 Excel → CSV 工作流（`Tools/excel2Config/` 工具 + `Script/Data/CsvLoader.gd` 运行时），CSV 同时是策划在 Excel 编辑、git 文本 diff、Godot 翻译系统（`.translation`）、运行时加载的最优共同载体；遂从最初的"纯数据走 JSON"调整为"纯数据走 CSV"。
- **三类配置归属表**：

  | 配置形态 | 推荐格式 | 理由 |
  |---|---|---|
  | 纯数据表（每行一条记录 / scalar / List(...) 字面量 / 可子行聚合） | **CSV**（放 `Data/FromExcel/<表名>.csv`） | Excel 直接编辑；git 文本 diff；CsvLoader 统一加载；可走 i18n `.translation` |
  | 数据 + 引用其他 .tres / PackedScene / Material / Texture / Curve | `.tres` | Godot 内嵌引用机制需要（如道具 icon、Item.tres 内嵌 GameplayEffect 引用） |
  | 数据 + 自定义方法 / 复杂校验 / 多态 Resource 数组（含 Fragment 这类） | `.tres + class_name Resource` | 业务逻辑本就该走 GDScript；多态嵌套 .tres 表达更顺 |

- **强制要求**：
  1. **新增配置时先判断**：是否纯数据（无方法 / 无引用其他 Resource / 无多态嵌套 / 无 PackedScene·Material·Curve 内嵌）→ 是则走 CSV；否则 .tres
  2. **目录约定**：CSV 放 `Data/FromExcel/<表名>.csv`，配套 `.csv.import` 由 Godot 自动生成；复合 .tres 放 `Data/<分类>/`（如 `Data/Items/`、`Data/Effects/`、`Data/Abilities/`）
  3. **CSV 格式契约**（与 `CsvLoader` / `Tools/excel2Config` 一致）：
     - 编码：**UTF-8 with BOM**
     - 行尾：CRLF（标准）或 LF 都接受
     - 表头第 1 行：`id, sub_id, <字段名…>`；**不带类型行**（运行时 `CsvLoader.as_int / as_float / as_string / as_string_name / as_list_int / as_list_float` 取值器自带类型转换）
     - 第 1 列 `id`：**强制 Int 主键**，全表非空、非 0；同 id 多行用 sub_id 区分
     - 第 2 列 `sub_id`：Int 或留空；留空 = 主行；非空 = 该 id 下的子行（聚合到 `sub_entries[]`）
     - List 字面量：`{a,b,c}`，引号包裹（CSV 内含逗号必须 `"…"` 转义，如 `"{20.0,5.0,10.0}"`）
     - 字符串字段如需多语言 → 用 Godot 翻译系统，每个 i18n 列单独导出 `.translation`（如 `Hero_Data.Hero.translation`），运行时 `tr_n("Hero")` 自动取语言
  4. **加载侧统一模式**：通过 `CsvLoader.load_table(path, aggregate_subs=true)` 拿到 `Dictionary[int, RowDict]`，业务侧用 `CsvLoader.as_*` 取值器读字段；不直接 `JSON.parse_string` / `FileAccess` 解析（除非已有 .json 历史资源）
  5. **失败语义**（R-CODE-01 联动）：CsvLoader 启动期必备表（如 Hero_Data / Char_Attr）找不到 / 表头缺 id-sub_id / id 非 Int → assert 崩
  6. **字段命名**：CSV 列名用 snake_case；运行时 `as_string_name(...)` 转 StringName
- **允许例外**：
  - **历史 .tres / .json 配置**：已存在的 .tres / .json（如 `Data/Config/CameraConfig.tres`、若已有 `*.json`）不强制迁移；本规则只对新增配置或主动迁移生效
  - **跨场景引用 / 多态 Resource 数组**：配置内嵌 PackedScene / Material / NodePath / Curve，或字段是 `Array[Fragment]` 这类多态 Resource → 仍用 .tres
  - **复合表**：表的 entry 含 Resource 子类引用（如道具 icon: Texture2D / effect: GameplayEffect / fragments: Array[ItemFragment]） → 保留 .tres
  - **大段文本字段（如对话）**：仍可用 CSV，但建议把每条 text 抽到 `.translation`，CSV 主表只放 i18n key；纯文本表的元数据（speaker / portrait_id / next_id）继续走 CSV
- **历史教训**（2026-05-22 R-Data 重构期实测）：
  - 3 份 `Growth_*.tres` 各自需要 3 层嵌套 Resource（AttributeGrowthTable + AttributeGrowthEntry + GrowthSegment）+ 3 个 .gd 类
  - 改 CSV 后总代码减少 ~120 行 + 策划用 Excel 直接改数值 + git diff 文本可读 + 同表自然支持多语言（`.translation`）
- **检查方式**：
  - 新建 .tres 时如果是 `script_class="XxxTable"` 且 .gd 里 `entries: Array[XxxEntry]` 而 XxxEntry 只有 @export 字段（无 method、无 Resource 引用），应建议改 CSV
  - grep `Data/Config/.*Tables/.*\.tres` 检查是否仍有"纯数据三层嵌套"形态
  - grep `JSON.parse_string` 在 `Script/Data/Loaders/`：新增 Loader 应优先走 CsvLoader，不走 JSON 解析（除非读历史 .json）

### R-EVENT-02 · EventBus 订阅必须用 named method，禁匿名 lambda（2026-05-24 新增）
- **严重级**：Error
- **核心原因**：Godot 4 中，`signal.connect(_named_method)` 会在 method 所在的 Object free 时**自动 disconnect**；但 `signal.connect(func ... )` 匿名 lambda **不绑定到任何 Object**，场景切换 / 节点 free 时**不会自动断开**，下次 emit 时 lambda 捕获的外部变量已变 freed object，触发 `Lambda capture at index N was freed. Passed "null" instead.`
- **强制要求**：
  - ❌ 禁止：`EventBus.signal_x.connect(func(arg): self._do_thing(arg))`
  - ❌ 禁止：`EventBus.signal_x.connect(func(arg): captured_player.health -= arg)`
  - ✅ 必须：定义 `func _on_signal_x(arg): ...` 然后 `EventBus.signal_x.connect(_on_signal_x)`
  - ✅ 回调内引用场景节点时，**额外加 `is_instance_valid(node)` 守卫**（双重防御，应对 Autoload 类长生命周期订阅者持有短生命周期节点引用的场景）
- **允许例外**：
  - 节点自身的 `signal.connect(func: ...)` 仅在该 signal **声明在自己 .gd 内**且 lambda 不捕获其它节点引用时可用（同实例信号 self-pipe，节点 free 信号也跟着没了）
  - Editor 工具脚本（`@tool` / `EditorScript`）不强制
- **检查方式**：grep `EventBus\.[a-z_]+\.connect\(func` 应为 0 命中。每次 commit 涉及订阅 EventBus 必扫此模式。
- **沉淀来源**：2026-05-24 排查 `AttributeSet.set_attr` lambda capture freed 报错，根因是 `test_arena.gd` / `boss_room.gd` / `main_scene.gd` / `InteractionPromptWidget.gd` 各有匿名 lambda 订阅 EventBus，场景切换后未自动断开。

### R-CODE-01 · 崩溃式失败优于隐式兜底（2026-05-22 新增）
- **严重级**：Error
- **范围**：所有业务代码（角色 / 组件 / GAS / UI 控制器 / Service 等），不含 Editor 工具脚本
- **核心原则**：**配置错误、必备组件缺失、契约违反等情况，应让代码直接崩**（`assert` / `push_error` + 立刻 return），不要静默降级 / 兜底创建 / 用默认值继续跑。
- **强制要求**：
  1. **配置数据缺失**（`entity_id` 找不到对应 def、Growth 表为空、必备 GE 资源不存在等）→ 用 `assert(cond, msg)` 崩；运行期会变成 push_error 但仍 return（开发期看到 stack 直接定位）
  2. **必备组件缺失**（玩家 ASC、MoveComponent 父节点不是 CharacterBody3D 等）→ 同上 `assert`
  3. **越权调用兜底**（`if EventBus.has_signal(...)` / `if has_method(...)` 防御静态可知的 API）→ **直接删**，让缺失立刻爆出来
  4. **AttributeSet / 资源兜底创建**（"找不到就 new 一个默认的"）→ 一律视为反模式删除；改用"调用方显式声明 + 被调方按声明创建"的"声明性创建"模式（参见 `ASC.ensure_attribute_sets`）
  5. **场景路径硬编码兜底**（`get_node_or_null("/root/X")` 找不到时静默 return）→ 改为 `assert(cfg != null, "...")` 崩
- **启动期必备资源白名单**（2026-05-22 R-Core 重构后明确）：以下资源缺失或类型不匹配时，必须在 ConfigCenter._bootstrap 用 `_load_resource_typed(path, expected_class)` assert 崩：
  - `CharacterInstances.tres`（CharacterInstanceTable）
  - `SkillDamageTable.tres`
  - `HitFeedbackConfig.tres` / `HealthBarConfig.tres` / `SfxBindings.tres`
  - `CameraConfig.tres` / `LightingConfig.tres` / `PostProcessConfig.tres`
  - `CombatBalanceConfig.tres`
  - `GameplayTags.tres`（GameplayTagRegistry，由 GameInstance 加载）
  - 可选但必须类型校验：`DialogueConfig.tres` / `PortraitsConfig.tres`（缺失允许，类型不匹配仍崩）
- **保留的 warn 场景**（不属于本规则禁止范围）：
  - 运行时数据缺失但业务可继续：如 `AnimationComponent` 找不到 `AnimatedSprite3D` → 对纯 MeshInstance3D 占位敌人是合理的，仅 GameLogger.warn
  - 玩家可见但非阻塞的功能降级：如 SfxBindings 缺某 sfx_id → 不放音效但游戏继续
  - 启动期 race condition：如 GameInstance.cue_manager 还没 ready 时返回 NoopStub（已有先例，不强求改）
- **写法约定**：
  - 用 `assert(cond, "可读消息含上下文")`；不要裸 `assert(cond)`
  - 消息格式：`类名.方法: 失败原因 (相关变量=值)`，例：`assert(asc != null, "InputComponent: ASC not found under %s" % str(get_parent()))`
  - assert 之后 return 不强求，但建议 `assert + return` 以便 release 包不崩可静默
- **检查方式**：
  - grep 兜底反模式：`if .+ == null:\s*return`、`if not .+:\s*return`、`\.has_signal\(`、`\.has_method\(`（在静态已知 API 上的）
  - 人工 review：每出现一个 `if X == null: return` 都问"这是运行时合理 vs 开发期不可能"，后者应改 assert
  - 新增代码 PR 前必须自检本规则；rule-keeper agent 在 T5 触发时也会扫

### R-CODE-02 · 静态可知的回调走声明式表，禁字符串反射查找（2026-05-23 新增）
- **严重级**：Error
- **范围**：所有基类（AttributeSet / GameplayAbility / BaseWidget / BaseCharacter 等）需要让子类挂载"按 key 路由的回调"的场景
- **核心原则**：**当一个基类需要让子类挂载"特定属性/字段触发的回调"时，禁止用 `has_method(&"_pre_change_xxx")` / `call(&"_pre_change_xxx")` 这类字符串反射方式查找；必须改为子类实现一个返回字典的虚函数（hook 表）声明 attr→callable 映射**。
- **强制要求**：
  1. **基类需要让子类挂载"特定 key 触发的回调"时，必须设计返回 Dictionary 的虚函数**：
     - 命名约定：`_get_xxx_hooks()` / `_get_xxx_table()` / `_get_xxx_config()`
     - 返回类型：`Dictionary[Key, Dictionary]`，内层用预定义的 schema key（如 `clamp_min` / `post_apply` / `max_attr`）
     - **必须在 `_init` 期缓存到 `_xxx_cache`**（不要每次都调虚函数）
  2. **禁止 `has_method(&"前缀_xxx")` 模式查找子类回调**（已被 R-CODE-01 §3 覆盖，本规则强化"必须用什么替代"）
  3. **回调字段使用 `Callable`**：`{"post_apply": _on_health_applied}` 而非 `{"post_apply": "_on_health_applied"}`，让方法名打错立刻 Parse Error 暴露
- **正例**（R-PreChange 阶段 AttributeSet 落地）：
  ```gdscript
  # 子类返回声明式 hook 表
  func _get_attribute_hooks() -> Dictionary:
      return {
          &"crit_chance":     {"clamp_min": 0.0, "clamp_max": 1.0},
          &"health":          {"max_attr": &"max_health", "post_apply": _on_health_applied},
          &"stamina_current": {"max_attr": &"stamina_max"},
          &"health_damage":   {"post_apply": _on_health_damage_applied},
      }

  # 基类 _init 缓存
  func _init() -> void:
      _hooks_cache = _get_attribute_hooks()

  # 基类 set_attr 查表（O(1) Dictionary lookup）
  func set_attr(name: StringName, v: float) -> void:
      var hook: Dictionary = _hooks_cache.get(name, {})
      if hook.has("clamp_min"): v = max(v, hook["clamp_min"])
      if hook.has("clamp_max"): v = min(v, hook["clamp_max"])
      if hook.has("max_attr"): v = min(v, get_attr(hook["max_attr"]))
      # ...落值...
      if hook.has("post_apply"):
          (hook["post_apply"] as Callable).call(name, old, new)
  ```
- **允许例外**：
  - **真正动态的回调**：如 GameplayEffect 的 modifier 列表是配置驱动的，每个 modifier 的 op 不一样，本来就是数据驱动，不算反射
  - **观察者模式信号**：`signal foo(...)` + `connect` 是 Godot 一等公民语法，不算反射
- **历史教训**（2026-05-22 R-PreChange 重构期实测）：
  - `AttributeSet._pre_change_xxx` + `_post_apply_effect` 两套反射在 PrimaryAttributeSet 与 HealthSet 上各有 4 处 / 1 处使用
  - 改声明式 hook 表后：① 静态可读（IDE 跳转到 `_get_attribute_hooks` 即看全貌）② 编译期校验（Callable 引用不存在立刻 Parse Error）③ O(1) 查找
- **检查方式**：
  - grep `has_method\(&\"_pre_change_` / `has_method\(&\"_post_apply_` / `call\(&\"_pre_change_` 应零命中
  - 在 `Script/GAS/Attributes/` 与 `Script/Data/` 下，所有 Resource/Component 子类如果有"按 key 路由的回调"，必须实现 `_get_xxx_hooks` 风格的虚函数

### R-CODE-03 · Object 失效检测必须用 is_instance_valid，禁 `== null`（2026-05-24 新增）
- **严重级**：Error
- **核心原因**：Godot 4 中 `node.queue_free()` 后引用并不会变 null，而是变 "freed Object"。`if node == null` 对它返回 false（即"还活着"），但下一步访问 `node.xxx` 立刻 SCRIPT ERROR。**只有 `is_instance_valid(node)` 能正确判定**。
- **强制要求**：
  - 凡是在 `_process` / 信号回调 / `call_deferred` / 异步 await 后访问可能被 free 的 Node / RefCounted 引用，必须先 `if not is_instance_valid(x): return`
  - 长寿命容器（Autoload / 单例 / `Array[Node]` 缓存）持有的 Node 引用，每次取出使用前都要检测
  - **典型场景**：技能时间轴持续推进期间 caster 被 queue_free（敌人被打死）；EventBus 跨场景信号订阅者持有的玩家 / 关卡节点引用
- **允许例外**：
  - 局部变量在同一函数内 free 后不再使用 → 不需检测
  - 已确知该引用走 RefCounted（不会出现 freed Object 状态）→ 不需检测
- **检查方式**：grep `(caster|target|owner|player|enemy|node)\s*(==|!=)\s*null` 在 `_process` / 信号回调上下文出现时打高亮，复核是否应改为 `is_instance_valid`
- **沉淀来源**：2026-05-24 修复 `SkillTimelinePlayerHost._dispatch_keyframe` "Invalid type in function 'handle' (previously freed)" 报错，根因是 advance 期间 caster 被 free，但 `_finalize` 用 `caster != null` 误判为还活着

### R-VERIFY-01 · 功能完成后先自测，再呼叫用户
- **严重级**：Error
- **范围**：所有由开发 agent / 主 agent 完成的 commit，包括但不限于：新增 .gd / .tres / 场景 / Autoload、修改组件、修改 InputMap、修改配置、HUD 新增 / 重构。

  1. **代码静态校验**：先跑 `read_lints` 确认目标文件 0 错误（pre-existing 错误除外）。
  2. **重启项目刷脚本缓存**：调用 `Tools/godot.bat restart`（或 `Tools/godot.bat r`）重启 Godot 编辑器，让新增的 `class_name` / Autoload / `.tres` 资源被引擎扫描。**这一步必做**，因为 Godot 4.6 在启动后新增 class_name 不会自动刷新，会导致 `.tres` 加载失败、`load("...")` 返回 null 等假阴性。

     - `get_editor_logs`：抓启动日志，确认无 `SCRIPT ERROR` / `Parse Error` / `Failed to load resource`。
     - `execute_editor_script` / `execute_script`：把验收脚本（如 P0-A1~A4 的临时脚本）一键跑掉，捕获输出。
     - `run_project` / `stop_project`：必要时启动游戏跑端到端验收。
     - `get_scene_tree` / `get_node_properties`：检查 Autoload 数量、节点结构、属性值是否符合预期。
  4. **结果分类**：
     - ✅ **MCP 能跑通的**：直接在开发日志填「✅ 通过」+ MCP 返回的关键日志片段，不打扰用户。
     - ⚠️ **MCP 跑不了的**：（如视觉对比、手感反馈、键盘输入、运行时手柄连接等）必须**显式呼叫用户**：「以下 N 项需要你在编辑器中手测，请帮我跑一下：[列具体步骤]」。
- **允许例外**：
  - 纯文档修改（`.md` / `Plans/`）不需要重启 + MCP，但仍需 `read_lints` 检查。
  - 用户在对话中明确说「先不测」/「先记下来一起测」时跳过本规则。
- **检查方式**：
  - 开发日志（如 `Plans/Dolphin设计/HUD开发日志.md`）每个 commit 必须有「✅ MCP 自测通过」或「⚠️ 需手测」明确标记。
  - 主 agent 在每次 commit 后**默认进入自测流程**，不得跳过。

#### R-VERIFY-01 附录 · MCP 验证踩坑与正确路径（2026-05-24 沉淀）

经实测，`godot-mcp` 在 Vibe-Coding 模式下有以下限制，自测时按下表选路径：

| 想做的事 | ❌ 不可用 / 易踩坑 | ✅ 正确做法 |
|---|---|---|
| 跑表达式查 Autoload / 静态状态 | `execute_script` 跑 **编辑器进程** Expression，访问不到 runtime 树 | 仅用于编辑器期值（如配置表 size、注册表 lookup），不要用来摸 runtime 节点 |
| 多行脚本 / 摸 runtime 节点 | `execute_editor_script` 也跑在**编辑器进程**，`/root` child_count=2 是编辑器自身（NOT 游戏树） | 一律绕开，直接命令行起 runtime 进程；要查 runtime 节点用 `get_scene_tree` / `get_node_properties` |
| 启动游戏 + 跑端到端 | `run_project` 在 Vibe-Coding 下偶发只 bootstrap autoload 就停（特征：runtime log 文件 ≈ 3198 字节、无 main scene 输出） | **改用命令行 runtime**：`Start-Process godot.exe --path <proj> -RedirectStandardOutput out.txt -PassThru` + `Start-Sleep N` + `Stop-Process`；stdout 完整可读 |
| 读 runtime print | `get_editor_logs(source=runtime)` 经常返回空；`source=editor_panel` 是上次快照 + 不抓 runtime 进程 | 1) 在 `project.godot` 启用 `application/run/log/file_logging/enable_file_logging=true` 让 print 落 `%APPDATA%\Godot\app_userdata\<ProjectName>\logs\godot*.log`；2) 直接读这些 .log（**最稳**）|
| 验证 Player / Inventory 等 runtime 行为 | 远程模拟键盘事件（F9 之类）—— godot-mcp 没这能力 | 临时在目标 `_ready()` 加 `call_deferred(&"_debug_xxx")` 钩子打 print，验完删；或加 HUDDebugCheats 调试键 + 提示用户按 |

**runtime stdout 日志识别诀窍**：纯 autoload bootstrap 输出 ≈ **3198 bytes**（项目特征值）；正常 runtime 跑通 main scene 输出会到 **140KB+**。看到几个连续 3198-byte log 就知道 main scene 没装载。

**外部资源引用残留检查**：删除 `.tres` / `.gd` 后必查所有 `.tscn` 是否还在 `[ext_resource]` 引用 —— Godot 4.6 引用不存在 .tres 会 `Parse Error` + **场景子树整体不实例化**（Player 都不 _ready），是隐性深坑。删资源后建议跑：
```powershell
Select-String -Path 'Scenes\**\*.tscn' -Pattern '<已删 tres 路径>' -Encoding UTF8
```
