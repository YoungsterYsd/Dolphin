## 关键架构决策（2026-05-20 已与用户确认）

| 决策点 | 最终方案 |
|---|---|
| 配置主存储格式 | **JSON**。策划维护的数据全部走 Excel → 工具 → JSON。**不产 .tres**。运行时由各业务类自己实现 JSON 读取（`FileAccess + JSON.parse_string`） |
| Excel → JSON 转换 | **独立 Python 工程**（`Tools/excel2tres/`），不挂 Godot 编辑器，附带独立 GUI 窗口（tkinter），不做 watch 模式 |
| Excel 文件组织 | **多份 .xlsx**，工具支持选目录/多文件批量导入；每份 .xlsx 内可多 sheet；**sheet 名 = 导出表名** |
| 输入格式约定 | 第 1 行字段名 / 第 2 行字段类型 / 第 1 列 `_export`(1或0) / 第 2 列 `id`(Int 主键) / 第 3 列 `sub_id`(Int 可空子键) |
| Excel 主键 | **联合主键 `(id, sub_id)`**：id 必填非 0 的 Int；sub_id 留空=主行 / 非空=子项；联合键全表唯一 |
| 嵌套数据 | **同 id 多行 + sub_id 列**聚合到该 id 记录的 `sub_entries[]`（方案 A）；主行可缺省，自动用类型默认值补齐 |
| 字段类型词表 | `Int / Float / String / Enum(v1,v2,...) / List(Int) / List(Float) / List(String) / Ignore`（**不使用 Bool / StringName**） |
| id 类型 | **强制 Int**（全表不允许 0；不同表之间 id 可重复，不做跨表唯一约束；id 分段命名由策划自行约定，不在代码层强制） |
| 外键引用 | 跨表 id 引用列类型也是 `Int`（如 Characters.growth_table_id 指 Growth 表的 id） |
| 输出格式 | **仅 JSON**：每张 sheet 一个 `.json` 文件，顶级是字典（key = id 字符串化），无元信息 |
| 输出文件路径 | `Data/FromExcel/Generated/<sheet>.json` |
| 类型校验 | **Fail-collect**：扫完整张 sheet 收集所有错误 → 一次性输出 → 不写文件 |
| 不可对接部分（PackedScene / Curve / 复杂分支） | 留在 .tres / .tscn，**程序员维护** |
| 增量改动 | 工具按需全量转换覆盖 `Generated/`；git diff 自然展示变化 |

### 运行时业务类约定

每张可对接 sheet 配一个 Loader，统一接口：

```gdscript
# Script/Data/Loaders/CharacterConfigLoader.gd
class_name CharacterConfigLoader
extends RefCounted

const PATH := "res://Data/FromExcel/Generated/Characters.json"

var _data: Dictionary = {}   # "id_str" -> Dictionary（条目）

func load() -> Error:
    var f := FileAccess.open(PATH, FileAccess.READ)
    if f == null:
        push_error("[CharacterConfigLoader] cannot open " + PATH)
        return FileAccess.get_open_error()
    var parsed: Variant = JSON.parse_string(f.get_as_text())
    if typeof(parsed) != TYPE_DICTIONARY:
        push_error("[CharacterConfigLoader] JSON root must be Dictionary")
        return ERR_PARSE_ERROR
    _data = parsed
    return OK

func get_by_id(id: int) -> Dictionary:
    return _data.get(str(id), {})

func all() -> Dictionary:
    return _data
```

ConfigCenter 注册所有 Loader，提供集中 `reload_all()` / `get_loader(sheet_name)` API。

- xlsx 文件本体进 git（每份 < 200KB，无需 lfs）

### 输入格式契约（强制）

每张 sheet 必须满足如下结构，否则 fail-collect 报错：

```
        | A 列      | B 列    | C 列    | D 列起 ...                |
   行1  | _export   | id      | sub_id  | <字段名>                   |   ← 字段名行
   行2  | Int       | String  | String  | <字段类型>                 |   ← 字段类型行
   行3  | 1         | slime   |         | <数据>                     |   ← 数据起点
   行4  | 1         | slime   | seg_0   | <子项数据>                 |
   行5  | 0         | wip_npc |         | <草稿，被跳过>              |
```

**前三列规则（工具内置，不允许策划改）：**

| 列 | 字段名 | 类型 | 含义 |
|---|---|---|---|
| A | `_export` | `Int` | 严格 `1`=导出 / `0`=不导出（值不在 {0,1} 报错；不允许空） |
| B | `id` | `Int` | 主键，**非空、非 0**；可重复（与 sub_id 一起组成联合主键） |
| C | `sub_id` | `Int` | 子键。**留空** = 该 id 的主行；非空（非 0） = 该 id 的子项 |

> id / sub_id 都是 Int，工具不在代码层做"分段命名"约束；不同表之间 id 可重复（互不干扰）；同表内 0 不允许作为 id / sub_id 值（避免与"空"语义混淆）。

**联合主键（强约束）：** `(id, sub_id)` 全表唯一：
- 同 id 多个主行（sub_id 都留空）→ 报错（联合键 (`5`, `null`) 重复）
- 同 id 同 sub_id 重复 → 报错
- 同 id 不同 sub_id 多行 → 合法（聚合）
- 不同 id → 各自独立

**字段类型词表（D 列起允许的类型字面量）：**

| 类型字面量 | 含义 | 单元格写法 | 默认值（单元格留空时） |
|---|---|---|---|
| `Int` | 整型 | `5` / `-3` | `0` |
| `Float` | 浮点数 | `3.14` / `-0.5` | `0.0` |
| `String` | 文本 | `Slime` | `""` |
| `Enum(v1,v2,...)` | 内联枚举，单元格必须是括号内某个值 | `Elite`（输出存字符串） | 第一项 `v1` |
| `List(Int)` | 整型数组 | `{1,2,3}` | `[]` |
| `List(Float)` | 浮点数组 | `{1.5,2.5}` | `[]` |
| `List(String)` | 字符串数组 | `{hello,world}` | `[]` |
| `Ignore` | 不导出（备注列） | 任意内容 | （不参与） |

**单元格留空规则：**
- 任意 D 列起的字段单元格留空 → **取该类型默认值，不报错**
- 仅 `_export` / `id` 两列空值会报错；`id` 还必须非 0
- `sub_id` 留空合法（=主行）

**List 写法补充：**
- 大括号必填：`{1,2,3}`；缺括号报错
- `{}` 与单元格留空等价（空数组）
- `{,,}` 视为 3 个空项，按类型转默认值（如 `List(Int)` 得 `[0,0,0]`、`List(String)` 得 `["","",""]`）
- 类型不匹配（如 `List(Int)` 写 `{1,abc,3}`）→ 报错

**子 id 聚合规则（方案 A）：**
- 工具按 `id` groupby，每个唯一 `id` 在输出 JSON 里成为一个顶级条目
- 一组内 `sub_id` 留空的那行是**主行**（提供顶级字段）；`sub_id` 非空的行是**子行**（进 `sub_entries[]` 数组）
- 主行可缺省：若某 id 只有子行没有主行，工具自动创建"虚拟主行"，顶级字段全部用类型默认值（不报错、不警告）
- 子行的 `sub_id` 字段值写入 `sub_entries[i].sub_id`
- 主行 / 子行字段语义不做区分，子行非空字段照原样进 `sub_entries[i]`，留空字段走类型默认值
- `sub_entries` 数组顺序按 Excel 行序保留

## M10.3 · 转换工具：excel2tres（独立 Python 工程）

**状态**：⬜ 未开始
**工期**：2.5 天

### 工程性质

- **完全独立**的 Python 工程，**不挂 Godot 编辑器**
- 单仓库共存，但不依赖 Godot 运行时
- **仅输出 JSON**（已废弃 .tres 支持）
- 同时提供：
  - **GUI 模式**（默认双击启动）：tkinter 独立窗口，零额外依赖
  - **CLI 模式**：供脚本/CI 使用

### 选型

- **语言**：Python 3.11+
- **依赖**：`openpyxl`（读 xlsx）、`click`（CLI）、`tkinter`（GUI，Python 标准库自带）
- **位置**：`Tools/excel2tres/`

### 类型校验（Fail-collect 策略）

校验器行为：
1. 扫完整张 sheet **不停**，把所有错误塞进 `errors: List[Error]`
2. 全部 sheet 扫完后：
   - 若 `errors` 非空 → 打印全部错误（含 `sheet / row / col / 类型 / 实际值 / 原因`）→ **不写任何文件**
   - 若全通过 → 写文件
3. Warning 不阻断写入，但日志里标黄

### 校验项清单

| 检查项 | 级别 | 触发条件 |
|---|---|---|
| 前三列字段名错误（`_export`/`id`/`sub_id`） | Warning | 不影响导出，但提示策划 |
| 前三列类型错误（必须 `Int`/`Int`/`Int`） | Warning | 同上 |
| `_export` 为空或不在 {0,1} | Error | 阻断 |
| `id` 列空 或 `id == 0` | Error | 阻断 |
| `sub_id == 0`（应留空表达主行） | Error | 阻断 |
| `id` / `sub_id` 不是 Int（含小数 / 字符串等） | Error | 阻断 |
| `(id, sub_id)` 联合主键重复 | Error | 阻断（覆盖"同 id 多主行"和"同 id 同 sub_id 重复"两种情况） |
| 字段类型不匹配（Int 列填 abc 等） | Error | 阻断（**留空除外，留空走默认值**） |
| `Enum` 值不在枚举词表 | Error | 阻断（留空走第一项默认值） |
| `List(...)` 缺大括号 / 内部类型不符 | Error | 阻断（`{}` 和留空合法，均视为空数组） |
| 类型行字面量未知（如写了 `Bool`） | Error | 阻断 |

> **设计要点**：D 列起所有字段单元格留空都不报错，全部走类型默认值；只有"前三列空缺/非法值"和"非空但类型不匹配"两类才报 Error。

### 输出约定（仅 JSON）

- **文件粒度**：每张 sheet 输出 1 个 `.json` 文件
- **路径**：`<output_dir>/<sheet_name>.json`，默认 `Data/FromExcel/Generated/`
- **顶级结构**：字典，key = id 字符串化（JSON 标准要求），value = 该条记录
- **不写元信息**：JSON 顶级直接是数据字典，运行时业务类直接读
- **不写注释**（标准 JSON 不支持注释；如需溯源走 git blame 或工具日志）
- **JSON 排版**：2 空格缩进；id key 按数值升序排列（便于 git diff 稳定）；UTF-8 无 BOM；行尾 LF
- **数值精度**：Float 写 `repr()` 等价（保证 round-trip 不失真）

输出示例见 M10.2「JSON 输出示例」段。

### 业务类读取约定

每张 sheet 配一个 Loader 类（M10.1 已规定接口），统一写法：

```gdscript
class_name <Sheet>ConfigLoader
extends RefCounted

const PATH := "res://Data/FromExcel/Generated/<Sheet>.json"

var _data: Dictionary = {}

func load() -> Error:
    var f := FileAccess.open(PATH, FileAccess.READ)
    if f == null:
        return FileAccess.get_open_error()
    var parsed: Variant = JSON.parse_string(f.get_as_text())
    if typeof(parsed) != TYPE_DICTIONARY:
        return ERR_PARSE_ERROR
    _data = parsed
    return OK

func get_by_id(id: int) -> Dictionary:
    return _data.get(str(id), {})

func all() -> Dictionary:
    return _data
```

**状态**：⬜ 未开始
**工期**：1.5 天

### 代码清单

| 文件 | 类型 | 内容 |

| `Script/Core/EventBus.gd` 增 | Autoload | 新 signal：`dialogue_started(graph_id) / dialogue_node_changed(node) / dialogue_choice_presented(options) / dialogue_ended(graph_id)` |

### 行为

- `start(graph_id)`：从 ConfigCenter 拿 graph → 当前节点 = start_node → 走 `_enter_node`
- `_enter_node`：
  - SpeechNode → emit `dialogue_node_changed(node)`，等待外部 `advance()` 调用
  - ChoiceNode → emit `dialogue_choice_presented(filtered_options)`，等待 `select_choice(idx)`
  - EffectNode → 内部触发 effect（switch effect_kind 派发：give_item → InventoryManager.add_item / set_var → GameInstance.set_dialogue_var / play_sfx → AudioManager.play_sfx 等）→ 自动选第一条满足 condition 的 next_link 推进
- `advance()`：speech 节点用，按 next_links 选第一条满足 condition 的，推进
- `end()` / 走完所有节点：emit `dialogue_ended(graph_id)`
