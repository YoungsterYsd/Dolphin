# GM 调试中心规划

> **生成日期**：2026-05-24
> **背景**：当前调试入口分散（HUDDebugCheats 21 个快捷键 / AttributeDebugWidget F1 切换 / DebugOverlay F11 / InterruptDebugLogger 编程式 install）。
> 随着系统增多（属性 34 字段 / 装备 / 任务 / Loot / 对话 / 技能 / BOSS 阶段），按键位将不够用。
> **目标**：建立**命令+参数式 GM 控制台**，统一收口所有 cheat / debug 入口；按键 cheat 改为打开控制台输入命令。

## 二、GM 调试中心架构设计

### 2.1 形态选择

| 方案 | 优点 | 缺点 |
|---|---|---|
| **A. 命令行控制台**（推荐） | 命令+参数完整、可历史、可补全、易扩展 | 需要解析器 |
| B. 选项菜单 | 直观 | 命令多了菜单层级深 |
| C. 蓝图脚本 | 灵活 | 学习成本高 |

> **决策**：方案 A — `~` 键唤出，CommandLine 风格控制台。

### 2.2 模块划分

```
Script/Debug/GMConsole/                  ← 新建目录
├── GMConsole.gd                         ← Autoload（取代 HUDDebugCheats，Release 自动卸载）
├── GMCommandRegistry.gd                 ← 命令注册表（命令名 → handler）
├── GMCommandContext.gd                  ← 命令上下文（args / player / scene_tree / 输出 sink）
├── GMCommandResult.gd                   ← 执行结果（success/fail + message）
└── Commands/                            ← 命令实现，按域分组
    ├── PlayerCommands.gd                ← player.* 系列
    ├── InventoryCommands.gd             ← inv.* 系列
    ├── LevelCommands.gd                 ← level.* 系列
    ├── QuestCommands.gd                 ← quest.* 系列
    ├── DialogCommands.gd                ← dialog.* 系列
    ├── HUDCommands.gd                   ← hud.* / ui.* 系列
    ├── CombatCommands.gd                ← combat.* 系列
    ├── AttrCommands.gd                  ← attr.* 系列
    ├── LootCommands.gd                  ← loot.* 系列
    ├── DebugCommands.gd                 ← debug.* 系列（订阅切换/性能查看）
    └── HelpCommand.gd                   ← help / list
```

### 2.3 UI 形态

```
Scenes/UI/Widgets/GMConsoleWidget.tscn   ← Console UI
├── ColorRect (背景半透明黑底，z=top)
├── ScrollContainer
│   └── VBoxContainer (输出历史)
├── HBoxContainer
│   ├── Label "> "
│   └── LineEdit (输入框，up/down 翻历史，Tab 补全)
└── （挂在 HUD L8_Debug 层，Release 隐藏）
```

### 2.4 命令格式

```
<domain>.<action> [arg1] [arg2] ...
```

- **空白分隔参数**，不引入引号转义（首期）
- **第一个 `.` 前是 domain**（player/inv/quest/...），用于命令路由
- **大小写不敏感**（`PLAYER.KILL` ≡ `player.kill`）
- **支持 alias**：`kill` → `player.kill`、`tp` → `level.load`

### 2.5 命令注册（示例）

```gdscript
# Script/Debug/GMConsole/GMConsole.gd
extends Node

var _registry: GMCommandRegistry

func _ready() -> void:
    process_mode = Node.PROCESS_MODE_ALWAYS
    if not OS.is_debug_build():
        queue_free()
        return
    _registry = GMCommandRegistry.new()
    _register_all_commands()
    _spawn_widget()

func _register_all_commands() -> void:
    PlayerCommands.register(_registry)
    InventoryCommands.register(_registry)
    # ... 其他

func _unhandled_input(event: InputEvent) -> void:
    if event is InputEventKey and event.pressed and event.keycode == KEY_QUOTELEFT:  # ~ 键
        _toggle_widget()

# Script/Debug/GMConsole/Commands/PlayerCommands.gd
class_name PlayerCommands
extends RefCounted

static func register(reg: GMCommandRegistry) -> void:
    reg.register(&"player.kill", _kill, "杀死玩家（触发 player_died）")
    reg.register(&"player.xp", _add_xp, "给玩家加经验。用法：player.xp <amount>")
    reg.register(&"player.tag", _toggle_tag, "切换玩家 ASC tag。用法：player.tag toggle <tag>")
    reg.register(&"player.heal", _heal, "玩家回血到 max")
    reg.register(&"player.god", _god, "无敌切换（granted_tags=state.invulnerable）")
    reg.register(&"player.tp", _teleport, "传送玩家。用法：player.tp <x> <z>")

static func _kill(ctx: GMCommandContext) -> GMCommandResult:
    EventBus.player_died.emit()
    return GMCommandResult.ok("Player killed")
# ...（参考现有 HUDDebugCheats 内的实现，逐项搬迁）
```

## 四、扩展性设计

### 4.1 命令注册接口

```gdscript
# 任意业务模块可在自己的 _ready 注册命令：
GMConsole.register(&"my.cmd", self._handle_my_cmd, "我的命令说明")
```

业务模块独立开发自己的命令，不需要改 GMConsole 核心。

### 4.2 参数解析

- **类型推断**：先尝试 int → float → bool → string
- **缺省参数**：handler 自己处理 `args.size() < required`
- **变长参数**：`args: PackedStringArray` 让 handler 自由切片
- **不引入复杂 schema**（首期）

### 4.3 输出 sink

- 默认输出到控制台 ScrollContainer
- 同时镜像到 `GameLogger.info("GM", msg)`（方便日志文件追溯）
- 错误用红色 + `push_error`

### 4.4 历史与持久化

- 历史命令存到 `user://gm_history.txt`（最多 200 条）
- 上次窗口位置/大小存到 `user://gm_console.cfg`

## 七、规则联动

- **R-DATA-02**：GMConsole 是 Debug Build only 工具，所有命令字符串硬编码合规（不入 Excel）
- **R-LOG-01**：GMConsole 输出镜像到 `GameLogger.info("GM", msg)` 入文件
- **R-EVENT-01**：GMConsole 命令通过既有 EventBus 信号驱动业务，不绕过事件系统
- **R-VERIFY-01**：每完成一个 Phase 必跑 read_lints + Tools/godot.bat restart + 至少 5 条命令自测

## 八、为什么需要 GM 中心

### 8.1 当前痛点
- 21 个快捷键挤在 F1–F12 + Shift 组合，**新增 cheat 必抢按键**
- 按键 cheat 无法**接收参数**（要 5 个 EXP 还是 1000 个 EXP？要切到哪个关卡？）
- 调试入口分散在 3 个文件，**新人发现成本高**
- 无法**输入物品 ID/Quest ID 等**精确测试

### 8.2 GM 中心的价值
- ✅ **命令+参数任意组合**（player.xp 25 vs player.xp 1000 一行解决）
- ✅ **业务模块独立注册命令**（解耦核心，Commands/ 子目录可按需扩展）
- ✅ **历史命令复用**（重复测试同一组操作只需上箭头）
- ✅ **统一日志入口**（GMLogger 镜像 GameLogger，验收报告易引用）
- ✅ **降低验收成本**（用户/QA 跑 BOSS 战时直接 `combat.spawn boss_demo` + `player.xp 1000` 而不用记按键表）
- ✅ **未来扩展性**（接入 RCON / Web Inspector 不需要重写）
