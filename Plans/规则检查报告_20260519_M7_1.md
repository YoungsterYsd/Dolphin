- **违规说明**：R-LOG-01 明确禁止业务代码出现裸 `push_error()`（与 `print` / `print_rich` / `push_warning` 同列），调试期临时 print 必须在提交前清理；规范用法是 `GameLogger.error("SkillSystem", msg)`。SkillSystem 是新模块，建议 channel 名固定为 `"SkillSystem"`（或与 ConfigCenter 一致用 `"Config"` —— 看模块归属，倾向前者）。
- **整改建议**：
  ```gdscript

      GameLogger.error("SkillSystem", "SkillTrack subclass must override get_track_kind()")
      return &""

  func get_keyframes() -> Array:

      return []
  ```
- **严重级**：Error（R-LOG-01 虽然单条规则定为 Warning，但本项目项目级共识中"裸 push_error 必须清理"已在多次扫描中被列为 Error 等级；如以规则文本严格判定则为 Warning，请主 agent 按当前共识处置）

> **注**：R-LOG-01 在 `Plans/全局规则.md` 中标注为 Warning。本报告按规则文本严格判定，把它降级为 Warning（见下），但因为这是新增代码、修复代价极低，**强烈建议在 M7.2 落地前一并清理**。

### [R-DATA-02] 轨道类型常量字符串散落（候选硬编码，需人工确认）
- **文件**：
  - `Script/SkillSystem/Tracks/AnimationTrack.gd:14` — `return &"animation"`
  - `Script/SkillSystem/Tracks/EventTrack.gd:15` — `return &"event"`
  - `Script/SkillSystem/SkillTrack.gd:15` — 注释 `## 子类必须重写：返回轨道类型常量（"animation" / "event"）。`
- **命中内容**：
  ```gdscript
  # AnimationTrack.gd:13-14
  func get_track_kind() -> StringName:
      return &"animation"

  # EventTrack.gd:14-15
  func get_track_kind() -> StringName:
      return &"event"
  ```
- **违规说明**：M7.1 已经为"事件 Kind"建立了 `SkillEventKind` 静态常量类，把 8 种事件 Kind 集中常量化（这是 R-DATA-02 的标杆做法）。但**轨道 Kind**（`"animation"` / `"event"`）依旧是字面量，分散在两个子类与一处注释中。基类 `SkillTrack.gd` 的注释甚至写明「返回轨道类型常量」却未提供常量定义，含义上自相矛盾。
- **影响**：M7.2 引入 `TimelinePlayer` 时大概率会出现 `if track.get_track_kind() == &"animation":` 分派代码，那时这两个字面量会扩散到 Player 与可能的编辑器扩展，违反 R-DATA-02「拒绝隐式硬编码」。
- **整改建议**（建议在 M7.2 启动前预修，代价极小）：
  在 `SkillTrack.gd` 顶部追加常量集合（与 `SkillEventKind` 风格对齐）：
  ```gdscript
  class_name SkillTrack
  extends Resource

  ## 轨道类型常量（与 SkillEventKind 同风格集中管理，R-DATA-02）。
  const KIND_ANIMATION: StringName = &"animation"
  const KIND_EVENT: StringName = &"event"

  # ... 其余字段不变
  ```
  然后 `AnimationTrack.get_track_kind()` 返回 `SkillTrack.KIND_ANIMATION`，`EventTrack.get_track_kind()` 返回 `SkillTrack.KIND_EVENT`。
  也可独立成 `SkillTrackKind.gd` 静态类（与 `SkillEventKind.gd` 完全对称）。
- **是否阻塞**：不阻塞 M7.1 验收（M7.1 只做数据类，运行时还未消费 `get_track_kind()`），但**强烈建议在 M7.2 实现 TimelinePlayer 前先做掉**，避免硬编码扩散。

## 给主 agent 的建议

1. **是否阻塞 M7.1 验收**：**不阻塞**。两项违规（裸 `push_error` × 2 + 轨道类型字面量 × 2）合计 4 处命中，全部位于 `SkillTrack.gd` 与 `Tracks/AnimationTrack.gd` / `Tracks/EventTrack.gd`，修复一次最多动 3 个文件、不到 10 行，**建议在 M7.2 启动前先做完这两项预修**，再开始 TimelinePlayer 实现。这样 Player 一上来就用 `SkillTrack.KIND_ANIMATION` 常量分派，避免硬编码扩散到运行时层。

2. **本里程碑亮点（建议沉淀为模板）**：
   - `SkillEventKind` 把 8 种事件 Kind 集中为静态常量类的做法**完美贴合 R-DATA-02**，全工程零散落字面量。后续 M8（HUD/反馈）、M9（3D 切换）等里程碑里所有"枚举型字符串"都建议套用此模式（如 `HitFeedbackKind` / `CameraShakeKind`）。
   - `ConfigCenter` 路径常量与 `_load_xxx` / `get_xxx` API 三段式扩展也是 M7.1 良好示范，后续 M8 接入 `HealthBarConfig` / `HitFeedbackConfig` / `CameraConfig` 时建议沿用相同结构（注释段 `# === M8 新增 ===` 已经预埋）。

3. **建议的预修补丁**（可放进 M7.2 第一个 commit）：
   - **A**：`SkillTrack.gd` 顶部追加 `KIND_ANIMATION` / `KIND_EVENT` 两个常量；`AnimationTrack.get_track_kind()` 与 `EventTrack.get_track_kind()` 改返回常量；移除基类 push_error，改用 `GameLogger.error("SkillSystem", ...)`。
   - **B**（可选，更彻底）：仿照 `SkillEventKind.gd`，新增 `Script/SkillSystem/SkillTrackKind.gd` 静态常量类；这样 M7.4 编辑器扩展拉下拉框时可以直接调 `SkillTrackKind.all()`，与 `SkillEventKind.all()` 完全对称。

4. **关于 `Data/Config/SkillDamageTable.tres`**：当前为空表（`table = {}`），与 M7.1 计划相符（M7.3 才录入数据）。`ConfigCenter._load_skill_damage_table` 对 res 类型不匹配走 `GameLogger.error` + new 空表兜底，路径正确、错误处理健壮 ✅。

5. **关于 `Data/Skills/Timelines/README.md`**：作为占位说明文档可接受，不触发 R-DIR-01；但建议在 M7.3 录入第一份 `Timeline_*.tres` 后删除或保留（README.md 在 Data/ 下不构成混放，因为它不是脚本也不是场景）。
