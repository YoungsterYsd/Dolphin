# AI 行为树重构计划

> 创建日期：2026-05-23
> 关联模块：`Script/AI/` · `Script/Character/EnemyCharacter.gd` · `Script/SkillSystem/DamageNode.gd` · `Script/GAS/DamagePipeline.gd` · `Script/Data/CombatBalanceConfig.gd` · `Script/Core/EventBus.gd`
> 依赖：现有 GAS / SkillTimeline / HitFeedback 不动
> 落地策略：增量 5 步，**S2 替换时旧 BossAI 暂保留至 S5 验收通过再清理**

---

## 0 · 背景

当前 AI 是「`AIController` + `AIState_*` 字符串切换」的硬编码状态机，无法在编辑器配置敌人行为差异；Boss 行为决策与代码强耦合。需求需要支持：

- **检测类型**：自身血量 / 友军血量 / 玩家距离 / 自身被破韧次数
- **行为顺序**：按概率随机 / 按顺序执行
- **行为内容**：对峙 / 追逐玩家 / 转向（仅正反两面）/ 释放技能
- **受击 / 破韧反馈**：技能配置削韧值，韧性归零进 5s 破韧状态

---

## 1 · 决策汇总（已锁定）

| # | 决策项 | 最终方案 |
|---|---|---|
| 1 | BT 与旧 State 关系 | **完全替换**（BossAI 兼容到 S5 验收后再删） |
| 2 | 受击作为黑板键 | `&"event_took_damage"`，BT tick 末尾自动消费 |
| 3 | 破韧次数存储 | `EnemyCharacter` 普通字段，不上 ASC Attribute |
| 4 | 削韧来源 | 技能配置 `DamageNode.poise_damage` |
| 5 | 破韧持续 | 5 秒（`@export` 可调），破韧期间易伤 1.5x（`CombatBalanceConfig` 可调） |
| 6 | 随机源 | `RandomNumberGenerator` 挂 Runner，`BTAsset.random_seed` 可注入 |
| Q1 | 破韧期间受击处理 | **不吃掉**：视觉抖动+伤害正常，但**不削韧、不重置 5s**（`apply_poise_damage` 内 tag 早退） |
| Q2 | 受击打断策略 | **预留硬度接口**：`BTAction.poise_level: int + interruptible_by_hurt: bool` + `AIInterruptPolicy.can_interrupt` 中央仲裁 |
| Q3 | Reactive Selector | **A · 全局 reactive**：顶层 Selector 每帧重评估，高优先级条件成立立刻抢断 RUNNING；`RandomSelector` 不 reactive |

### 默认 Action 硬度配置

| Action | `poise_level` | `interruptible_by_hurt` |
|---|---|---|
| `BTAction_Standoff` | 0 | true |
| `BTAction_Chase` | 0 | true |
| `BTAction_FaceTarget` | 0 | true |
| `BTAction_CastAbility`（普通技） | 0 | true |
| `BTAction_CastAbility`（霸体技 .tres 重写） | 50/100 | true |
| `BTAction_EnterPoiseBroken` | 999 | true |

未来"技能硬度系统"上线时，攻击 payload 自动带 `attacker_poise_level: int`，仅改 `AIInterruptPolicy.can_interrupt` 一处即可启用硬度比较。

### 数据流（受击 → 破韧）

```
SkillDamageNode.poise_damage  (新增字段)
        ↓
HitDamageResolver.resolve_hit() 把 poise_damage 透传
        ↓
DamagePipeline.compute_and_apply(...,  poise_damage)
   └─ 第 5 步后插入「破韧易伤倍率」(target 有 Status.PoiseBroken tag → dmg *= 1.5)
   └─ 末段调用 target.apply_poise_damage(final_poise * (1+break_bonus))
        ↓
EnemyCharacter.apply_poise_damage(amount)
   └─ Q1: 已有 Status.PoiseBroken tag → 直接 return
   └─ poise_current -= amount
   └─ poise_current <= 0 → _trigger_poise_broken()
        ├─ asc.add_loose_tag(&"Status.PoiseBroken")
        ├─ poise_broken_count += 1
        ├─ _poise_broken_history.append(now_ms)
        ├─ EventBus.poise_broken.emit(self)
        └─ ai.bb.set_var(&"event_poise_broken", true)
        ↓
BehaviorTreeRunner 下一帧 tick：
   reactive Selector 检测 BTCondition_OnEvent(&"event_poise_broken") SUCCESS
   → 抢断 RUNNING → 进入 BTAction_EnterPoiseBroken (5s)
        ↓ 5s 后
BTAction_EnterPoiseBroken._on_exit():
   ├─ asc.remove_loose_tag(&"Status.PoiseBroken")
   ├─ poise_current = poise_max  // 重置
   ├─ EventBus.poise_recovered.emit(enemy)
   └─ bb.erase(&"event_took_damage")  // 防止退出瞬间立切 HurtReact
```

## 6 · 风险与回退

| 风险 | 应对 |
|---|---|
| BT tick 性能下降（每帧从 Resource 读 children） | `tick_rate_hz` 限频；远处怪 BTAsset 配 5Hz |
| Resource 引用环（root 持有 child，child 持有 root） | BTNode 不持有 parent；BTContext 提供 runner 反向引用 |
| 配 .tres 时手误漏字段 | BTAsset 加 `_validate()`：root 为空、children 含 null 时编辑器警告 |
| S2 替换破坏现有 Slime 行为 | S2 配的 BTAsset 行为 1:1 复刻旧 idle→chase→attack 三态；先验证零回归 |
| 旧 AIController 与新 Runner 同时存在期间 EnemyCharacter 类型混乱 | EnemyCharacter 用 `@export var bt_asset: BTAsset`，bt_asset==null 时回退旧 AIController（兼容期保留） |
