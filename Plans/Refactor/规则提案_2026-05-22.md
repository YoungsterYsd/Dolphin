## R-ARCH-04 · 跨模块状态变更走 EventBus，禁反向 get_node 调用

### 严重级
Error

### 内容
**任何模块需要影响另一模块状态时（包括同节点的兄弟组件、ASC 与 Component 之间），必须经由 `EventBus` 信号广播**，禁止反向 `get_node_or_null` / `find_child` 拿到目标节点直接调它的方法。

### 触发本规则的真实场景（R-ASC 阶段）
**反例**（重构前）：

```gdscript
# AbilitySystemComponent.consume_block 里
if new_val <= 0.0:
    add_tag(&"Combat.Block.Broken")
    # ❌ ASC 反向找父节点的 BlockComponent
    var bc: Node = get_parent().get_node_or_null(^"BlockComponent")
    if bc != null and bc.has_method(&"stop_block"):
        bc.call(&"stop_block")
```

问题：
1. ASC 是数值/状态服务者（被多个 Component 共享），它**不应该**知道 BlockComponent 的存在
2. 节点路径硬编码（`^"BlockComponent"`），换名 / 换层级就崩
3. `has_method` 字符串反射是 R-CODE-01 明令禁止的

**正解**（重构后）：

```gdscript
# AbilitySystemComponent.gd
if new_val <= 0.0:
    EventBus.block_broken.emit(get_parent())  # 广播事件

# BlockComponent.gd
func _ready() -> void:
    EventBus.block_broken.connect(_on_block_broken)

func _on_block_broken(blocker: Node) -> void:
    if blocker == get_parent():  # 自己才响应
        stop_block()
```

收益：
- ASC 与 BlockComponent 完全解耦（ASC 不再 import 任何 BlockComponent 知识）
- 多个 listener 可同时响应（如 BuffWidget 也想监听破防 → 只需新增一个 connect）
- 静态 Tag/Signal 名命名错误立刻在编辑器 Parse Error 暴露

### 强制要求

1. **跨模块状态变更必须经 EventBus**：组件 A 想让组件 B 改状态时，A emit 信号 + B connect。
2. **禁反向查找子组件 / 兄弟组件然后调方法**：
   ```gdscript
   # ❌ 禁止
   parent.get_node_or_null(^"X").call(&"do_y")
   parent.find_child("X").do_y()
   parent.get(&"x_component").do_y()
   ```
3. **特别针对 ASC**：ASC 内代码**不允许**出现 `get_parent().get_node_or_null(...)` 之类的反查。ASC 只关心自己的 attribute_sets / tags / abilities / cooldowns / active_effects。

### 允许例外

- **节点对自己的 child 调 method**：`hp_bar.set_value(...)`、`hud_root.add_child(...)` 这种**父→子的拥有关系**调用允许（不属于"跨模块"）。
- **Component 找自己 owner 的字段**：如 `BlockComponent` 通过 NodeFinder 找父节点的 ASC 是 R-CHAR-01 允许的（owner 关系）。
- **场景启动期一次性 wiring**：Player.gd 的 `_ready` 里把 ASC 引用拷给 Components 是允许的（一次性初始化）。

### 检查方式
- grep `get_parent\(\)\.get_node_or_null\(` / `get_parent\(\)\.find_child\(` 在 `Script/Character/Components/` 与 `Script/GAS/` 应零命中
- 新增信号必须配套：发起方 emit + 至少一个订阅方 connect（无订阅的信号会在编辑器报"Signal X has no connections"）

### 历史教训
2026-05-22 R-ASC 阶段：ASC.consume_block 反向调 BlockComponent.stop_block 引发"ASC 越权 + has_method 反射"双重违规；改 EventBus.block_broken 后两个问题一并解决。

## R-CODE-02 · 静态可知的回调走声明式表，禁字符串反射查找

### 严重级
Error

### 内容
**当一个基类需要让子类挂载\"特定属性/字段触发的回调\"时，禁止用 `has_method(&"_pre_change_xxx")` / `call(&"_pre_change_xxx")` 这类字符串反射方式查找；必须改为子类**实现一个返回字典的虚函数**（hook 表）声明 attr→callable 映射。

### 触发本规则的真实场景（R-PreChange 阶段）
**反例**（重构前）：

```gdscript
# AttributeSet.gd 基类 set_attr 内部
func set_attr(name: StringName, v: float) -> void:
    var hook = &"_pre_change_" + str(name)
    if has_method(hook):
        v = call(hook, v)        # ❌ 字符串反射
    # ... 落值 ...
    var post = &"_post_apply_effect"
    if has_method(post):
        call(post, name, old, new)  # ❌ 又一次反射
```

问题：
1. 编辑器静态分析查不到 `_pre_change_crit_chance` 跟 `crit_chance` 字段的关联（重命名属性时漏改回调名）
2. 反射成本（每次 set_attr 都跑 has_method 查表）
3. 子类的回调散落在多个独立函数里，看不出全貌

**正解**（重构后）：

```gdscript
# 子类返回声明式 hook 表
func _get_attribute_hooks() -> Dictionary:
    return {
        &"crit_chance":     {"clamp_min": 0.0, "clamp_max": 1.0},
        &"def_pierce":      {"clamp_min": 0.0, "clamp_max": 1.0},
        &"health":          {"max_attr": &"max_health", "post_apply": _on_health_applied},
        &"stamina_current": {"max_attr": &"stamina_max"},
        &"health_damage":   {"post_apply": _on_health_damage_applied},
    }

# 基类 _init 缓存
func _init() -> void:
    _hooks_cache = _get_attribute_hooks()

# 基类 set_attr 查表（O(1) Dictionary lookup）
func set_attr(name: StringName, v: float) -> void:
    var hook: Dictionary = _hooks_cache.get(name, {})
    if hook.has("clamp_min"): v = max(v, hook["clamp_min"])
    if hook.has("clamp_max"): v = min(v, hook["clamp_max"])
    if hook.has("max_attr"): v = min(v, get_attr(hook["max_attr"]))
    # 落值 ...
    if hook.has("post_apply"):
        (hook["post_apply"] as Callable).call(name, old, new)
```

收益：
- 静态可读：一份 Dictionary 就能看完一个 Set 的所有钩子（IDE 跳转到 `_get_attribute_hooks` 即知全貌）
- 编译期校验：`post_apply: _on_health_applied` 是 Callable，方法名打错立刻 Parse Error（不是运行时 has_method 失败）
- O(1) 查找：Dictionary lookup 替代 has_method 反射
- 框架可扩展：基类支持 `clamp_min/clamp_max/max_attr/post_apply` 4 类 hook，未来加新类型只改基类

### 强制要求

1. **基类需要让子类挂载\"特定 key 触发的回调\"时，必须设计一个返回 Dictionary 的虚函数**：
   - 命名约定：`_get_xxx_hooks()` / `_get_xxx_table()` / `_get_xxx_config()`
   - 返回类型：`Dictionary[Key, Dictionary]`，内层用预定义的 schema key（如 `clamp_min` / `post_apply` / `max_attr`）
2. **禁止 `has_method(&"前缀_xxx")` 模式查找子类回调**（已被 R-CODE-01 §3 覆盖，这里强化"必须用什么替代"）。
3. **声明式表必须在 `_init` 期缓存**（不要每次 set_attr 都调 `_get_xxx_hooks()`）

### 允许例外

- **真正动态的回调**：如 GameplayEffect 的 modifier 列表是配置驱动的，每个 modifier 的 op 不一样，这种本来就是数据驱动，无所谓"反射"
- **观察者模式信号**：`signal foo(...)` + `connect` 是 Godot 一等公民语法，不算反射

### 检查方式
- grep `has_method\(&\"_pre_change_` / `has_method\(&\"_post_apply_` / `call\(&\"_pre_change_` 应零命中
- 在 `Script/GAS/Attributes/` 和 `Script/Data/` 下，所有 Resource/Component 子类如果有"按 key 路由的回调"，必须实现 `_get_xxx_hooks` 风格的虚函数

### 历史教训
2026-05-22 R-PreChange 阶段：`AttributeSet._pre_change_xxx` + `_post_apply_effect` 两套反射在 PrimaryAttributeSet 和 HealthSet 上各有 4 处 / 1 处使用；声明式 hook 表重构后代码量减少且静态可读。

## R-DATA-03 · 纯数据配置（无方法、无 @export Resource 引用）走 JSON

### 严重级
Warning（不阻塞，给重构指引）

### 内容
**当一份配置只是\"数据\"（key/value 数组、表格、字段集合）而**不含**方法、不引用其他 Resource、不依赖 .tres 编辑器内嵌资源（如 PackedScene/Material）时，应优先采用 JSON 而非 .tres**。

### 三类配置的归属

| 配置形态 | 推荐格式 | 原因 |
|---|---|---|
| 纯数据表（字段值 / 数组 / 嵌套 dict） | **JSON**（放 `Data/Common/`） | 文本 diff 友好；不绑 Resource 类生命周期；策划可手编 |
| 数据 + 引用其他 .tres / PackedScene | `.tres` | Godot 内嵌引用机制需要 |
| 数据 + 自定义方法 / 复杂校验 | `.tres + class_name Resource` | 业务逻辑本就该走 GDScript |

### 触发本规则的真实场景（R-Data 阶段）
**反例**（重构前）：

```
# Growth_Player.tres （纯数据 — 4 行字段值 + 数组嵌套，但用 .tres）
[gd_resource type="Resource" script_class="AttributeGrowthTable" ...]
[ext_resource type="Script" path="res://Script/Data/AttributeGrowthTable.gd" ...]
[sub_resource type="Resource" id="seg1"]
script = ExtResource(...)
breakpoint = 10
per_level = 10.0
[resource]
script = ExtResource(...)
id = &"growth_player"
entries = [SubResource("entry_health"), ...]
```

问题：
1. 三层嵌套（Resource / Entry / Segment）每层都需要单独 .gd 文件 + class_name + @export 字段
2. .tres 文本 diff 不可读（`SubResource("seg1")` 之类）
3. 策划改个数值要打开 Godot 编辑器
4. 编译时若 .gd 类增删字段，老 .tres 会失效报错

**正解**（重构后）：

```json
{
  "id": "growth_player",
  "entries": [
    {
      "attribute": "health_base",
      "base": 100.0,
      "segments": [{"breakpoint": 10, "per_level": 10.0}]
    }
  ]
}
```

收益：
- 删 3 个 .gd 类（AttributeGrowthEntry / AttributeGrowthTable / GrowthSegment）
- 文本 diff 清晰（git history 直接可读）
- 策划用任何文本编辑器（VSCode / Notepad++）就能改
- 加载逻辑统一走 `JSON.parse_string(FileAccess.get_file_as_string(path))`
- AttributeResolver 输入参数从 `AttributeGrowthTable` 改成 `Dictionary`，签名更通用

### 强制要求

1. **新增配置时必须先判断**：
   - 是否纯数据（无方法、无引用其他 Resource、无 PackedScene/Material 内嵌）
   - 是 → JSON；否 → .tres
2. **目录约定**：纯数据 JSON 放 `Data/Common/<分类>/*.json`，复合 .tres 仍放 `Data/Config/`
3. **加载侧统一模板**：在 `ConfigCenter` 用 `_load_json_dir(dir, key_field)` 通用模板（待后续抽出）
4. **字段命名**：JSON key 用 snake_case 字符串字面量；GDScript 侧 cast 时显式 `StringName(...)`
5. **类型校验**：JSON 解析后 cast 失败要 assert（参见 R-CODE-01 §启动期必备资源白名单）

### 允许例外

- **历史 .tres 配置**：已经存在的 .tres 不强制迁移；新建配置才适用本规则
- **跨场景引用**：如果配置内嵌 PackedScene / Material / NodePath，仍用 .tres
- **CharacterInstanceTable**：当前是 .tres 因为 entries 数组里每个 CharacterInstanceEntry 是 Resource 子类（含 @export 字段），暂不强求迁移；后续如果发现 entry 里都是纯数据，可以再考虑改 JSON

### 检查方式
- 新建 .tres 时如果是 `script_class="XxxTable"` 且 .gd 里 entries: Array[XxxEntry] 而 XxxEntry 只有 @export 字段（无 method），rule-keeper 应建议改 JSON
- 现有 `Data/Config/AttributeGrowthTables/` 目录已清空（迁移到 `Data/Common/AttributeGrowth/`）

### 历史教训
2026-05-22 R-Data 阶段：3 份 Growth_*.tres 各自需要 3 层嵌套 Resource + 3 个 .gd 类；改 JSON 后总代码减少 ~120 行 + 策划工具链解锁。
