## 批次小结

**Top 5 严重文件**：
1. **HUDManager.gd（382 行）🔴** — 7 类职责合一，急需拆 LayerRegistry + StackController + SettingsBinder
2. **DialogueWidget.gd（333 行）🔴** — 5 类职责合一，按打字机/输入/选项/Layout 拆 4 子组件
3. **DamagePopupPool.gd（198 行）🟡** — 信号双轨 + 池化 + 样式分发，删 v2 兼容并抽 StyleResolver
4. **HUDStateMachine.gd（165 行）🟡** — 资源路径硬编码 + 裸数字状态比较（与 DialogueRunner 同病）
5. **BossHealthBar.gd（177 行）🟡** — ProgressBar + ghost + _draw 三事一类

**跨文件共性**：
- **C1 · Tween 渐入-停留-渐出模板重复 6+ 处**：AreaNameBanner / BigBanner / Toast / KillFeed / Pickup / DialogueWidget；建议抽 `BaseWidget.fade_lifecycle(d_in, hold, d_out)` 公共 helper
- **C2 · `_pull_config` Autoload 弱类型访问 5+ 处**：所有需要 ConfigCenter 的 widget 都写 `Engine.get_main_loop().root.get_node_or_null(^"ConfigCenter")` —— 与全局 C1 (ConfigCenter 强类型化) 同根
- **C3 · `EventBus.has_signal` 防御 4+ 处**：删
- **C4 · HUDStateMachine 状态用裸数字而非枚举**：HUDStateMachine / DialogueRunner / LevelManager 都是

**待用户确认项**：
- **U1**：HUDManager 拆三个子节点会改变 .tscn 结构；要在 D2.E 里做还是单独排？
- **U2**：DialogueWidget 拆分后 4 个子组件对场景影响大，是否分两步走（先拆 typewriter，再拆 input router）？
- **U3**：v2 damage 信号下线时机？是否有外部代码仍在订阅？
