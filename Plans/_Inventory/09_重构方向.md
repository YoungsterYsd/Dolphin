## 零、SOLID 五原则速查（用于本报告对齐术语）

| 原则 | 含义 | 在 GDScript 中的典型违反 |
|---|---|---|
| **SRP** 单一职责 | 一个类只承担一种变化原因 | 一个 .gd 又管数据加载又管 UI 又管业务流 |
| **OCP** 开闭原则 | 对扩展开放、对修改关闭 | 新增类型时改 switch/match；新增 widget 时改 HUD 主类 |
| **LSP** 里氏替换 | 子类可替换父类不破坏行为 | 子类 override 后偷偷改变父类前置/后置条件 |
| **ISP** 接口隔离 | 客户端不应依赖它不需要的接口 | UI 直接 cast 到业务类拿单个字段 |
| **DIP** 依赖倒置 | 高层不依赖低层；都依赖抽象 | HUD `as PlayerCharacter` 直读字段 |

**对应**：07_错误清单 R5-2 / R6-1；DIR-1.1。

**重构前**（HUD.gd:114）：
```gdscript
var pc := player as PlayerCharacter   # ← 直接依赖具体类
if pc == null: return
var asc := player.asc as AbilitySystemComponent
for i in range(SLOT_NODES.size()):
    var ability_id: StringName = pc.ability_slot_to_id[i] if i < pc.ability_slot_to_id.size() else &""
```

**重构后**（DIP 落地）：

```gdscript
@export var attribute_provider: IAttributeReadable = null   # 注入抽象
@export var cooldown_provider: ICooldownReadable = null

func _refresh_cooldowns() -> void:
    if cooldown_provider == null: return
    for i in range(SLOT_NODES.size()):
        var ability_id := cooldown_provider.get_slot_ability_id(i)
        var cd := cooldown_provider.get_cooldown_remaining(ability_id)
        _update_slot_visual(i, ability_id, cd, cooldown_provider.get_max_cooldown(ability_id))
```

适配器实现（玩家专用，但 HUD 不知道）：
```gdscript
# Script/Character/PlayerCooldownProvider.gd
class_name PlayerCooldownProvider extends ICooldownReadable

var _player: PlayerCharacter
func _init(p: PlayerCharacter): _player = p

func get_slot_ability_id(idx: int) -> StringName:
    return _player.ability_slot_to_id[idx] if idx < _player.ability_slot_to_id.size() else &""

func get_cooldown_remaining(id: StringName) -> float:
    return (_player.asc as AbilitySystemComponent).get_cooldown_remaining(id)
# ...
```

**受影响**：HUD.gd / BossHealthBar.gd / InventoryUI.gd / DamagePopupPool.gd（全 9 个旧 widget）+ 新增 4-6 个 Provider 适配器
**风险**：低；Contracts 已就位，是 HUD Phase 2 既有计划
**收益**：DIP 落实；HUD 可独立测试（喂 Mock Provider 跑 HUDShowcase）；P2-A10 grep 验收通过

```gdscript
# GameInstance.gd（参照 SkillTimelinePlayerHost 的成熟做法）
```

**调用站点改造**（grep 全工程 ~30 处）：

或者**保留全局别名**（更平滑）：

### REF-5 · BaseCharacter 组件注册改抽象注册表（OCP） · P2

**对应**：本盘点新发现，BaseCharacter._collect_components 用 if-elif 链识别 5 个组件类型。

**现状**：
```gdscript
func _collect_components() -> void:
    for child in get_children():
        if child is MoveComponent: move_comp = child
        elif child is AnimationComponent: anim_comp = child
        elif child is HitboxComponent: hitbox = child
        elif child is HurtboxComponent: hurtbox = child
        elif child is InputComponent: input_comp = child
        elif child is AbilitySystemComponent: asc = child
```

**重构后**：
```gdscript
# 让组件自报 role
class_name CharacterComponent extends Node
@export var role: StringName = &""    # "move" / "anim" / "hitbox" / ...

# BaseCharacter
var _components: Dictionary = {}     # role → component
func _collect_components():
    for child in get_children():
        if child is CharacterComponent:
            _components[(child as CharacterComponent).role] = child
```

**评估**：实际收益不大（5 个组件 if-elif 不是热点）；**不推荐做**，仅作记录。

**结论**：REF-5 列入但不推荐执行；当前 if-elif 链可读性更高。

### REF-7 · AttributeSet.bind_owner 封装（封装性） · P2

**对应**：07_错误清单 R5-1。

**现状**：`AttributeSet.owner_node` 在 ASC:43 和 EnemyCharacter:102 都直接 `attribute_set.owner_node = X` 赋值，违反 R-GAS-02 的"封装精神"（虽然 owner_node 不是属性数值，技术上不违反）。

**重构后**：
```gdscript
# AttributeSet.gd 新增
func bind_owner(node: Node) -> void:
    if owner_node != null and owner_node != node:
        GameLogger.warn("GAS", "AttributeSet rebind owner: %s -> %s" % [owner_node, node])
    owner_node = node
```

调用站点：
```diff
- attribute_set.owner_node = get_parent()
+ attribute_set.bind_owner(get_parent())
```

**受影响**：AttributeSet.gd（加方法）+ 2 处调用站点
**风险**：极低
**收益**：封装边界清晰；未来可在 bind_owner 内做"重复 bind 警告 / 信号迁移"
**时机**：DIR-2（Player 数据驱动）一并做

### REF-8 · GAS Ability 失败原因走结构而非字符串（OCP） · P2

**对应**：本盘点新发现。AbilitySystemComponent.try_activate 用拼接字符串作为失败原因：
```gdscript
_emit_failed(ability_id, "on cooldown (%.2fs)" % get_cooldown_remaining(...))
_emit_failed(ability_id, "missing required tags: %s" % str(...))
_emit_failed(ability_id, "blocked by tags: %s" % str(...))
```

**重构后**：
```gdscript
enum FailReason { NOT_GRANTED, ON_COOLDOWN, MISSING_TAGS, BLOCKED_TAGS, EXTRA_CONDITION }

# EventBus.gd
signal ability_activation_failed(owner: Node, ability_id: StringName, reason: int, detail: Dictionary)
```

**受益**：UI（Hotbar 抖动 / Toast）可按 reason 类型显示不同提示，而不是 grep 字符串；满足 R-DATA-02 的"分类可被消费"。

**时机**：DIR-6.6（Ability 信号订阅方接入）一并做
