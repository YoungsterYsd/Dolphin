### R-FIX-D2.HIST-01 ✅ Ability_TimelineDriven 双历史 Error（M7.3 引入）

- **关闭日期**：2026-05-21
- **关闭依据**：D2 全里程碑闭环后用户要求"修复历史问题"
- **错误现象**（stderr 反复刷屏）：
  ```
  ERROR: No meta values with key "ability_target".
  ERROR: Cannot determine if connected, target instance is null. Use is_valid() instead.
  ```
  Slime AI 每次发起 `Ability_TimelineDriven` 普攻就会触发一次（4 条 / 攻击循环）。
- **根因分析**：
  1. **Bug-1**（line 50）`asc.get_meta(&"ability_target", null)`：Godot 4.6 即使提供 default 值，meta 不存在时仍会 `push_error`（仅返回 default 但 stderr 报错）。AI 路径不一定提前 `set_meta` → 几乎每次都报。
  2. **Bug-2**（line 65）`var on_ended_cb := Callable()` 先初始化空 Callable 再赋值闭包，闭包内 `EventBus.skill_timeline_ended.is_connected(on_ended_cb)` 拿到的是**外层 var 的旧引用**（空 Callable 的 `self` 已 null），触发 `Cannot determine if connected`。
- **完成动作**（`Script/GAS/Abilities/Ability_TimelineDriven.gd`）：
  1. **Bug-1 修复**：`get_meta` 前先 `has_meta(&"ability_target")` 判断；不再依赖 default 行为。
  2. **Bug-2 修复**：用 `EventBus.skill_timeline_ended.connect(on_ended_cb, CONNECT_ONE_SHOT)` 替代手动 `is_connected + disconnect` 模式；Godot 自动在第一次触发后 disconnect，**完全规避**空 Callable 误用。同时闭包内用 `is_instance_valid(asc)` 防御 ASC 已销毁场景。
- **验证**：12 秒命令行启动 + 让 3 只 Slime AI 多轮触发 Ability_TimelineDriven 普攻，stderr **完全干净**（0 Error）。stdout 关键日志（Player/3 只 Slime 8-step init done / CueManager / CombatStateService 正常）均完整。
- **关联**：本修复让 D2 验收时 stderr 段彻底归零；D6 词条 / D4 武器系统沿用 Ability_TimelineDriven 时不再有错误干扰。
