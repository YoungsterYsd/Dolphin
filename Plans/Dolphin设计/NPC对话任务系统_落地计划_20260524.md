## 一、设计共识总览（与用户多轮对齐）

### 1.1 架构铁律

| 序号 | 决策 | 落地形式 |
|---|---|---|
| **A1** | **对话系统纯解耦** | DialogueRunner 只发 `dialogue_started/ended` 信号；任务/商店等业务方各自订阅。**对话表 0 effect 字段** |
| **A2** | **奖励发放统一接口** | 现有 `LootSpawner.dispatch(drop_id, caller)` 已抽离；任务奖励、怪物掉落、调试 cheat 全用同一入口 |
| **A3** | **任务接取仅两条途径** | ① 关卡初始化时 LevelLoader 批量 accept；② 上一个 sub_id 完成后自动接下一个 |
| **A4** | **任务交付走对话信号反查** | QuestSystem 全局订阅 `dialogue_ended`；按 `Quest_Data.Deliver_Dialogue_ID` 查表匹配，对应 sub 完成 |
| **A5** | **链式任务用 sub_id 串行** | 同 quest_id 的 sub_id 按序激活；每完成 1 sub_id 发一份 Drop_Rule_ID 奖励，自动接下一 sub_id |
| **A6** | **NPC ↔ 对话包多对一** | NPC_Data.Diapack_ID 引用 NPC_Diapack.id，**多 NPC 可共享对话包**（村长 + 长老共用问候等） |
| **A7** | **触发条件单条独立 + 同 id AND** | Condition 表同 id 多 sub_id = AND；不支持 OR（OR 通过另开 id + 引用方处理） |
| **A8** | **商店本期不做** | 仅保留架构入口（Shop 系统可后续加 Autoload 同模式订阅 dialogue_ended） |

### 1.2 EventBus 信号清单（**新增**）

```gdscript
# Script/Core/EventBus.gd 增补
signal dialogue_started(graph_id: int, npc_id: int)
signal dialogue_ended(graph_id: int, npc_id: int)         # 自然结束（推进任务用）
signal dialogue_aborted(graph_id: int, npc_id: int)       # 玩家强制关闭，**不触发** quest 推进

signal quest_objective_started(quest_id: int, sub_id: int)
signal quest_objective_completed(quest_id: int, sub_id: int)
signal quest_series_completed(quest_id: int)              # 整任务系列结束
```

> R-EVENT-02 合规：所有订阅用具名 func，不使用 lambda/bind。

## 二、配表契约（最终版，5 张表）

### 2.1 NPC_Data

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Int | npc_id（业务侧引用） |
| `sub_id` | Int | 留空（与 Item_Data 风格一致） |
| `Name` | String | 显示名（HUD 头像名字） |
| `Diapack_ID` | Int | 对话包 ID → NPC_Diapack.id |
| `Scene` | String | NPC 场景资源路径（.tscn） |
| `Talk_Show` | String | 对话半身像路径（.png） |

**当前数据**：
```csv
1,村长,1,res://Content/NPC/Elder.tscn,res://Content/UI/Portraits/Elder.png
2,铁匠,2,res://Content/NPC/Smith.tscn,res://Content/UI/Portraits/Smith.png
```

### 2.2 NPC_Diapack

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Int | 对话包 ID（被 NPC_Data.Diapack_ID 引用） |
| `sub_id` | Int | 选项序号（1..N，决定菜单显示顺序） |
| `Talk_Text` | String | 选项按钮文字 |
| `Dialogue_ID` | Int | 选中后跳转的对话 graph_id |
| `Condition` | Int | 显示条件 → Condition.id；0 = 始终显示 |

**当前数据**：村长（id=1）4 个选项 + 铁匠（id=2）1 个选项。

**运行机制**：
- 玩家与 NPC 互动按 G → InteractorComponent 找到 NPC → 取其 Diapack_ID → 加载 NPC_Diapack 该 id 全部子项 → 过滤 Condition 满足的子项 → 显示菜单
- 仅 1 个可见 → **直接进对话**（跳过菜单）
- 0 个可见 → 显示默认台词（**默认台词来自 NPC 的固定 graph 或者后续加 Default_Text 字段**，本期 0 个可见时静默关闭）

### 2.3 Dialogue

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Int | graph_id |
| `sub_id` | Int | 节点 ID（graph 内唯一）；空行 = 主行（聚合用，无业务数据） |
| `Text` | String | 对话文本 |
| `Branch_Text` | List(String) | 选项文本列表，与 Branch_ID/Branch_Cond 等长 |
| `Branch_ID` | List(Int) | 选项跳转目标 sub_id 列表 |
| `Branch_Cond` | List(Int) | 选项显示条件 Cond_ID 列表，0=无条件 |

**节点流转规则**：
- 无 Branch → 该节点播完后**自动进 sub_id+1**（下一个连续节点）；无 sub_id+1 则对话结束
- 有 Branch → 弹出选项菜单；玩家选 → 跳到 Branch_ID 对应 sub_id

**当前数据**：5 个 graph（1001 介绍 / 1101-1103 三步交付 / 1500 闲聊）。

### 2.4 Quest_Data

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Int | quest_id（任务系列 ID） |
| `sub_id` | Int | 步骤序号（同 id 内 sub_id 顺序串行） |
| `Name` | String | 当前步骤的 HUD 标题 |
| `Desc` | String | 当前步骤的 HUD 描述 |
| `Kind` | Enum(Item,Monster,NPC,Tricky) | 目标类型 |
| `ID` | Int | 目标 ID（Item→item_def_id；Monster→monster_id；NPC→npc_id；Tricky→机关 id） |
| `Num` | Int | 数量；Kind=NPC 时也是数量（一般 1）|
| `Drop_Rule_ID` | Int | 该步骤完成奖励 → Drop_Rule.id；0=无奖励 |
| `Deliver_Dialogue_ID` | Int | 交付对话 graph_id；0 = 目标达成立即完成；非 0 = 目标达成后需走完该对话才完成 |

**当前数据**：1 条任务系列 4 步（收集→击杀→见铁匠→击败 BOSS）。

### 2.5 Condition

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | Int | 条件 set ID（被引用方使用） |
| `sub_id` | Int | 子条件序号；同 id 多 sub_id = **AND** 组合 |
| `Type` | Enum(Lev, Quest_Ongoing, Quest_Finished, Quest_PendingDeliver) | 条件类型 |
| `Param` | Int | 参数（Lev=等级阈值；Quest_*=quest_id） |

**Type 定义**：
- `Lev`：玩家等级 ≥ Param
- `Quest_Ongoing`：任务系列 quest_id 处于"进行中"（active 任意 sub_id 阶段）
- `Quest_Finished`：任务系列 quest_id 全部 sub_id 完成
- `Quest_PendingDeliver`：任务系列 quest_id 当前 active 的 sub_id 已达成目标，等待交付（即玩家身上有"未交付的步骤"）

**当前数据**：5 个 condition set（1=Lev≥5 / 2=Quest1进行中 / 3=Quest1完成 / 4=Quest1待交付 / 5=AND 组合）。

#### 🟢 新增 ConditionEvaluator（SRP：仅做条件求值）

```
Script/Conditions/ConditionEvaluator.gd     # 静态工具
```

```gdscript
class_name ConditionEvaluator
extends RefCounted

## 求值入口。cond_id <= 0 = 无条件（始终满足）
static func eval(cond_id: int) -> bool:
    if cond_id <= 0: return true
    var entries: Array = ConfigCenter.get_condition_set(cond_id)
    for e in entries:  # 同 id 内 AND 短路
        if not _eval_one(e):
            return false
    return true

static func _eval_one(e: Dictionary) -> bool:
    var t: StringName = CsvLoader.as_string_name(e, "Type")
    var p: int = CsvLoader.as_int(e, "Param", 0)
    match t:
        &"Lev":                  return PlayerStats.get_level() >= p
        &"Quest_Ongoing":        return QuestSystem.is_ongoing(p)
        &"Quest_Finished":       return QuestSystem.is_finished(p)
        &"Quest_PendingDeliver": return QuestSystem.is_pending_deliver(p)
        _:
            assert(false, "ConditionEvaluator: unknown Type=%s" % t)
            return false
```

**SOLID·OCP**：新增条件类型 = 在 match 加 1 个分支（短小）；外部调用零变更。
**SOLID·DIP**：调用方传 cond_id，ConditionEvaluator 不知道谁调用它。
**DRY**：所有"显示/隐藏"判断（NPC_Diapack 选项、Dialogue Branch_Cond、未来 Shop_Item）**全部走这一个 eval(cond_id)**，不再复制条件判断代码。

#### 🟡 改造 QuestSystem（增加链式推进 + 全局订阅 dialogue_ended）

**新增方法**（沿用现有 .gd 类，**不破坏现有 API**）：
```gdscript
# Script/Quest/QuestSystem.gd 新增

func _ready() -> void:
    EventBus.dialogue_ended.connect(_on_dialogue_ended)  # R-EVENT-02 合规

# 关卡启动时由 LevelLoader 调（A3 决策）
func bulk_accept(quest_ids: Array[int]) -> void:
    for qid in quest_ids: accept(qid)

func accept(quest_id: int) -> void:
    # 进入 sub_id=1 active 状态
    _active[quest_id] = 1
    EventBus.quest_objective_started.emit(quest_id, 1)

func is_ongoing(quest_id: int) -> bool:
    return _active.has(quest_id) and not _finished.has(quest_id)

func is_finished(quest_id: int) -> bool:
    return _finished.has(quest_id)

func is_pending_deliver(quest_id: int) -> bool:
    return _pending_deliver.has(quest_id)

# 全局订阅回调（A4 决策）
func _on_dialogue_ended(graph_id: int, _npc_id: int) -> void:
    # 找当前 active 任务里 当前 sub_id 的 Deliver_Dialogue_ID == graph_id 的
    for qid in _active.keys():
        var sub: int = _active[qid]
        var sub_def: Dictionary = ConfigCenter.get_quest_step(qid, sub)
        if int(sub_def.get("Deliver_Dialogue_ID", 0)) == graph_id and _is_objective_done(qid, sub):
            _finalize_step(qid, sub)  # 发奖 + 推进下一 sub_id 或结束系列

func _finalize_step(quest_id: int, sub_id: int) -> void:
    # 1. 发奖
    var sub_def: Dictionary = ConfigCenter.get_quest_step(quest_id, sub_id)
    var drop_id: int = int(sub_def.get("Drop_Rule_ID", 0))
    if drop_id > 0:
        LootSpawner.dispatch(drop_id, self)  # A2 决策：复用统一奖励接口
    EventBus.quest_objective_completed.emit(quest_id, sub_id)
    
    # 2. 推进下一 sub_id 或结束系列
    var next_sub: int = sub_id + 1
    if ConfigCenter.has_quest_step(quest_id, next_sub):
        _active[quest_id] = next_sub
        EventBus.quest_objective_started.emit(quest_id, next_sub)
    else:
        _active.erase(quest_id)
        _finished[quest_id] = true
        EventBus.quest_series_completed.emit(quest_id)
```

**SOLID·OCP**：未来加 "Deliver_Cutscene_ID" 之类新交付方式 = 加新订阅 + 在 sub_def 加新字段；不动既有逻辑。
**SOLID·SRP**：QuestSystem 仅管"任务状态机"（active/pending_deliver/finished）；不直接发奖（委托 LootSpawner）；不渲染 HUD（委托 EventBus 信号）。
**DRY**：奖励发放复用 `LootSpawner.dispatch`，与怪物掉落、调试 cheat 共用。

## 给定 NPC，返回当前应该展示的对话起点：

#### 🟡 改造 NPCActor（数据驱动）

**改动点**：
- 新增 `npc_id` 字段（替代当前可能的硬编 NPCDef）

**SOLID·SRP**：NPCActor 只是"场景里那个能互动的玩偶"；不读配表、不评条件、不开对话——这些活全分给 Service / Loader / Runner。
