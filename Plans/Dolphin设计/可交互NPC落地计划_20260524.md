## 二、设计目标

### 2.1 核心思路

```
NPCDefinition.tres   ←── 策划在 Inspector / Excel 维护
   │                     字段：display_name / dialogue_root_id / shop_id / quest_giver_ids / sprite_frames / ...
   │
   ▼
NPC.tscn  +  set_definition(def)   ←── 通用模板，关卡里用 def_id 拖一份即可
   │                              （或运行时 NPCSpawner 按 marker 实例化）
   │
   ▼
按 G ── interact() ── 决策树 ─┬─► DialogueRunner.start(dialogue_root_id)
                             │     └─ 对话内 EffectNode 派发 start_quest / open_shop / ...
                             │
                             ├─► （已在范围内任务可领/可交时，dialogue_root_id 可动态选择"任务对话"分支）
                             │
                             └─► （Shop NPC：直接走 OpenShopHandler 弹 ShopWidget）
```

### 2.2 关键决策（待 user 确认 → followup §五）

| 决策点 | 备选 |
|---|---|
| **D1 · NPCDefinition 维护方式** | A. 仅 .tres（Inspector 编辑） / B. Excel `NPC` sheet → CSV → Loader / **C. 双轨（Inspector 优先，配表覆盖）** |
| **D2 · 商店是单独 NPC 子类还是通用 NPC + 配置** | A. 独立 ShopNPC.gd / **B. NPCDefinition.shop_id 不为空即"该 NPC 提供商店"，对话 EffectNode 触发 open_shop** |
| **D3 · 商店 UI 形态** | **A. 独立 ShopWidget.tscn（HUDLayout Modal Slot）** / B. 与 InventoryUI 复用同一面板加分页 |
| **D4 · 任务可视化标记** | **A. NPC 头顶 Sprite3D billboard 显示 `!` / `?` 图标**（HD-2D 标准做法） / B. 通过 InteractionPromptWidget 文字提示 `[G] 接受任务` |
| **D5 · 任务-NPC 映射存储** | A. NPCDefinition.quest_giver_ids / NPCDefinition.quest_taker_ids（NPC 侧主动声明） / **B. QuestDef.giver_npc_id / QuestDef.taker_npc_id（任务侧声明，反查更省事）** |
| **D6 · NPC 场景实例化方式** | A. 关卡 .tscn 里直接拖 NPC.tscn + Inspector 改 def_id / **B. 关卡 .tscn 放 NPCSpawner Node3D + def_id**，运行时 spawn（与 LevelSpawnMarker 风格一致） |

> **推荐方案（用户回 "全推荐" 即可走通）**：D1=C / D2=B / D3=A / D4=A / D5=B / D6=B

### 2.3 推荐 cue_tag / EventBus 复用

无需新增 EventBus 信号。本系统**100% 复用已有**：
- `interaction_target_entered/left`：HUD 显示提示
- `dialogue_started/ended`：对话生命周期
- `quest_started/completed`：任务标记切换 `!` ↔ `?` ↔ 隐藏
- `currency_changed`：商店购买后金币刷新
- `inventory_changed`：商店购买后背包刷新

如真有需要再追加（本计划不预留）。

### 3.2 NPCDefinition Resource 字段

```gdscript
# Script/Data/NPCDefinition.gd
class_name NPCDefinition
extends Resource

## 唯一 id（与 Excel NPC sheet 的 id 列一致；StringName 形式）。
@export var id: StringName = &""
## 显示名（HUD 提示用）。
@export var display_name: String = "NPC"
## 提示文本。空则用「[G] 对话」默认。
@export var prompt_text: String = ""

## 默认对话图 id（按 G 触发）。
@export var dialogue_root_id: StringName = &""

## 商店 id（非空 = 该 NPC 提供商店；EffectNode 的 open_shop 会引用）。
@export var shop_id: StringName = &""

## 视觉资产（HD-2D billboard Sprite3D）；空则保持 NPC.tscn 默认 Visual。
@export var sprite_frames: SpriteFrames = null
## 默认动画名（idle）。
@export var default_animation: StringName = &"idle"

## 交互范围半径（米）。继承 InteractableTarget 的 interact_radius 概念。
@export var interact_radius: float = 2.5

## 是否朝向玩家。
@export var face_player_on_interact: bool = true
```

### 3.3 NPC 实例化方式（D6 推荐 B）

**关卡 .tscn 写法**：
```
TestArena.tscn
└── NPCSpawnerLayer (Node3D)
    ├── NPCSpawner_Elder (NPCSpawner.gd)
    │     def_id = "npc_elder"
    │     position = (5, 0, 3)
    │     facing_yaw = 90.0
    └── NPCSpawner_Blacksmith (NPCSpawner.gd)
          def_id = "npc_blacksmith"
          position = (-5, 0, 0)
```

**NPCSpawner._ready** 流程：
1. 从 ConfigCenter 取 NPCDefinition（先查 Excel JSON / 否则查 `Data/Manual/NPCs/<id>.tres`）
2. 实例化 `NPC.tscn` → 注入 def → reparent 到关卡根
3. queue_free 自身

> 与 `LevelSpawnMarker` 设计一致：marker 节点只是数据容器，启动时实例化真正的 Actor。

### 3.4 商店流程

```
玩家走近铁匠 → 进入 InteractRange → HUD 显示 [G] 对话
  按 G → DialogueRunner.start(npc_blacksmith_intro)
    SpeechNode："要看看我的商品吗？"
    ChoiceNode：
      └─ "买东西" → next_id = "open_shop_node"
      └─ "聊聊"   → next_id = "chat_node"
    EffectNode(open_shop_node)：kind="open_shop" payload={shop_id="shop_blacksmith"}
       ↓
    EffectHandlerRegistry → OpenShopHandler
       ↓
    ShopSystem.open(shop_id)
       ↓
    HUDManager.push(ShopWidget, {shop_id, currency_id=gold})
       ↓
    InputContextManager.push(Modal)
```

**ShopSystem.try_buy(entry)**：
1. CurrencyManager.try_spend(price) → 失败弹 toast
2. InventoryComponent.add_by_id(item_def_id, count)
3. ShopEntry.stock -= 1（-1=无限）
4. 触发 cue: `Cue.UI.Shop.Buy`（命中反馈系统接入）

**ShopWidget**：
- 复用 InventoryUI 的 `ItemSlotWidget` 渲染（**0 重复造轮子**）
- 入参：typed `ShopDefinition`（R-HUD-02）
- Esc / 点关闭 → pop Modal context

### 3.5 任务标记可视化（D4 推荐 A）

```gdscript
# Script/UI/Widgets/NPCQuestMarker.gd
class_name NPCQuestMarker
extends Sprite3D    # billboard=Y_BILLBOARD，与玩家视角始终面对

## 当前 NPC 的 def（绑定时由 NPCActor 注入）。
var _npc_def: NPCDefinition = null

func bind(def: NPCDefinition) -> void:
    _npc_def = def
    _refresh()
    EventBus.quest_started.connect(_refresh.unbind(1))
    EventBus.quest_completed.connect(_refresh.unbind(1))
    EventBus.quest_objective_changed.connect(_refresh.unbind(4))

func _refresh() -> void:
    var state := _detect_state()  # 见下
    match state:
        &"giver":   texture = preload("res://Content/Icons/HUD/quest_giver_!.png")
        &"taker":   texture = preload("res://Content/Icons/HUD/quest_taker_?.png")
        _:          visible = false; return
    visible = true

func _detect_state() -> StringName:
    # 反查所有 QuestDef.giver_npc_id == _npc_def.id 的任务
    # → 玩家未接 → "giver"（!）
    # → 玩家已接但目标已达成 + taker_npc_id == _npc_def.id → "taker"（?）
    ...
```

> 订阅都用 named method（R-EVENT-02）；`_refresh.unbind(N)` 是 Godot 4 标准用法，自动转发去掉参数。

### 3.6 OpenShopHandler

```gdscript
# Script/Dialogue/Handlers/OpenShopHandler.gd
class_name OpenShopHandler
extends RefCounted

const KIND := &"open_shop"

func handle(payload: Dictionary) -> void:
    var shop_id: StringName = payload.get("shop_id", &"")
    if shop_id == &"":
        GameLogger.warn("Dialogue", "open_shop without shop_id")
        return
    # ShopSystem 是 GameInstance.shop_system，启动期已注册（不增 Autoload）
    GameInstance.shop_system.open(shop_id)
```

注册（在 EffectHandlerRegistry._ready 内）：
```gdscript
register(OpenShopHandler.KIND, OpenShopHandler.new())
```
