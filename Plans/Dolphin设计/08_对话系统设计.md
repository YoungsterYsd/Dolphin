## 0. 设计目标 · 5 条铁律

| ID | 铁律 |
|---|---|
| **R-DLG-01** | **数据驱动**。一段对话 = 一份 `DialogueGraph` Resource；引擎代码不写 if-else 分支。新增对话 = 加 Excel 行 / 加 .tres，**不改 .gd**。 |
| **R-DLG-02** | **HUD 复用**。对话 UI 走 `BaseWidget` + `HUDManager.push_widget(L2_GameMenu)`；不新建独立 HUD 框架，与 InventoryUI / PauseMenu 同栈。 |
| **R-DLG-03** | **输入锁定**。对话期间必须 `InputContextManager.push(Dialogue)`，屏蔽战斗动作（A/Q/W/E/R/X），只允许 `combat_interact`（推进/选择）+ `cancel`（关闭，可选）。 |
| **R-DLG-04** | **业务解耦**。DialogueRunner 不知道 InventoryComponent / EquipmentComponent / QuestSystem 长什么样；通过 `EffectNode.effect_kind` + payload 派发到 **EffectHandler 注册表**，业务侧自行注册处理器（R-HUD-02 同源思想）。 |
| **R-DLG-05** | **条件表达式纯文本**。`condition_expr` 限定在 `HasTag(...)` / `Var.X >= N` / `&&` / `\|\|` / `!` 五种基础元素；不引入完整 expression 库，复杂条件逼策划拆分子节点（避免运行时调试地狱）。 |

## 3. 数据模型

### 3.1 节点图

| 类 | 类型 | 字段 | 说明 |
|---|---|---|---|
| **DialogueGraph** | Resource | `graph_id: StringName` | 全局唯一标识（如 `npc_blacksmith_intro`） |
|  |  | `start_node_id: StringName` | 入口节点 |
|  |  | `nodes: Array[DialogueNode]` | 节点列表（任意顺序） |
| **DialogueNode**（基类） | Resource | `node_id: StringName` | 图内唯一 |
|  |  | `next_links: Array[NextLink]` | 出边列表（按顺序求值，第一条满足条件的胜出） |
| **NextLink** | Resource | `next_id: StringName` | 目标节点 id |
|  |  | `condition_expr: String = ""` | 空 = 无条件 |
| **SpeechNode**（子类） | Resource | `speaker: StringName` | 说话者名（用于显示）|
|  |  | `portrait_id: StringName` | 肖像 id（PortraitsConfig 解析） |
|  |  | `text: String` | 文本（支持 `{var:gold}` / `{tag:friendship}` 插值） |
|  |  | `voice_id: StringName = &""` | 语音 id（AudioManager 解析；空=无语音） |
| **ChoiceNode**（子类） | Resource | `prompt: String = ""` | 选项标题（可空） |
|  |  | `choices: Array[ChoiceOption]` | 选项列表（按条件过滤后渲染） |
| **ChoiceOption** | Resource | `text: String` | 按钮文本 |
|  |  | `condition_expr: String = ""` | 不满足 → 该选项不显示（也不灰显，避免暴露剧情） |
|  |  | `next_id: StringName` | 选中后跳转目标 |
| **EffectNode**（子类） | Resource | `effect_kind: StringName` | 派发到 EffectHandler 的 key（见 §4） |
|  |  | `payload: Dictionary` | 入参（give_item 时 `{item_id, qty}`；set_var 时 `{key, value}`）|

### 3.2 全局变量（DialogueVars）

挂在 `GameInstance.dialogue_vars: Dictionary[StringName, Variant]`。
- **API**：`GameInstance.set_dialogue_var(key, value)` / `get_dialogue_var(key, default=null)`
- **持久化**：参与存档（D5 SaveSystem 落地后自动续上）
- **典型用法**：`Var.friendship_blacksmith = 30`、`Var.has_met_merchant = true`

### 3.3 标签查询（Tags）

复用 GAS / 业务侧已有的 GameplayTag 体系：
- 玩家身上的 `LooseTag`（如 `Quest.MainStory.Step1.Done`）
- 通过 `Player.asc.has_tag(&"...")` 查询
- DialogueExpr 内**用 group `&"player"`** 找当前玩家，**不直接 cast** PlayerCharacter（R-HUD-02 同源）

### 3.4 条件表达式语法（DialogueExpr）

```
expr      := term (("&&" | "||") term)*
term      := "!" term | "(" expr ")" | atom
atom      := HasTag(<tag_name>)
           | Var.<key> <op> <number>
           | Var.<key>                 ; bool 求值（非 0 / 非空）
op        := "==" | "!=" | "<" | "<=" | ">" | ">="
```

**示例**：
- `HasTag(Quest.MainStory.Step1.Done)`
- `Var.friendship_blacksmith >= 30 && !HasTag(Quest.Blacksmith.Refused)`
- `Var.has_key || HasTag(Item.MasterKey)`

**实现限制（R-DLG-05 落地）**：
- 不支持函数调用（除 `HasTag`）
- 不支持字符串比较
- 不支持算术运算（不允许 `Var.gold - 10 >= 0`，改为前置 EffectNode 计算）

## 4. EffectHandler 注册表（业务解耦核心）

`DialogueRunner` 不知道 InventoryManager / QuestSystem 是什么，靠 **EffectHandlerRegistry** 派发：

### 4.1 接口

```gdscript
class EffectHandler:
    extends RefCounted
    # ctx 包含：runner, current_node, dialogue_vars, source_npc（可选）
    func handle(payload: Dictionary, ctx: Dictionary) -> void:
        pass
```

### 4.2 注册（业务侧 _ready 内调）

```gdscript
# 由业务侧 Autoload（如 GameInstance 或单独 DialogueEffects.gd）注册
EffectHandlerRegistry.register(&"set_var", SetVarHandler.new())
EffectHandlerRegistry.register(&"give_item", GiveItemHandler.new())
EffectHandlerRegistry.register(&"play_sfx", PlaySfxHandler.new())
EffectHandlerRegistry.register(&"add_tag", AddTagHandler.new())
EffectHandlerRegistry.register(&"start_quest", StartQuestHandler.new())   # 等 QuestSystem 接入
EffectHandlerRegistry.register(&"start_shop", StartShopHandler.new())     # 等 ShopSystem 接入
```

### 4.3 内置 4 个基础 Handler（M11 必交付）

| effect_kind | payload 字段 | 行为 |
|---|---|---|
| `set_var` | `{key: StringName, value: Variant}` | `GameInstance.set_dialogue_var(key, value)` |
| `add_tag` | `{tag: StringName}` | 玩家 `ASC.add_loose_tag(tag)` |
| `play_sfx` | `{sfx_id: StringName}` | `AudioManager.play_sfx(sfx_id)` |
| `hud_toast` | `{text: String, duration: float = 2.0}` | `EventBus.hud_toast_requested.emit(...)` |

### 4.4 业务侧扩展 Handler（M11 不必交付，留扩展点）

| effect_kind | 来源 |
|---|---|
| `give_item` / `take_item` | M12 NPC + Inventory 接入后 |
| `start_quest` / `update_objective` | QuestSystem 模块（DEP-4）|
| `start_shop` | ShopSystem 模块 |
| `unlock_recipe` / `unlock_skill` | 各成长系统 |

## 5. 与现有系统对接

### 5.1 HUD 系统（已就位 ✅）

| 现有 HUD 能力 | 对话系统怎么用 |
|---|---|
| `BaseWidget` | `DialogueWidget extends BaseWidget`，自动获得 input_mode / pause_policy 配置能力 |
| `HUDManager.push_widget(L2_GameMenu, w)` | 对话开始时调，自动入栈、自动失焦上一层 |
| `HUDManager.pop_widget(L2_GameMenu)` | 对话结束时调；**真实验证 P1-A4 push/pop**（HUD 前置依赖 DEP-13）|
| `HUDStateMachine.DIALOGUE` 状态 | 业务侧 emit `hud_state_changed(GAMEPLAY, DIALOGUE)` |
| `InputContextManager.push(Dialogue.tres)` | 对话开始；自动屏蔽战斗 action（DEP-11） |
| `EventBus.hud_toast_requested` | `hud_toast` Handler 直接复用 |

### 5.2 EventBus 信号（M11 新增）

```gdscript
## 对话生命周期信号（R-EVENT-01：snake_case + 类型声明）。

## 对话开始（DialogueRunner 派发）。
signal dialogue_started(graph_id: StringName)

## 当前节点变化（每次 _enter_node 派发；DialogueWidget 据此渲染）。
signal dialogue_node_changed(node: Resource)

## 选项呈现（仅 ChoiceNode 触发，已过滤 condition）。
signal dialogue_choice_presented(options: Array)

## 对话结束（正常 end 或外部强制 close）。
signal dialogue_ended(graph_id: StringName)

## EffectNode 触发（业务侧可订阅做埋点 / 调试）。
signal dialogue_effect_dispatched(effect_kind: StringName, payload: Dictionary)
```

### 5.3 ConfigCenter 加载

新增 `ConfigCenter.get_dialogue_graph(graph_id: StringName) -> DialogueGraph`：
- M11 阶段：直接从 `Data/Manual/Dialogues/*.tres` 加载（程序员/策划手工写）
- M11 ↔ M10 联调期：从 `Data/FromExcel/Generated/Dialogue.json` 加载（Excel 转出）
- 两种来源共存：先查 Generated.json，找不到再 fallback .tres（与 M10 通用 emitter 一致）

### 5.4 SaveSystem（D5）

- `GameInstance.dialogue_vars` **整个 Dictionary 进存档**（key:string + value:Variant 友好序列化）
- 当前正在进行的对话（`current_graph_id` + `current_node_id`）**不存档**（关卡切换 / 死亡复活时强制中断对话，避免序列化运行时状态）
- 玩家身上的 LooseTag（dialogue 加的 tag）随 ASC 存档（D5 已有支持）

## 6. UI 形态规范

### 6.1 DialogueWidget 结构

```
DialogueWidget (Control, BaseWidget, top_level=true, anchor=底部全宽)
├─ Bg (ColorRect / NinePatch，半透黑)
├─ PortraitFrame (TextureRect，左侧)
├─ Speaker (Label，肖像上方)
├─ Text (RichTextLabel，打字机效果)
├─ ContinueIndicator (Label "▼"，速通时闪烁，仅 SpeechNode 显示)
└─ ChoicesVBox (VBoxContainer，仅 ChoiceNode 显示)
    └─ ChoiceButton × N（动态生成 / 复用池）
```

### 6.2 UI 输入约定

| 上下文 | 键 | 行为 |
|---|---|---|
| SpeechNode（打字中）| 任意键 | 跳过打字机，整段文本立即显示 |
| SpeechNode（完成）| `combat_interact` | 推进到下一节点 |
| ChoiceNode | ↑/↓ | 切换选中 |
| ChoiceNode | `combat_interact` | 确认选项 |
| 任意时刻 | `cancel`（可配置）| 关闭对话（仅"可中断对话"启用，由 graph 顶层 flag 控制） |

### 6.3 动画时长（走 UIDurations.tres）

| 阶段 | 档位（默认）|
|---|---|
| 对话框入场（淡入 + 上滑）| `S` (180ms) |
| 打字机速度 | 40 chars/sec（DialogueConfig 可调）|
| 选项渐入 | `XS` (80ms) × N（间隔 50ms 错开）|
| 对话框退场（淡出 + 下滑）| `S` (180ms) |

## 8. 入口与生命周期

### 8.1 启动一段对话（业务侧 API）

```gdscript
# 任意业务侧（NPC.interact / Trigger / Cheat F8）：
DialogueRunner.start(&"npc_blacksmith_intro")
```

`DialogueRunner.start` 内部：
1. 检查是否已有对话在运行 → 有则 warn return（不堆叠）
2. 通过 ConfigCenter 加载 graph（找不到 → error return）
3. `InputContextManager.push(load("res://Data/Config/InputContexts/Dialogue.tres"))`
4. emit `EventBus.hud_state_changed(GAMEPLAY, DIALOGUE)`（间接让 HUDStateMachine 切状态）
5. `HUDManager.push_widget(&"L2_GameMenu", DialogueWidget_instance)`
6. emit `dialogue_started(graph_id)`
7. `_enter_node(graph.start_node_id)`

### 8.2 推进 / 选择 / 结束

| API | 触发 |
|---|---|
| `advance()` | SpeechNode → 走 next_links（按 condition 选第一条） |
| `select_choice(index)` | ChoiceNode → 选 filtered_options[index].next_id |
| `end()` / 自动到达无 next 节点 | 反向流程：pop widget → pop input context → emit hud_state_changed(DIALOGUE, GAMEPLAY) → emit `dialogue_ended` |

### 8.3 中断（外部强制）

```gdscript
DialogueRunner.force_end()  # 立刻走 end() 流程，不触发未走完的 EffectNode
```

典型场景：玩家死亡 / 关卡切换 / 进入 Boss 战。

## 9. 文本插值

文本里支持 3 类占位符（DialogueRunner 在 emit 前预处理）：

| 占位符 | 解析 |
|---|---|
| `{var:friendship_blacksmith}` | `GameInstance.get_dialogue_var(&"friendship_blacksmith", 0)` |
| `{tag:Quest.MainStory.Step1.Done}` | 玩家是否有该 tag → "是"/"否"（i18n 后由 LocalConfig 决定）|
| `{player_name}` | `GameInstance.player_name`（D5 接入后）|

不支持的占位符保持原样（不报错，便于策划调试）。

## 11. 验收清单（架构层）

完整验收清单见落地路线文档 `09_对话系统落地路线.md`。本文只列**架构层**必过项：

- [ ] DialogueRunner 是 Autoload 且常驻 `/root`，跨场景持久
- [ ] DialogueWidget extends BaseWidget；对话开始时**通过 HUDManager.push_widget 入栈**（不直接 add_child）
- [ ] 对话开始/结束自动 push/pop InputContextManager 的 `Dialogue.tres`
- [ ] 战斗 action（A/Q/W/E/R/X）在对话中被屏蔽（按下无响应）
- [ ] EffectNode 通过 EffectHandlerRegistry 派发，DialogueRunner 0 处 if-else 业务分支
- [ ] DialogueExpr 5 种基础元素全部覆盖单元测试
- [ ] 一份示例 graph（含 speech / choice / effect）能完整走完 → end，0 报错
- [ ] R 键死亡复活时未结束的对话被 `force_end()` 强制清理
- [ ] HUDStateMachine 状态切换：GAMEPLAY → DIALOGUE → GAMEPLAY 正确，DebugOverlay 可见

## 12. 共同的工程原则

1. **架构锁定，文案挂起**——所有"铁匠说什么 / 任务给什么道具"用占位字符串/数值，落地后再调
2. **配置可热改**——graph 字段必须从 .tres / .json 读，不允许硬编码到 .gd
3. **预留扩展接口**——EffectHandler 注册表 + 文本插值占位符两处必须写成"未来只加新 Handler / 占位符不改主流程"
4. **Cheese 防守**——对话期间不存档；外部强制 end 时不触发未走完 Effect（避免连点 cheat）
5. **不联网假设**——Demo 单机；所有 `dialogue_vars` 用 Dictionary 不用 Replicated
