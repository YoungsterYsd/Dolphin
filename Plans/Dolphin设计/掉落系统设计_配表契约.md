## 一、需求来源

策划提出（2026-05-24）：

```
掉落规则
    使用场景
        怪物被击杀时
        任务发奖励时
    掉落规则
        同一ID的作为一条配置
        两类Type都需要走一轮
            Weighted   Weight 填写权重，在子id内 按权重随机一条
            Random     Weight 填写万分比概率，每条 Random 的子id单独判定
```

配套表：`Tools/Excel/掉落表.xlsx`（已存在）。

## 二、配表契约

### 2.1 Drop_Rule 主表

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | Int | 掉落表主键（drop_table_id）。怪物 / 任务通过它引用 |
| `sub_id` | Int | 该表内每条规则的子 id |
| `Type` | Enum(Weighted, Random) | 抽样类型，详见 § 2.2 |
| `Weight` | Int | Weighted: 加权抽样的权重；Random: 万分比概率（10000 = 100%） |
| `Item_ID` | Int | 道具主键（→ `Item_Data.id`） |
| `Item_Num` | List(Int) | `{N}` = 固定 N 个；`{min,max}` = 闭区间随机；其它默认 1 个 |

### 2.2 抽样语义（核心）

**同一 drop_table_id 下两类 Type 各自走一轮，结果合并发放：**

| 类型 | 行为 |
|---|---|
| **Weighted** | 同 id 下所有 Weighted 子行 = 一个加权池，按权重**抽 1 条**；池空 → 跳过这一轮 |
| **Random** | 同 id 下每条 Random 子行**独立掷骰**；命中条件：`randi() % 10000 < Weight`；可同时多条命中 |

> 边界：单 drop_table_id 可只有 Weighted、只有 Random、或两类都有。

### 2.3 现行示例（来自 xlsx → 已导出 `Data/FromExcel/Drop_Rule.csv`）

```csv
id, sub_id, Type, Weight, Item_ID, Item_Num
1,  1,      Weighted, 30,    1,       {1}
1,  2,      Weighted, 30,    2,       {1,2}
2,  1,      Random,   6000,  1001,    {1}
3,  1,      Random,   10000, 1002,    {1}
```

| drop_table_id | 行为 |
|---|---|
| 1 | Weighted 池抽 1：50% 给 item=1（经验，1 个），50% 给 item=2（金币，1~2 个） |
| 2 | Random 一条：60% 给 item=1001（1 个） |
| 3 | Random 一条：100% 给 item=1002（1 个） |

> ⚠️ 注：当前 `Item_Data.csv` 最大 id=5，drop_table_id=2/3 引用的 `1001/1002` 在表里不存在。
> 测试时优先用 drop_table_id=1（指向真实存在的经验/金币）。
> 若需测试 Random 路径，请先在道具表新增 1001 / 1002 两件物品。

## 三、运行时架构

### 3.1 数据流

```
启动期：
  ConfigCenter._bootstrap
    └── _load_loot_tables()
          └── LootTableLoader.load()        # 读 Drop_Rule.csv → Dictionary[id, RowDict]

运行期（怪物死亡）：
  EnemyCharacter._handle_death()
    └── _dispatch_loot_on_death()
          ├── ConfigCenter.get_monster_data(data_id)["drop_id"]
          └── LootSpawner.dispatch(drop_id, self)
                ├── LootRoller.roll(drop_id)        # 两轮抽样 → [{item_id, count}, ...]
                │     ├── 第一轮：Weighted 池 → _pick_weighted（加权抽 1）
                │     └── 第二轮：Random 列表 → _hit_random（每条独立判定）
                └── _grant_to_player(drops, caller)
                      └── PlayerCharacter.InventoryComponent.add_by_id(item_id, count)
                            （Currency 走 Fragment_Currency 拦截入 CurrencyManager；
                             装备走 ItemInstance.create_new 滚字进装备槽；
                             堆叠走槽位合并）

运行期（任务奖励）：
  QuestSystem._try_complete_if_done(quest_id)
    └── _dispatch_reward(reward)
          └── _reward_loot(reward)            # kind = &"loot" handler
                └── LootSpawner.dispatch(reward.payload.drop_id, self)
```

### 3.2 文件清单

| 文件 | 职责 |
|---|---|
| `Data/FromExcel/Drop_Rule.csv` | 掉落表 CSV（UTF-8 BOM、与道具系统同规格） |
| `Script/Data/Loaders/LootTableLoader.gd` | 启动期加载 Drop_Rule.csv → `Dictionary[id, RowDict]` |
| `Script/Items/LootRoller.gd` | 抽样工具（静态）：`roll(drop_table_id) → Array[Dict]` |
| `Script/Items/LootSpawner.gd` | 分发工具（静态）：`dispatch(drop_table_id, caller)` 给玩家发奖励 |
| `Script/Core/ConfigCenter.gd` | 新增 `get_drop_rule(id)` / `has_drop_rule(id)` API + bootstrap 内 `_load_loot_tables` |
| `Script/Character/EnemyCharacter.gd` | 死亡时读 `Monster_Data.drop_id`，调 LootSpawner.dispatch |
| `Script/Quest/QuestSystem.gd` | 新增 `_reward_loot` handler；任务奖励 kind=`loot` 走 LootSpawner |
| `Script/Quest/QuestReward.gd` | kind 注释新增 `loot` 类型说明 |
| `Script/UI/HUDDebugCheats.gd` | Shift+F9：跑一次 Drop_Rule[1] 抽样验证 |

### 3.3 关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | LootRoller 输出**纯 Dict 数组** `[{item_id, count}, ...]` | 与 AffixRoller 同模式；好测、可序列化、不耦合 InventoryComponent |
| 2 | 两轮抽样在 LootRoller 一次完成（一次扫描拆表 + 两轮独立处理） | 简单直白，符合策划描述「两类都走一轮」的字面语义 |
| 3 | LootSpawner 走 `InventoryComponent.add_by_id`，不绕过 Fragment 路由 | Currency 自动入 CurrencyManager（被 Fragment_Currency 拦截），装备自动滚字。**所有获取路径行为一致**（背包菜单、商店、掉落、任务奖励）|
| 4 | Monster_Data 加 **drop_id 列**（软兼容） | CSV 没列时 `CsvLoader.as_int` 返回 0，自动跳过；策划随时加列即生效，无需改代码 |
| 5 | QuestReward 新增 kind=`loot`（payload.drop_id），不重写 `kind=item` | 与 LootSpawner 复用；同一份 Drop_Rule 既能用于怪物掉落也能用于任务奖励 |
| 6 | `Drop_Rule.csv` 缺失允许（早期项目阶段） | LootTableLoader.load() 内部判断文件存在与否，缺失只 warn 不崩 |
| 7 | 单条 Type 字段非法 / Item_ID ≤ 0 → assert 崩（R-CODE-01） | 配置错误必须开发期暴露，不能静默 |

## 四、Excel 加列指南（启用怪物掉落必读）

当前 `怪物表.xlsx` 的 Monster_Data sheet **未配 `drop_id` 列**，所以怪物死亡不会触发掉落。
启用方式：

### 步骤

1. 打开 `Tools/Excel/怪物表.xlsx` 的 **Monster_Data** sheet
2. 在末尾增列：
   - 行 1 字段名：`drop_id`
   - 行 2 类型：`Int`
   - 数据行填上对应的 Drop_Rule 主键 id（如 `1`）；不掉落保持空 / 0
3. 跑 `Tools/excel2Config` 重新导出 → 覆盖 `Data/FromExcel/Monster_Data.csv`
4. 重启 Godot 编辑器，自动生效（无需改任何代码）

### 当前怪物表样例

```csv
id, sub_id, name, type, attr_id, level
1,  ,       小怪A, Normal, 1,      1
2,  ,       BossB, Boss,   2,      1
```

加列后建议：

```csv
id, sub_id, name, type, attr_id, level, drop_id
1,  ,       小怪A, Normal, 1,      1,     1
2,  ,       BossB, Boss,   2,      1,     1
```

→ 击杀小怪 A / BossB 都会跑一次 `Drop_Rule[1]`：50% 经验 / 50% 金币。

## 五、QuestReward 配置示例

在 `Data/Manual/Quests/<quest_id>.tres` 的 rewards 数组中：

```ini
# 任务奖励：跑一次 Drop_Rule[1] 抽样并发放
[sub_resource type="Resource" id="Reward_Loot"]
script = ExtResource("QuestReward.gd")
kind = &"loot"
payload = { "drop_id": 1 }
```

QuestSystem `_reward_loot` 自动 dispatch → 走与怪物掉落相同的 LootSpawner 路径。

## 六、规则合规性

| 规则 | 体现 |
|---|---|
| **R-DATA-01/02** | 数值全部走 CSV，脚本零硬编码 |
| **R-DATA-03**（CSV 路线） | Drop_Rule 是纯数据（无 Resource 引用、无方法），完美适配 CSV |
| **R-CODE-01** | Type 非法 / Item_ID ≤ 0 → assert 崩；玩家 / Inventory 缺失 → warn + return 0（运行时合理降级） |
| **R-CODE-02** | LootSpawner / LootRoller 全静态、强类型；无 has_method / call(StringName) 反射 |
| **R-ARCH-02** | 不新增 Autoload；LootTableLoader 由 ConfigCenter 持有 |
| **R-ARCH-03** | 业务侧 ConfigCenter.get_drop_rule(id) 直访 |
| **R-ARCH-04** | LootSpawner 用 NodeFinder 强类型查找 InventoryComponent；未引入跨模块反向调用 |
| **R-CHAR-01** | PlayerLocator + NodeFinder 标准查找 |
| **R-EVENT-01** | 不新增信号（沿用 EventBus.item_added / inventory_changed） |
| **R-LOG-01** | 全部走 GameLogger.info("Loot", ...) / GameLogger.warn("Loot", ...) |

## 七、自测清单

### 7.1 启动期（编辑器重启后）

- [ ] 编辑器日志含 `LootTableLoader done: 3 drop tables loaded`
- [ ] ConfigCenter bootstrap 末尾 `loot_tables=3`

### 7.2 运行期（启动游戏，按调试键）

- [ ] **Shift+F9** 多次按下：
  - HUD Toast 显示 `Loot[1] → 1 entries`
  - 控制台日志 `LootSpawner: granted item_id=1 count=1` 或 `item_id=2 count=1~2`
  - 多次按下两条 Weighted 应近似 1:1 分布
- [ ] 怪物死亡（**前置：先在 Monster_Data 加 drop_id 列指向 1**）：
  - 击杀 TestArena 的史莱姆 → HUD Toast 弹出经验 / 金币
  - 控制台日志 `LootSpawner: granted item_id=...`
- [ ] **任务奖励**（前置：QuestDef.rewards 加一条 kind=loot, payload.drop_id=1）：
  - 完成任务 → 同样 dispatch

### 7.3 边界

- [ ] `LootSpawner.dispatch(0, self)` → 静默返回 0（不崩）
- [ ] `LootSpawner.dispatch(999, self)` → warn `drop_table_id=999 not found` + 返回 0
- [ ] 当 Item_Data 没有 1001 时（drop_table_id=2/3），对应 `add_by_id` 会 assert 崩 —— 这是预期（配置错误）
