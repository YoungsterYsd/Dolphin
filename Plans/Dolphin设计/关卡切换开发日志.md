## 架构

```
玩家踩进 LevelTransitionArea / BossPortal
        │
        ▼
LevelManager.load_level(LevelDef)
        │
        ├─ EventBus.level_loading_started(from, to)
        ├─ HUDStateMachine.change_state(LEVEL_TRANSITION) → push Cutscene InputContext
        ├─ LoadingScreenWidget.begin_fade_out (await)         ← 黑幕渐显
        ├─ AudioManager.play_bgm（如配置）
        ├─ get_tree().change_scene_to_packed(LevelDef.scene)  ← Godot 异步切场景
        ├─ await 2 帧让场景就绪
        ├─ _teleport_player_to_marker(spawn_marker_id)         ← 玩家 teleport 到对应 spawn 点
        ├─ EventBus.level_changed
        ├─ LoadingScreenWidget.begin_fade_in (await)           ← 黑幕渐隐
        ├─ HUDStateMachine.change_state(GAMEPLAY) → pop InputContext
        └─ EventBus.level_loading_finished
```

## 关键设计决策

### 1. 跨场景持久 vs 关卡内重建
| 数据 | 持久层 |
|---|---|
| dialogue_vars / quest_states / current_level_id | GameInstance (Autoload) ✅ 自动持久 |
| HUD widgets / HUD_Main | 挂在 /root（Autoload 同级）✅ 不重建 |
| Player / Camera / 场景 NPC / Slime | 关卡内节点，**会随场景重建**（D5 SaveSystem 落地后从存档还原） |

### 2. SpawnMarker 设计
- 不直接 teleport 玩家到关卡 (0,0,0)，而是按 `spawn_marker_id` 找对应 LevelSpawnMarker 节点
- 同关卡可有多个 Marker（main_entrance / from_boss / checkpoint_1）
- 不同入口（村→副本东门 / 副本→村南门）配不同 spawn_id
- LevelDef 配 `spawn_marker_id` 决定哪个 Marker 生效

### 3. 循环引用解决
- `Scenes/Levels/TestArena.tscn` 通过 BossPortal 引用 LevelDef_BossRoom_01
- LevelDef_BossRoom_01 引用 BossRoom_01.tscn
- BossRoom_01.tscn 通过 ReturnPortal 引用 LevelDef_TestArena
- LevelDef_TestArena 引用 TestArena.tscn ⟶ **循环！**

**解决**：LevelTransitionArea / BossPortal 加 `target_level_path: String` 字段，运行时 `load(path)`，不在 .tscn ext_resource 里预引用 LevelDef。

### 4. fade out / change_scene / fade in 时序
- fade out 期间切 BGM（听感最好）
- change_scene_to_packed 是 deferred → 等 2 帧让场景就绪
- 切完场景后再 teleport 玩家 + fade in
- 整个流程用 `await` 串起来，避免回调地狱
