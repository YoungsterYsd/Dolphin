# 命中反馈配置化设计

> **生成日期**：2026-05-24
> **范围**：技能命中目标后（玩家打怪 / 怪打玩家 / 怪打怪）按**配置**生成对应的特效（VFX）和音效（SFX），策划无需改代码。
> **现状**：Cue 后端管线已就位（CueManager + CueBinding + VFXSpawner + AudioManager + CameraRig + HitStopHost），但**命中 cue_tag 写死**为 `Cue.Damage.Default.Hit`，无法按"攻防双方组合 / 元素 / 暴击 / 格挡"分流。
> **目标**：把命中点 cue_tag **从写死改为按上下文路由**；同时建立一份「Hit Cue 路由表」让策划在 Inspector / Excel 里维护"打谁、用什么、怎么响"的对应关系。

---

### 1.2 待补（本次新增）🔴

| 项 | 痛点 |
|---|---|
| **命中 Cue 路由器**（HitCueResolver） | DamagePipeline 写死 `Cue.Damage.Default.Hit`，无法区分 player vs enemy / 元素 / 武器 |
| **Hit Cue 路由表配置**（HitCueRoutingTable.tres） | 缺数据驱动的"攻防组合 → cue_tag"映射；策划无入口配置 |

| **命中部位 / 角度 / 暴击/格挡 的上下文进 cue_tag** | DamagePipeline 已有 is_crit/is_block/is_perfect_block flags，但没有把这些信息编码进 cue_tag |

## 二、设计目标

### 2.1 三条核心路由维度

```
谁打谁 + 怎么打 + 什么结果  →  cue_tag
─────────────────────────   ──────────
attacker_kind: player/enemy/boss/projectile
weapon_kind:   melee/bow/staff/...（M10+ 武器系统接入）
damage_type:   physical/fire/ice/true（已就位 GameplayTag）
hit_result:    hit/crit/block/perfect_block/dodge
```

### 2.2 推荐 cue_tag 命名规约

```
Cue.Damage.<DamageType>.<HitResult>[.<AttackerKind>]
  例如：Cue.Damage.Physical.Hit
       Cue.Damage.Physical.Crit
       Cue.Damage.Fire.Hit
       Cue.Damage.Physical.Block
       Cue.Damage.Physical.PerfectBlock
       Cue.Damage.Physical.Hit.Boss   ← Boss 命中玩家专用（强反馈）
       Cue.Damage.Physical.Hit.Player ← 玩家命中敌人专用
```

> **降级路由由 CueManager 的 Tag 父匹配自动处理**：
> `Cue.Damage.Physical.Hit.Boss` 没注册 → 退到 `Cue.Damage.Physical.Hit` → 退到 `Cue.Damage.Physical` → 退到 `Cue.Damage`。配置时只需关注差异化条目，剩下的吃父级。

### 2.3 落地策略

| 策略 | 说明 |
|---|---|
| **A. 直接在 DamagePipeline 内编码 cue_tag**（最小改动） | DamagePipeline 已知 attacker / target / is_crit / is_block / is_perfect_block / damage_type，可以直接拼字符串。**优点**：0 新文件；**缺点**：拼接逻辑硬编码在 pipeline，未来加维度（部位/武器）需改代码 |
| **B. 抽出 HitCueResolver 静态工具**（推荐） ⭐ | 把"上下文 → cue_tag"决策从 DamagePipeline 解耦，给单元测试 + 未来扩展留口子 |
| **C. 走外部 RoutingTable.tres**（数据驱动极致版） | 在 .tres 里写"if attacker_kind=boss && damage_type=physical → cue_tag=Xxx"。**优点**：策划完全自主；**缺点**：表达匹配条件需要 mini DSL，复杂度上一档 |

> **决策**：采用 **B + 部分 C**。HitCueResolver 内置规约把 5 维度映射成 cue_tag（覆盖 80% 场景）；少数特例可在 Timeline EventKeyframe 上**显式填 cue_tag 覆盖**（即 C 的轻量版）。RoutingTable.tres 留作 P2 演进方向。

## 三、模块设计

### 3.1 HitCueResolver（新建静态工具）

```gdscript
# Script/Effects/HitCueResolver.gd
class_name HitCueResolver
extends RefCounted

## 把命中上下文编码成 cue_tag。
##
## 优先级（高→低）：
## 1. 显式覆盖：caster.get_meta(&"override_hit_cue_tag")（Timeline EventKeyframe 用）
## 2. 命中结果分流：dodged → Cue.Damage.<Type>.Dodge
##                  perfect_blocked → Cue.Damage.<Type>.PerfectBlock
##                  blocked → Cue.Damage.<Type>.Block
##                  crit → Cue.Damage.<Type>.Crit
##                  普通命中 → Cue.Damage.<Type>.Hit
## 3. 攻击者类型后缀：boss → 加 .Boss；player vs enemy 不加（默认派生 Hit/Crit 即够用）
##
## 返回 StringName 形式的 cue_tag；CueManager 会做父级降级。
static func resolve(ctx: HitCueContext) -> StringName:
    # 1. Timeline 显式覆盖优先
    if ctx.override_cue_tag != &"":
        return ctx.override_cue_tag

    # 2. 命中结果
    var result_seg: String
    if ctx.is_dodged:
        result_seg = "Dodge"
    elif ctx.is_perfect_blocked:
        result_seg = "PerfectBlock"
    elif ctx.is_blocked:
        result_seg = "Block"
    elif ctx.is_crit:
        result_seg = "Crit"
    else:
        result_seg = "Hit"

    # 3. 伤害类型（默认 Physical）
    var type_seg: String = String(ctx.damage_type) if ctx.damage_type != &"" else "Physical"

    # 4. 攻击者类型后缀
    var suffix: String = ""
    if ctx.attacker_kind == &"boss":
        suffix = ".Boss"

    return StringName("Cue.Damage.%s.%s%s" % [type_seg, result_seg, suffix])
```

```gdscript
# Script/Effects/HitCueContext.gd
class_name HitCueContext
extends RefCounted

## 攻击者节点。
var attacker: Node = null
## 受击者节点。
var target: Node = null
## 攻击者类型：&"player" / &"enemy" / &"boss" / &"projectile" / &"environment"。
var attacker_kind: StringName = &""
## 伤害类型 GameplayTag（如 &"Physical" / &"Fire"）。空 → Physical。
var damage_type: StringName = &""
## 暴击。
var is_crit: bool = false
## 普通格挡。
var is_blocked: bool = false
## 完美格挡。
var is_perfect_blocked: bool = false
## 闪避（命中点已被 Combat.Dodge.IFrame 拦截）。
var is_dodged: bool = false
## 显式覆盖（Timeline EventKeyframe.cue_tag 走这里）。
var override_cue_tag: StringName = &""
## 调用方携带的 payload（dealt / extra metadata）。
var payload: Dictionary = {}
```

### 3.2 DamagePipeline 接入点（最小改动）

**改动位置**：`Script/GAS/DamagePipeline.gd:L191` 周边（命中后 cue 派发段）

**伪代码**：
```gdscript
# 改前（写死）：
GameInstance.cue_manager.execute_cue(&"Cue.Damage.Default.Hit", attacker, {
    dealt = final_damage, is_crit = is_crit
})

# 改后（路由）：
var ctx := HitCueContext.new()
ctx.attacker = attacker
ctx.target = target
ctx.attacker_kind = _resolve_attacker_kind(attacker)  # 查 group/tag/CharacterDef
ctx.damage_type = damage_type_tag  # 已在 spec 中可取
ctx.is_crit = is_crit
ctx.is_blocked = is_blocked
ctx.is_perfect_blocked = is_perfect_blocked
ctx.payload = {dealt = final_damage, is_crit = is_crit, is_block = is_blocked}

var cue_tag := HitCueResolver.resolve(ctx)
GameInstance.cue_manager.execute_cue(cue_tag, attacker, ctx.payload)
```

**`_resolve_attacker_kind` 实现**（轻量）：
- attacker 在 `unit.boss` group → boss
- attacker 在 `unit.player` group → player
- attacker 在 `unit.enemy` group → enemy
- attacker 是 Projectile/InstanceProjectile → projectile
- 兜底 → enemy

### 3.3 Timeline EventKeyframe 增加 cue_tag 字段（推荐演进）

**改动位置**：`Script/SkillSystem/Keyframes/EventKeyframe.gd`

```gdscript
# 在 EventKeyframe.gd 中加：
## 显式 Cue tag（运行时优先于自动路由）。
##
## 用法：技能"火球爆炸"在自身命中点关键帧填 cue_tag=&"Cue.Damage.Fire.Explosion"
## 即可统一发出 [音效+VFX+震屏+冻帧]，无需 5 个独立的 sfx/vfx/shake/hitstop 关键帧。
```

## 五、其他场景的命中反馈

### 5.1 远程弹道（Projectile）命中

- ProjectileSpawner 实例化 Projectile（Area3D + 沿向量飞行）
- Projectile 命中 Hurtbox 时调 ASC.apply_effect → 走同一条 DamagePipeline → 自动经 HitCueResolver
- attacker_kind = projectile（如 BOSS 火球：`Cue.Damage.Fire.Hit.Boss`）

### 5.2 持续伤害（DoT，如灼烧 GE 每秒掉血）

- GE_Burning_3s 是 Periodic 类型，每 tick 走 DamagePipeline.apply_effect
- 默认不发命中 cue（频次太高伤眼），HitCueResolver 增加 `is_periodic` 字段判定 → 早 return
- DoT 用 LOOPING cue：GE 应用时 `add_active_cue(&"Cue.Status.Burning.Apply", target)`，移除时 `remove_active_cue`

### 5.3 玩家自我治疗

- 走 GE_Heal30 → ASC.apply_effect → DamagePipeline 检测 amount > 0 / damage_type=heal → 路由到 `Cue.Heal.<source>`
- 简化版：HitCueResolver 增加 `is_heal: bool` 分支

### 5.4 环境伤害（陷阱 / DoT 地面）

- attacker = environment trigger node（Area3D）
- attacker_kind = environment
- cue_tag → `Cue.Damage.Physical.Hit.Environment` → 兜底到 `Cue.Damage.Physical.Hit`

## 十、为什么这样设计

| 维度 | 说明 |
|---|---|
| **复用既有 Cue 系统** | CueManager + CueBinding 已经把"4 表现手段叠加 + Tag 父匹配"实现得很完整；本设计不重写，只**补一层路由器**让 cue_tag 能动态路由 |
| **配置面足够策划自助** | 策划只需要在 Inspector 编 `Array[CueBinding]`（10 行内可填一套 BOSS 战完整反馈），不需要写代码 |
| **降级路由保兜底** | 没注册的 cue_tag 自动退到父级；任何新 attacker_kind / damage_type 加入都能立刻有兜底反馈 |
| **DamagePipeline 改动最小** | 只动一行 cue_tag 来源（写死 → resolver），不影响伤害计算主链路 |
| **Timeline 显式覆盖** | 极少数特殊技能（如"狂暴突进每命中专用反馈"）可在 Timeline EventKeyframe 写死 cue_tag 覆盖路由器 |
| **不引入 RoutingTable.tres 复杂度** | 5 维度路由用代码规约即可表达，没必要做 mini DSL；P2 演进时如真的需要再上 |
