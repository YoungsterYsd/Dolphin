# 战后结算系统设计

> **生成日期**：2026-05-24
> **范围**：战斗结束（BOSS 击杀 / 关卡完成 / 玩家死亡）后，统一展示**战斗结果 + 战斗表现**面板。
> **定位**：归属 Combat 域 + UI 域跨界 —— 数据采集走 Combat/Stats 子系统，展示走 UI BossClearWidget / DeathScreenWidget 复用。
> **强依赖**：EventBus.damage_dealt_v3（已就位）/ block_* 信号（已就位）/ dodge_* 信号（待补，与玩家闪避 GA 同步落地）。

---

## 一、数据模型

### 1.1 战斗结果（CombatResult）

| 字段 | 类型 | 含义 | 来源 |
|---|---|---|---|
| `outcome` | `enum {Victory, Defeat, Escaped}` | 战斗最终结果 | BossEncounterController / LevelManager 派发 |
| `arena_id` | `StringName` | 战斗场景 / BOSS id（如 `boss_demo`、`level_arena_01`） | 进入战斗时记录 |
| `started_at_msec` | `int` | 战斗开始（Time.get_ticks_msec） | 进入战斗时记录 |
| `ended_at_msec` | `int` | 战斗结束 | 派发结算时记录 |
| `duration_sec` | `float` | 用时（end - start） | 计算 |
| `rewards` | `Array[RewardEntry]` | 奖励列表（金币/物品/经验） | LootSpawner / CurrencyManager / LevelComponent 累计 |

> **MVP 阶段**：仅 outcome + duration + rewards 三项即可显示「VICTORY / 用时 02:13 / +120 金币 +1 铁剑」最小结算。

### 1.2 战斗表现（CombatStats）

> **作用域**：单场战斗（StatsRecorder.start_session 到 end_session 之间累计），战斗结束后落到 CombatResult.stats。

| 字段 | 类型 | 含义 | 公式 / 触发源 |
|---|---|---|---|
| `damage_dealt_total` | `float` | 玩家累计输出（含暴击 / 含被格挡前的原伤） | EventBus.damage_dealt_v3 source==player 累加 |
| `damage_taken_total` | `float` | 玩家累计承伤（最终落地伤害） | damage_dealt_v3 target==player 累加 |
| `damage_blocked_total` | `float` | 被格挡减免的伤害（普通 0.4× + 完美 1.0×） | DamagePipeline 第 7 步 emit `damage_blocked` 累加 |
| **`dps`** | `float` | 输出 DPS = damage_dealt_total / duration_sec | 结算时算 |
| **`hits_taken`** | `int` | 受击次数（非 block / 非 perfect_block 的 damage_dealt_v3 target==player 计数） | damage_dealt_v3 + is_block=false + is_perfect_block=false |
| **`blocks_normal`** | `int` | 普通格挡次数 | damage_dealt_v3 + is_block=true + is_perfect_block=false |
| **`blocks_perfect`** | `int` | 完美格挡次数 | block_perfect_triggered |
| **`blocks_total`** | `int` | 格挡总次数 = blocks_normal + blocks_perfect | 计算 |
| **`dodges_count`** | `int` | 闪避次数（成功躲避：闪避 i-frame 期间被命中且无伤） | dodge_succeeded（待补信号） |
| `dodges_attempted` | `int` | 闪避尝试次数（闪避 GA 激活次数） | dodge_started（待补） |
| `crits_dealt` | `int` | 玩家造成的暴击次数 | damage_dealt_v3 + is_crit=true + source==player |
| `crit_rate` | `float` | 暴击率 = crits_dealt / hits_dealt_count | 计算 |
| `combo_peak` | `int` | 单场最高连击 | 订阅 ComboTracker（已就位，combo_changed 取 max） |
| `enemies_killed` | `int` | 击杀敌人数（含杂兵 + BOSS） | enemy_died 累计 |
| `interrupts_caused` | `int` | 玩家造成的打断次数 | character_interrupted + attacker==player |
| `poise_broken_caused` | `int` | 玩家造成的破韧次数 | poise_broken 累计（target≠player） |
| `times_died` | `int` | 玩家死亡次数（仅当允许复活/重试时 >1） | player_died |

#### 衍生指标（仅展示，不入存储）

- **生存率**：`100% - damage_taken_total / max_health` （单参考值，可负）
- **格挡参与度**：`blocks_total / (hits_taken + blocks_total)` （决定"是否积极格挡"评级）
- **完美格挡占比**：`blocks_perfect / max(blocks_total, 1)`
- **平均伤害**：`damage_dealt_total / max(hits_dealt_count, 1)`

### 1.3 评级（可选，P1）

> 对照《黑帝斯》/《死亡细胞》模式，根据综合表现给 S/A/B/C 评级 + 一句点评：

| 评级 | 触发条件（任意 1 项满足都行） |
|---|---|
| **S** | dps > 配表阈值 × 1.5 OR perfect_block_rate > 50% OR 0 受击通关 |
| **A** | dps > 配表阈值 × 1.0 |
| **B** | dps > 配表阈值 × 0.6 |
| **C** | 其他（含死亡复活的） |

> 评级阈值走 `Data/Config/CombatRatingConfig.tres`（数据驱动 R-DATA-02 合规）。

## 二、采集面（信号映射）

> **关键发现（2026-05-24 现状）**：项目当前 EventBus 已经把绝大多数指标信号铺好了 —— 战后结算几乎不需要新增信号，只需新建一个「订阅器」节点把它们汇总即可。

### 2.1 已就位（直接订阅，零新增成本）✅

| 指标 | 订阅信号 | 现状 |
|---|---|---|
| damage_dealt_total / damage_taken_total | `damage_dealt_v3(source, target, amount, is_crit, is_block, is_perfect_block, tags)` | ✅ M8 落地，含完整 flags |
| crits_dealt / crit_rate | damage_dealt_v3 + is_crit | ✅ |
| blocks_normal | damage_dealt_v3 + is_block && !is_perfect_block | ✅ |
| blocks_perfect | `block_perfect_triggered(blocker)` | ✅ D2.D 已发出 |
| damage_blocked_total（完美格挡部分） | `damage_perfect_blocked(attacker, target, would_dealt)` | ✅ |
| hits_taken | damage_dealt_v3 + target==player + !is_block && !is_perfect_block | ✅ |
| combo_peak | `combo_changed(count)` 取 max | ✅ ComboTracker Autoload |
| enemies_killed | `enemy_died(enemy)` | ✅ |
| times_died | `player_died()` | ✅ |
| interrupts_caused | `character_interrupted(target, attacker, impact_level)` | ✅ |
| poise_broken_caused | `poise_broken(target)` + 比对 target ≠ player | ✅ |

### 2.2 待补（与玩家闪避 GA 一起落地）🔴

| 指标 | 需要新增 | 落地点 |
|---|---|---|
| dodges_attempted | `signal dodge_started(actor: Node)` | 闪避 GA `_activate` 时 emit |
| dodges_count | `signal dodge_succeeded(actor: Node, attacker: Node)` | DamagePipeline 第 X 步检测「target 持有 Combat.Dodge.IFrame tag」时 emit + abort 伤害管线 |
| —（不直接展示） | `signal dodge_ended(actor: Node)` | 闪避 GA `_end` 时 emit（用于动画/UI） |

### 2.3 待补（damage_blocked_total 普通格挡部分）🟡

> 当前 `damage_perfect_blocked` 只覆盖完美格挡的 would-dealt；普通格挡的减伤没有独立信号。

**最小改动**：
- 方案 A（推荐）：在 `damage_dealt_v3` payload 增加 `damage_blocked_amount: float`（is_block=true 时填减伤量；is_perfect_block=true 时填全部 would-dealt）；其他 flag 字段不变。
- 方案 B：新增 `signal damage_normal_blocked(attacker, target, mitigated_amount)`，与 perfect_blocked 配对。

> 优先级 P2，本结算系统 v1.0 不必等。MVP 阶段「damage_blocked_total」只统计完美格挡部分即可。

## 三、采集器架构

### 3.1 模块位置

```
Script/Combat/Stats/                       ← 新建子目录（不新增 Autoload，挂 GameInstance 子节点）
├── CombatStatsRecorder.gd                 ← 核心订阅器节点
├── CombatResult.gd                        ← Resource：战斗结果数据载体
├── CombatStats.gd                         ← Resource：战斗表现数据载体
└── RewardEntry.gd                         ← Resource：奖励项（kind/id/count/icon）
```

### 3.2 CombatStatsRecorder 行为

```gdscript
# Script/Combat/Stats/CombatStatsRecorder.gd
class_name CombatStatsRecorder
extends Node

## 当前 session（active=true 时累计；end_session 后冻结）。
var _stats: CombatStats = null
var _result: CombatResult = null
var _is_active: bool = false


func _ready() -> void:
    # 订阅一次性，session 内通过 _is_active 守卫
    EventBus.damage_dealt_v3.connect(_on_damage)
    EventBus.block_perfect_triggered.connect(_on_perfect_block)
    EventBus.damage_perfect_blocked.connect(_on_perfect_blocked_amount)
    EventBus.combo_changed.connect(_on_combo)
    EventBus.enemy_died.connect(_on_enemy_died)
    EventBus.player_died.connect(_on_player_died)
    EventBus.character_interrupted.connect(_on_interrupted)
    EventBus.poise_broken.connect(_on_poise_broken)
    # 待补：dodge_started / dodge_succeeded


func start_session(arena_id: StringName) -> void:
    _stats = CombatStats.new()
    _result = CombatResult.new()
    _result.arena_id = arena_id
    _result.started_at_msec = Time.get_ticks_msec()
    _is_active = true


func end_session(outcome: int) -> CombatResult:
    if not _is_active:
        return null
    _is_active = false
    _result.ended_at_msec = Time.get_ticks_msec()
    _result.duration_sec = float(_result.ended_at_msec - _result.started_at_msec) / 1000.0
    _result.outcome = outcome
    _stats.dps = _stats.damage_dealt_total / max(_result.duration_sec, 0.001)
    _stats.crit_rate = float(_stats.crits_dealt) / max(_stats.hits_dealt_count, 1)
    _stats.blocks_total = _stats.blocks_normal + _stats.blocks_perfect
    _result.stats = _stats
    return _result


func add_reward(kind: StringName, id: int, count: int) -> void:
    if not _is_active: return
    var e := RewardEntry.new()
    e.kind = kind; e.id = id; e.count = count
    _result.rewards.append(e)

# ─── 订阅回调 ───
func _on_damage(src: Node, tgt: Node, amount: float, is_crit: bool, is_block: bool, is_perfect_block: bool, _tags: Array) -> void:
    if not _is_active: return
    var player_node: Node = _get_player()
    if src == player_node:
        _stats.damage_dealt_total += amount
        _stats.hits_dealt_count += 1
        if is_crit: _stats.crits_dealt += 1
    if tgt == player_node:
        _stats.damage_taken_total += amount
        if is_block and not is_perfect_block:
            _stats.blocks_normal += 1
        elif not is_block and not is_perfect_block:
            _stats.hits_taken += 1
        # is_perfect_block 由 _on_perfect_block 单独处理（damage_dealt_v3 此时 amount=0，跳过）
# ...（其他订阅回调略，按§1.2 字段映射）
```

### 3.3 挂载位置

- **Autoload？** —— 不（项目 R-ARCH-02 控制 Autoload 数量；CombatStats 不需要跨场景常驻）
- **GameInstance 子节点？** —— 否（与战斗强相关，放 GameInstance 太"全局"）
- **推荐**：`BossEncounterController` / `LevelManager.current_level_root` 内 `add_child(CombatStatsRecorder.new())`，关卡退出时 `queue_free()`。

### 3.4 生命周期编排

```
进入关卡 / BOSS 战
  └─ BossEncounterController._on_intro_finished()
       └─ stats_recorder.start_session(&"boss_demo")

战斗中
  └─ EventBus 信号 → recorder 订阅累计
  └─ LootSpawner.dispatch / CurrencyManager → recorder.add_reward()

战斗结束
  ├─ Victory: BossEncounterController._on_boss_died()
  │            └─ result = recorder.end_session(Victory)
  │            └─ HUDManager.push_widget(BossClearWidget, result)
  │
  ├─ Defeat:  EventBus.player_died
  │            └─ result = recorder.end_session(Defeat)
  │            └─ HUDManager.push_widget(DeathScreenWidget, result)
  │
  └─ Escape:  LevelManager.unload_current（中途撤离）
               └─ result = recorder.end_session(Escaped)（可选不展示）
```

## 八、规则联动

- **R-DATA-02**：评级阈值 / 点评 / 星级配置全部走 `CombatStatsConfig.tres`，无硬编码
- **R-ARCH-02**：不增 Autoload，CombatStatsRecorder 挂在战斗场景内（关卡级生命周期）
- **R-EVENT-01**：所有数据靠订阅 EventBus，**不直接读其他系统状态**（解耦）
- **R-HUD-02**：BossClearWidget / DeathScreenWidget 入参用 typed Resource（CombatResult），保持 UI 不持业务节点引用
- **R-VERIFY-01**：每 Phase 完成跑 read_lints + Tools/godot.bat restart + 至少 5 项指标手验

## 九、为什么独立设计

| 维度 | 说明 |
|---|---|
| **复用性** | 不只 BOSS 战；后续普通关卡、肉鸽房间、训练场都能复用同一套 recorder + UI |
| **解耦** | 采集层（订阅 EventBus）与展示层（Widget 渲染 Resource）完全分离，可独立测试 |
| **扩展性** | 新增指标只在 CombatStats 加字段 + recorder 加订阅；UI 渲染 Resource 即可，无需改流程 |
| **可观测** | GM 命令 `stats.dump` 可用作调试工具；指标数值天然可记录、可分析 |
